## 0. Кратко

1. **Один сервер, один путь к арендатору** (п. 5.6). `npm run picker -- serve --tenants <папка> [--home <папка>] [--port N]` читает папку один раз, проверяет каждый `*.json`
   правилами REQ-054 (`readTenantFile(путь, { baseDir })` → `checkBytes` на тех же байтах), оставляет исправных арендаторов и слушает `127.0.0.1`. Арендатор — первый отрезок пути
   `/t/<id>/`; из строки запроса, заголовков и тела его взять нельзя (статический тест п. 9, SV-4e). Неизвестный арендатор, арендатор из файла с ошибками и любой неизвестный путь
   отвечают одной и той же готовой строкой байт: 404, тело и заголовки не зависят ни от пути, ни от метода, ни от `lang`.
2. **Маршруты — закрытый список из пяти видов** (п. 5.6): страница `GET /t/<id>/`, переадресация `GET /t/<id>` (308, для любого `id` по правилу REQ-054, есть арендатор или нет),
   анкета `GET /t/<id>/api/questionnaire`, результат `POST /t/<id>/api/result`, файлы страницы `GET /assets/<имя>`. Путь не раскодируется: `%2D`, `..`, `//` — неизвестный путь.
3. **Что отдаётся посетителю** (п. 5.3) строится по полям, а не копированием: анкета — ровно 10 полей верхнего уровня и по белому списку внутри; результат — объект движка REQ-055
   **без `ranking`** (баллы нерекомендованных решений остаются на сервере, ISS-0077, п. 7). Версия анкеты — sha256 байт файла арендатора, одна на все языки.
4. **Язык** (п. 5.4): `?lang=` → ru; в файле арендатора нет языка — ru; `Accept-Language` не читается. Тексты ответов об ошибках — ключи `TEXTS` (`server_*`) на языке запроса;
   ответы без арендатора (404, 405 для файлов страницы, 500) не зависят от языка и несут три языка в одной строке.
5. **Защита** (п. 5.7): `Host` — первое действие, до чтения любых данных (403, пустое тело); у POST — `Origin` (обязателен; тот же адрес и порт), тип `application/json`, тело не больше
   16384 байт (413), пауза в теле не дольше 15 с (408); заголовки `Cache-Control: no-store`, `X-Content-Type-Options`, `Referrer-Policy` на каждом ответе и `Content-Security-Policy`
   без внешних источников и `X-Frame-Options` на страницах. Порядок проверок записан таблицей и закреплён тестом (п. 5.6).
6. **Сбои не роняют сервер** (п. 5.9): каждый путь отказа — таблица «что видит человек — что неизменно»; любое исключение в обработчике — 500 с языковой строкой и одна строка
   журнала без текста исключения; файл арендатора с ошибками не обслуживается, сервер печатает «Арендатор <имя файла> не обслуживается:» и строки проверки и работает с остальными.
7. **Команда `serve`** (п. 4): параметры, разбор значений, двенадцать сообщений кода 2, три сообщения кода 1, остановка по SIGINT/SIGTERM кодом 0; `startPicker(options, io)` — единственная функция запуска
   (её же вызовет стенд REQ-062). `cli.js` остаётся скриптом-точкой входа, его никто не импортирует; ошибка программы — код 3 (ISS-0077, п. 2, 3).
8. **Стенд** (п. 6): команда, адреса для владельца и шаг приёмки с командами `curl` и поиском по названиям и id решений на трёх языках — команды опробованы на прототипе.
   Страница на этом этапе — заглушка с одной фразой на трёх языках (п. 5.5); пройти анкету в браузере можно только после REQ-057 и REQ-058 (вопрос О1).
9. **Охранные тесты прежних требований** (п. 7): 14 строк «было → стало» — PK-6a, PK-6d, PK-6e, PK-6f, PK-7c, PK-8c, PE-8d, TR-4b, TR-4d, TR-4e, блок `eslint`; PK-7a, PK-7b, TR-4c,
   TR-4f и PK-L2 не меняются. Измерено на прототипе: после кода красных ровно 8, после таблицы замен все 164 теста `picker-*` и `traces-runtime` зелёные, `npm run check` — код 0.
10. **Подшаги** 56a–56e (п. 8): чистые модули → чтение папки → сервер (`server.js`) → команда (`serve.js`, `cli.js`) → README; красных существующих тестов 2 → 4 → 5 → 8, все названы заранее (замерено на четырёх свежих копиях).

## 4. Команда `serve`

`cd tools && npm run picker -- serve --tenants <папка> [--home <папка>] [--port N]`. Скрипт `picker` в `package.json` прежний (PK-7b).

### 4.1. Параметры

| Ключ | Значение | Умолчание | Правило |
|---|---|---|---|
| `--tenants` | папка с файлами арендаторов (путь от текущей папки или абсолютный) | нет — обязателен | непустая строка без нулевого знака; папка должна быть, читаться и быть папкой |
| `--port` | целое число | 4782 (`DEFAULT_PORT`) | только цифры (`/^\d+$/`), не больше 65535; 0 — любой свободный порт |
| `--home` | путь | нет | принимается; в этом требовании ничего с ним не делается (D25) |

Ключ можно писать как `--port 0` и как `--port=0`. Ключ указывают один раз. Другие ключи и лишние слова — отказ. **Значение ключа** — следующее слово или часть после «=». Значение **отсутствует**, если слова нет, оно пустое, начинается с «--» или содержит нулевой знак (как у команды `handoff`, `tools/README.md`, «Ключ `close`»): `--port --tenants x` — у `--port` нет значения, и `--tenants` не становится его значением; `--tenants` в конце, `--port=`, `--tenants=--x` — тоже без значения. Порядок проверки аргументов: слева направо каждый аргумент (лишнее слово, неизвестный ключ, повтор, нет значения), затем «нет `--tenants`», затем порт, затем папка. Первый найденный отказ — единственный. Вызовы ключей в любом порядке равны.

### 4.2. Вывод и коды выхода

Успех (stdout, пять строк; `<порт>` — настоящий порт; ссылки в порядке имён файлов, по строке на исправного арендатора):

    Сайт подбора запущен. Откройте ссылки:
    http://127.0.0.1:<порт>/t/svet-marketing/
    http://127.0.0.1:<порт>/t/uchet-pro/
    Изменения файлов арендаторов применяются после перезапуска.
    Остановить сайт: Ctrl+C.

Строк stderr при успехе нет, кроме блоков «не обслуживается» (п. 4.3).

| Код | Когда | Что печатается (stderr; stdout пуст) |
|---|---|---|
| 0 | сайт остановлен сигналом SIGINT или SIGTERM | ничего; сокет закрыт, открытые соединения закрыты |
| 0 | `--help` в любом месте | справка (п. 7, З5) в stdout |
| 1 | в папке нет ни одного исправного арендатора (пустая, нет `*.json`, все с ошибками) | блоки «не обслуживается» и `picker: В папке нет ни одного исправного файла арендатора. Исправьте файлы и запустите снова.` |

| 2 | неверный вызов или папку нельзя прочитать | одна строка `picker: <текст>` из таблицы ниже |
| 3 | ошибка программы | стек в stderr (без префикса `picker:`), stdout пуст |

Тексты кода 2 (имена папок и ключей — через `tame`: пробелы и управляющие знаки — «_», не больше 40 знаков; имя папки — последняя часть пути):

### 4.3. Файл с ошибками

Для каждого неисправного файла, в порядке имён, до запуска сервера, в stderr:

    Арендатор <имя файла> не обслуживается:
    <строки проверки REQ-054 как их печатает check, или одна строка отказа чтения>

Строки проверки — те, что даёт `checkBytes` (до 100 и «И ещё ошибок: N.»); отказ чтения — сообщение `PickerError` (ссылка, папка вместо файла, больше 512 КБ и т. д.). Имя файла в первой строке — `tame` (управляющие знаки — «_»), слова вроде `token` не скрываются (в строках самой проверки их имя по-прежнему скрыто — ISS-0077, п. 4, не закрывается этим требованием).

### 4.4. Остановка и устойчивость вывода

SIGINT и SIGTERM: сервер перестаёт принимать, закрывает все соединения (`closeAllConnections`), процесс завершается кодом 0 (замер: 3 мс). Если читатель stdout или stderr исчез (труба закрыта командой `head`), запись молча отбрасывается и сайт работает дальше (замер: после `| head -1` ответ 200). Никаких файлов команда не пишет (PK-6e).

### 4.5. Функции модуля `serve.js` (сигнатуры)

* `parseServeArguments(args: string[]) → { ok: true, tenants: string, home: string | null, port: number } | { ok: false, text: string }`.
* `startPicker(options, io) → Promise<{ ok: true, address: string, port: number, close(): Promise<void>, ids: string[] } | { ok: false, exitCode: 1 | 2, lines: string[] }>`; `options` — **закрытый** список: `tenants` (обязателен), `home`, `port`, `publicDir`, `bodyIdleMs`, `headersTimeoutMs`, `requestTimeoutMs`; `io` — `{ out(line), err(line) }`. Проверка параметров — в таком порядке, отказ возвращается значением (код 2), а не исключением: ключ вне списка → `Неизвестный параметр запуска <имя>.`; нет `tenants` или он пустой → текст «Не указана папка арендаторов…»; `port` не передан → 4782 (`DEFAULT_PORT`), не целое от 0 до 65535 → текст о порте; затем папка (п. 4.2). `runServe` передаёт только `tenants`, `home`, `port`. `address` — настоящий адрес сокета (`server.address().address`). REQ-062 допишет в список поле адаптера.
* `runServe(args, io, onStop) → Promise<number>`: разбор, запуск, печать, ожидание остановки; `onStop(callback)` вызывает `callback` один раз, когда процесс просят остановиться. `cli.js` передаёт `process.once("SIGINT" | "SIGTERM")`.
* `cli.js`: `serve` → `runServe(...)`; `run(argv)` может вернуть результат или обещание результата; точка входа ждёт его; `process.on("uncaughtException")` пишет стек в stderr и завершает процесс кодом 3; без `export`.

### 5.2. Арендаторы: чтение папки, реестр, версия

* `inspectDirectory(dir) → { ok: true } | { ok: false, text }` — `stat` папки; тексты кода 2 п. 4.2 (папки нет, не папка, нет права, другая ошибка системы).
* `loadTenants(dir) → { registry, notServed } | { error }` — `error` — одна строка отказа кода 2 (папка или больше 100 имён). Порядок: `inspectDirectory` → `readdirSync(dir, { withFileTypes: true })` → имена на `.json` → сортировка по кодовым единицам → для каждого `readTenantFile(join(dir, имя), { baseDir: dir })`, при `PickerError` — запись в `notServed` с его сообщением; иначе `checkBytes(bytes, fileName)`; код 0 — запись реестра, код 1 — `notServed` со строками проверки.
* Любое другое исключение (не `PickerError`) не ловится: это ошибка программы (код 3 для команды).
* `notServed` — список `{ fileName: tame(имя), lines: string[] }`.
* Запись реестра (заморожена): `id` (из проверенного файла; равен имени без `.json` — гарантирует E_ID), `fileName`, `version` (`fingerprintOf(bytes)` — те самые байты, что проверены), `languages` (`fileLanguages(tenant)`), `views` — `Map` «язык → глубоко замороженный `tenantInLanguage(tenant, язык)`», `questionnaires` — `Map` «язык → `Buffer` с `JSON.stringify(publicQuestionnaire(вид, { version, lang, languages }))`». `tenantInLanguage` вызывается только после кода 0 (D11).
* Реестр: `get(id) → запись | undefined` (по `Map`: `constructor`, `__proto__` — не арендаторы), `ids() → string[]` (в порядке имён файлов), `size`.
* `fingerprintOf(bytes: Uint8Array) → string` — sha256, 64 знака hex в нижнем регистре (`fingerprint.js`).
* К диску `tenants.js` обращается только как `fs.<функция>(…)` через объект по умолчанию (`fs.readdirSync`, `fs.statSync`), не разрушающим импортом, — как `load.js`: так внедрение сбоев (`tools/test/fault-inject.js`) подменяет эти вызовы (D30).
* Файл читается и проверяется один раз. После старта сервер к диску арендаторов не обращается (проверяется: файл изменён во время работы — ответы прежние; SV-2d).

### 5.3. Формы ответов

**Анкета** (`GET /t/<id>/api/questionnaire`, 200, `Content-Type: application/json; charset=utf-8`). Строится по полям функцией `publicQuestionnaire(вид, { version, lang, languages })` — новый простой объект; поле, не названное здесь, не копируется (белый список; новое поле файла в ответ не попадёт).

| Уровень | Поля (в этом порядке; «?» — только если есть в файле) | Правила |
|---|---|---|
| верхний | `version`, `lang`, `languages`, `name`, `intro`, `questions_min`, `questions_max`, `questions`, `ai`, `leads` | `version` — 64 знака hex; `lang` ∈ `languages`; `languages` — `["ru","kk","en"]` для `/2`, `["ru"]` для `/1`; `name`, `intro` — строки на языке `lang`; `questions_min` — число вопросов без `show_if`; `questions_max` — число всех вопросов; `ai` — `false`; `leads` — `null` или объект |
| вопрос | `id`, `title`, `help?`, `type`, `required`, `options?`, `min?`, `max?`, `unit?`, `show_if?` | значения равны файлу (тексты — на языке `lang`); `options`, `min`, `max`, `unit` — как в файле |
| вариант | `id`, `label` | |
| условие | `question`, затем один вид: `any_of` или `none_of` или `min` и/или `max` | как в файле |
| `leads` (не `null`) | `contact_fields`, `consent_text`, `operator_name`, `privacy_contact`, `retention_days` | `null`, если в файле нет `leads` или `leads.enabled` не `true`; `consent_text` — на языке `lang`; `operator_name`, `privacy_contact` — строка как в файле (`decisions/0070`, п. 1) |

Не уходят: правила (`rules`, `when`, `points`), решения (`solutions`), гипотезы, настройки `result`, `schema`, `id` арендатора, имя и путь файла, `enabled`.

**Результат** (`POST /t/<id>/api/result`, 200): `{ clear_leader, recommended, no_match_text, hypotheses }` — объект движка REQ-055 для вида файла на языке запроса **без `ranking`**. `recommended[]` — решения с полями движка (`id`, `name`, `summary`, `includes`, `needs_from_you`, `next_steps`, `price_text?`, `duration_text?`, `not_suitable_when`, `score`, `rules[]` с `id`, `points`, `text`, `because[]`); id нерекомендованных решений и их баллы в ответе не встречаются (SF-6m). Настроек `top`, `min_score`, `clear_lead_gap` нет и не будет.

**Тело запроса**: `{ "answers": { "<id вопроса>": <ответ> } }`. Других ключей нет.

**Ошибка**: `{ "error": "<код>", "message": "<текст>" }`, для `answers_invalid` ещё `"question": "<id вопроса этого арендатора>" | null`. Коды `error`: `not_found`, `forbidden`, `method_not_allowed`, `wrong_type`, `too_large`, `timeout`, `bad_request`, `answers_invalid`, `internal`. Ответ на неверный `Host` — без тела (`Content-Length: 0`).

`question` в `answers_invalid` — id вопроса из файла **этого** арендатора (ошибка «нет ответа на обязательный вопрос», «ответ не того вида» и т. д.); если движок вернул ключ, которого у арендатора нет (чужой или выдуманный посетителем), в ответе `null`, а сам ключ нигде не повторяется (D15). Причина (`reason`) не отдаётся: у списка с несколькими испорченными элементами она зависит от порядка (ISS-0077, п. 8).

### 5.4. Язык, тексты и ошибки

* `languageOf(query, languages) → "ru" | "kk" | "en"`: `new URLSearchParams(query).get("lang")` (первое значение) → `chooseLanguage({ query, available: languages })`. Значение вне трёх (`KK`, `de`, пустое, `kk,en`, с пробелом) — как отсутствие; язык, которого нет в файле, — ru (REQ-061, п. 7). Заголовки не читаются.
* `textOf(key, lang, values?) → string` — `TEXTS[key][lang]`, подстановка `{имя}` по таблице значений (замена функцией, не шаблоном: `$&` во вставляемом значении остаётся буквами); неизвестный ключ — ошибка программы. `textInAllLanguages(key) → string` — три языка через « / ». `errorBody(code, key, lang | null, values?, extra?) → string` — JSON `{ error, message, ...extra }`; `lang = null` — три языка в одной строке.

### 5.5. Страница и файлы `public/`

* Страница `GET /t/<id>/` — один и тот же файл `public/index.html` для всех арендаторов; данных арендатора в ней нет. Тип `text/html; charset=utf-8`, заголовки `Content-Security-Policy`, `X-Frame-Options: DENY`. Читается с диска на каждый запрос, как и все файлы `/assets/` (кэша нет); нет файла — ответ неизвестного пути.
* `assets.js` обращается к диску только как `fs.<функция>(…)` через объект по умолчанию (`fs.openSync`, `fs.fstatSync`, `fs.readFileSync`, `fs.closeSync`), как `load.js` (D30; SF-6h подменяет `fs.openSync`).
* `readAsset(dir, name) → { type, bytes } | null`: имя по `STATIC_NAME`, без «..», расширение из `STATIC_TYPES`; файл открывается с `O_NOFOLLOW` и `O_NONBLOCK`, должен быть обычным файлом; ссылка, папка, труба, нет файла, слишком длинное имя — `null` (404); любая другая ошибка системы — исключение (500).
* `GET /assets/<имя>`: все файлы `public/` с допустимым расширением (сейчас `index.html`, `stub.js`, `texts.js`). Данных арендаторов в них нет.
* `index.html`: `<!doctype html>`, `<html lang="ru">`, `<meta charset>`, `<meta name="viewport">`, `<title>Sai</title>`, `<main id="app"></main>`, `<script type="module" src="/assets/stub.js">`. Ни встроенных `<script>` и `<style>`, ни атрибутов `style` и `on…`, ни адресов с `http://` и `https://`.
* `stub.js`: `import … from "./texts.js"` (относительный адрес — работает и в браузере, и в Node, где тест его загружает); берёт `lang` из `location.search` через `chooseLanguage({ query, available: LANGUAGES })`, ставит `document.documentElement.lang`, кладёт `TEXTS.page_stub_notice[язык]` в `#app` как текст (`textContent`). Ни `fetch(`, ни `new URL(`: ветка TR-4e для файлов страницы в этом требовании не нужна, а нужен только блок `eslint` (п. 7).
* REQ-057 заменяет `index.html` и удаляет `stub.js` и ключ `page_stub_notice` (п. 12).

**Запросы, которые отвергает разборщик HTTP** (Ф20, Ф23) до нашего кода получают ответ обработчика `clientError` (D28): закрытый ответ — строка состояния, общие заголовки п. 5.7 (`Cache-Control`, `X-Content-Type-Options`, `Referrer-Policy`), `Content-Type: application/json; charset=utf-8`, верный `Content-Length`, `Connection: close`, тело `{ "error", "message" }` с тремя языками в одной строке (`textInAllLanguages`), без текста исключения и кода Node; после ответа соединение закрыто. Если сокет уже закрыт — он уничтожается без ответа.

| Что отвергнуто (код ошибки Node) | Ответ | `error` | Ключ `TEXTS` |
|---|---|---|---|
| заголовок больше 16 КиБ (`HPE_HEADER_OVERFLOW`) | 431 | `too_large` | `server_too_large` |
| заголовки или запрос не дошли за `HEADERS_TIMEOUT_MS` / `REQUEST_TIMEOUT_MS` (`ERR_HTTP_REQUEST_TIMEOUT`) | 408 | `timeout` | `server_slow` |

HTTP/1.1 без заголовка `Host` Node по умолчанию отвергает сам; `requireHostHeader: false` в `http.createServer` отдаёт такой запрос нашему коду, и он получает 403 п. 5.6 строки 1 (HTTP/1.0 без `Host` — тоже). Тексты ответов этого раздела не зависят от языка запроса: язык ещё неизвестен.

### 5.7. Защита

**Заголовки.** На каждый ответ нашего кода: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Content-Length` (точный). На ответы `text/html` (страница и `/assets/index.html`) ещё `Content-Security-Policy` (п. 5.1) и `X-Frame-Options: DENY`. Заголовков `Access-Control-*`, `Server`, `Set-Cookie`, `X-Powered-By` нет. Node сам добавляет `Date`, `Connection`, `Keep-Alive` — одинаковые у всех ответов, кроме `Date`. `Allow` — у 405, `Location` — у 308, `Connection: close` — у 408.

**Host и Origin.** Сравнение строгое и целиком: `Host: 127.0.0.1` (без порта), чужой порт, `LOCALHOST:<порт>`, пустой, `[::1]:<порт>` — 403. Два заголовка `Host`: Node оставляет первый (Ф20), проверяется он. `Origin` `null`, другого порта, `https://…`, с «/» на конце, в верхнем регистре — 403; `Origin` нет — 403 (D16). Страница REQ-057 вызывает `fetch` **без** `mode: "same-origin"` и без `referrerPolicy`, иначе браузер может послать `Origin: null` (по спецификации Fetch для режима, отличного от `cors`, и политики `no-referrer`) — проверяется шагом приёмки REQ-057 в браузере; Q3: здесь это не утверждается как факт, а передаётся как условие.

**Размеры и времена.** Таблица п. 5.1. Тело больше 16384 — 413; после отказа остаток тела сбрасывается, но не больше 8 МиБ и только пока данные идут не реже раза в 5 с, иначе соединение закрывается (SF-6b: 40 МиБ потоком — соединение закрыто раньше). Заголовки: больше 16 КиБ — 431, чтение заголовков дольше 10 с или всего запроса дольше 30 с — 408 (разборщик Node ловит, проверка раз в секунду; ответ даёт обработчик п. 5.6). Пауза в теле 15 с — наш 408 (SF-6i с короткой паузой через `bodyIdleMs`).

**Q9, Q11.** SQL нет. Сервер не ходит по адресам: адрес из запроса нигде не используется как адрес; `id` арендатора — ключ в `Map` после проверки правилом; `Host`/`Origin` — только сравнение строк. Поиск `grep` п. 9 (критерий 8) пуст.

### 5.8. Изоляция арендаторов (Q8) — правила, которые держат тесты

* **И1.** Единственный источник арендатора — `found.id` из `routeOf(путь)`. Заголовки запроса читаются только четыре: `host`, `origin`, `content-type`, `content-length` (статический тест SV-4e).
* **И2.** На запрос приходится один вызов `registry.get(found.id)`; обработчики не обходят реестр (`ids()`, `values()`, `entries()`, `keys()` в `server.js`, `request.js`, `public-data.js` нет — SV-4e).
* **И3.** Всё тело ответа строится из одной записи реестра и ответов этого запроса. Нет изменяемых переменных уровня модуля в `server.js`, `request.js`, `public-data.js`, `messages.js` (нет `let` вне функций — SV-4e) и общих таблиц между арендаторами (мутант М48); записи заморожены.
* **И4.** Ответы посетителя проверяет движок по вопросам этого арендатора; ключ, которого у него нет, — ошибка ответов, а не ответ (SV-4b).
* **И5.** Что в ответ не попадает, решает белый список (`publicQuestionnaire`, `publicResult`), а не страница (SV-2g).
* **И6.** Любая чужая строка в ответе — ошибка: ни текстов, ни id другого арендатора ни в одном ответе (SV-2c, SV-4b, SP-3, шаг приёмки п. 6.3).
* **И7.** Неизвестное одинаково неизвестно: п. 5.6 строки 2 и 5 дают один `notFound`.

### 5.10. Интерфейс для REQ-057…REQ-063 (меняется только вместе с ними)

* **Страница (REQ-057/058).** Адрес страницы `/t/<id>/` — со «/» на конце, поэтому относительные адреса `api/questionnaire` и `api/result` ведут под `/t/<id>/` и арендатор в них — тот же. Файлы страницы — `/assets/<имя>` из `public/` (только `.html`, `.js`, `.css`; других расширений сервер не отдаёт — например, `.svg` и `.json` нет). `engine.js` не отдаётся: как страница получит «одно правило видимости на сервере и в странице» (REQ-057), решает проект REQ-057 (вопрос О12). `fetch` страницы — без `mode: "same-origin"` (п. 5.7). Язык: `?lang=` в каждом запросе страницы к серверу; сервер сохранённого языка не знает.
* **Заявки (REQ-059).** Новый вид маршрута `lead` в `routeOf`, обработчик в `server.js`, хранилище — отдельный модуль записи (`WRITE_MODULES` п. 7). Для арендатора без заявок (`leads === null` в записи) обработчик вызывает `notFound` — тот же ответ, что и неизвестный путь. `home` приходит в `startPicker`.
* **Совет ИИ (REQ-062/063).** Вид `advice`, поле `advisor` в `options` `startPicker`; анкета сообщает `ai: false` до тех пор; `/api/result` не меняется.
* **Команды `new`, `leads`.** Добавляются в `COMMANDS` `cli.js`; справка и «Доступны: …» растут литералами таблицы п. 7.
* **Тексты.** Новые ключи `TEXTS` с префиксами `lead_`, `advice_`; ключи `server_*` — из этого требования; все новые ключи должны пройти запрет слов REQ-057 (тест SU-10 — образец).
* **Запись реестра** — поля п. 5.2; `view.leads.consent_text` на языке запроса берётся из `views.get(lang)`.
