## 1. Что не так и что выбрано

Строка `.item` (панель «Задачи», карточка агента) собирается одной функцией `itemInto` в `tools/src/pixel-office/public/app.js`: внутри `.item-head` стоят два соседа — название `.item-role` и плашка `.item-state` со словом состояния. Три правила `tools/src/pixel-office/public/style.css` вместе дают дефект:

1. `.item-head` — `display: flex` без `flex-wrap`: сосед всегда в той же строке.
2. `.item-state` — `flex: none`: плашка не сжимается, её ширина — ширина слова (300 px у «сервер перезапускался, события не записывались»).
3. `.item` — `overflow-wrap: anywhere`, наследуется названием: минимальная ширина названия — одна буква, поэтому плашка забирает 300 px, а названию остаётся остаток (20 px в основном окне, 11–12 px в окне 375) и оно ломается по буквам.

Дефект — в части «страница» (CSS). Слово, состояние, журнал, хук и сервер верны; R2 не затронут.

**Выбор.** Шапка строки переносится (`flex-wrap: wrap` у `.item-head`): если название и плашка вместе не помещаются, плашка уходит отдельной строкой под название; плашка не шире строки (`max-width: 100%` у `.item-state`); вертикальный зазор между перенесёнными соседями — 2 px вместо 8 (`gap: 0.125rem 0.5rem`). Тексты, разметка, порядок, цвета, `data-state` не меняются.

**Почему не проще** (измерено в диагнозе на копиях вне проекта, окно 1470×784, стенд СТ-3 после перезапуска):

| Вариант | Результат | Вывод |
|---|---|---|
| В1: убрать только `overflow-wrap: anywhere` у `.item` | название не рвётся по буквам, но основная сессия 96×78 px (4 строки), строка 134 px | корень не в нём: плашка 300 px не сжимается и не переносится |
| В2: `.item-state { flex: 0 1 auto }` | `Explore` 45×39 px (две строки по буквам), плашка двухстрочная | ослабление `flex-shrink` не помогает |
| В5: В2 и `.item-role { flex: none }` | плашка 39×223 px, нечитаема | сжатие плашки хуже переноса |
| **В3b: `flex-wrap: wrap` + `gap: 0.125rem 0.5rem` + `max-width: 100%`** | название в одну строку в окнах 1470, 390, 375; плашка под ним, если не помещается; строка основной сессии 95–112 px | **выбрано** |

## 4. Изменения

### 4.1. `tools/src/pixel-office/public/style.css` (единственный файл кода)

Правила заменяются целиком; все остальные строки обоих правил остаются как есть. Единицы — `rem` (охранный тест PN-22 допускает `px` только у линий 1–2 px).

```css
.item-head {
  display: flex;
  flex-wrap: wrap;
  align-items: baseline;
  justify-content: space-between;
  gap: 0.125rem 0.5rem;
}

.item-state {
  flex: none;
  max-width: 100%;
  padding: 0.0625rem 0.4375rem;
  border-radius: 62.4375rem;
  font-size: 0.65625rem;
  font-weight: 700;
}
```

Разница с текущими правилами (строки 631–636 и 646–652): в `.item-head` добавлена строка `flex-wrap: wrap;` после `display: flex;`, и `gap: 0.5rem` стало `gap: 0.125rem 0.5rem`; в `.item-state` добавлена строка `max-width: 100%;` после `flex: none;`.

Что делает каждое свойство:

- `flex-wrap: wrap` — если название и плашка вместе не помещаются в шапку, плашка уходит на вторую строку; название остаётся в первой. Это снимает сжатие названия в любом окне.
- `max-width: 100%` — плашка никогда не шире шапки; слово, которое не помещается, переносится по словам внутри плашки (`overflow-wrap: anywhere` рвёт по буквам только слово, шире всей строки, чего у слов состояний нет).
- `gap: 0.125rem 0.5rem` — вертикальный зазор между перенесёнными соседями 2 px (критерий 14 (в): «отступ между плашкой и названием»), горизонтальный — как был.

### 4.2. Что НЕ меняется

- `tools/src/pixel-office/public/app.js` (`itemInto`, `historyState`, `sessionCard`): разметка, классы, порядок соседей, `data-state` те же.
- `texts.js` (слова), `index.html`, сервер, хук, журнал, модель (`model.js`, `panels.js`, `history.js`).
- Правила `.item`, `.item-role`, `.card-section .item`, `.history-state` (и все `[data-state=…]`), `.history-meta`, `.history-table`, `.session-badge`: ни одного изменения. `overflow-wrap: anywhere` у `.item` остаётся (на неё опирается перенос неизвестной роли в 60 знаков).
- Цвета и контраст слов (`FS-20`, `ISS-0063`): не затронуты.

### 7.2. Регрессионный тест PN-23

- **Файл:** `tools/test/pixel-office-panels.test.js` (импорты `fs`, `path`, `PUBLIC`, `parseCss`, `cssDecls` там уже есть; новых зависимостей нет).
- **Имя (смысл):** «PN-23: the CSS rule of the row (ISS-0062, REQ-042 criterion 14) — the head of an item may wrap and the word may not outgrow the row, the layout properties of the word do not depend on its state; this checks the rule of the CSS, not the view (the view is measured in the acceptance)».
- **Чтение:** `style.css` из `PUBLIC` через `parseCss`, как FS-20; без `process.env`, без браузера, без сети. Тест не пишет файлов.
- **Что проверяет** (раскладочные свойства — перечень п. 4.3):
  - **А.** `cssDecls(rules, ".item-head").get("display") === "flex"`.
  - **Б.** `cssDecls(rules, ".item-head").get("flex-wrap") === "wrap"`; ни одно правило `.item-head` внутри `@media` не задаёт `flex-wrap` (проверка по всем значениям `media`, кроме `null`).
  - **В.** `cssDecls(rules, ".item-state").get("max-width") === "100%"`; `white-space` у `.item-state` не `nowrap` и не `pre`.
  - **Г.** Раскладочные свойства `.history-state`, заданные в правиле, — ровно `display`, значение `inline-block`.
  - **Д.** Все правила, один из селекторов которых оканчивается на `.item-state` или `.history-state` (с любым числом `[…]`) и не равен самому `.item-state` / `.history-state`, не задают раскладочных свойств. Количество таких правил — не меньше 8 (сегодня 8: 654, 659, 664, 669, 952, 957, 962, 967); меньше — тест красный (поиск ничего не нашёл — не проходить молча, Q6).
  - **Е.** Внутри любого `@media` ни `.item-state`, ни `.history-state` не задают раскладочных свойств.
- **Красный до, зелёный после:** тест добавляется на клон репозитория на метке (`git clone` проекта вне проекта, дерево на метке `base/ISS-0062-20261013-01`) — красный: `AssertionError … expected: 'wrap'` (часть Б); в проекте с исправленным `style.css` — зелёный. Не брать для «красного до» копию одного `tools/` (`context.pre_fix_copy`): в ней 43 теста Pixel Office красные по среде (диагноз, I10, AP-074).
- **Прототип** (вне проекта, на клоне, Ф12): на метке красный, после исправления зелёный.
- **Оговорка в самом тесте:** комментарий: «проверка правила, а не вида; вид — замер в приёмке REQ-042».
- В `npm run check` браузерную проверку не вводить: она зависела бы от установленного Chrome, а отсутствие превратилось бы в пропуск (Q6).

### 8.2. Откуда брать h для места (2) (замечание G1 ворот)

Критерий берёт h у «плашки того же элемента со словом „в работе“ в том же окне». Для места (2) проект предлагает:

1. **Основной путь.** На шаге (i) (до перезапуска) BA-ANALYST добавляет открытие окна «Просмотр истории» для задачи `Plan` («в работе») в обоих окнах и замер `.history-state` в `.history-meta` — это и есть h места (2) (ожидается 18 px).

Допустимо, потому что у `.item-state` и `.history-state` совпадают `padding` (`0.0625rem 0.4375rem`), `font-size` (`0.65625rem`) и `font-weight` (700) — высота одной строки одна и та же (измерено в диагнозе: 18 и 18 px).

Проект не добавляет в PN-23 проверку равенства этих свойств: это было бы ограничение вида, которого в критерии нет (О2).
