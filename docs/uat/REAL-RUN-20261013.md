## Итоговая страница целиком

Это содержимое файла `t-0006-1-tips_cafe.md` (последняя версия страницы), без правок.

> # Как получить первых 10 постоянных клиентов кофейни
>
> ## 1. Запоминайте гостей лично
>
> - Суть: ведите простой лист гостей (бумажный блокнот) — записывайте имя, любимый напиток и одну деталь о госте после 2–3
>   визита.
> - Почему работает: когда бариста узнаёт гостя и его напиток без напоминания, человек чувствует, что его здесь ценят, и
>   возвращается снова.
> - Первый шаг: сегодня начните лист гостей и записывайте туда тех, кто заходит второй раз.
>
> ## 2. Бумажная карта «6 напитков — седьмой в подарок»
>
> - Суть: сделайте 20 простых бумажных карточек с отметками на каждый напиток; после шестой отметки гость получает седьмой
>   напиток.
> - Почему работает: седьмой напиток — не автоматическая скидка по программе, а конкретный подарок с личным жестом
>   (например, бариста сам вручает его и благодарит гостя за визиты), и это запоминается сильнее, чем просто процент
>   скидки.
> - Первый шаг: на этой неделе сделайте первые 20 карточек и начните выдавать их постоянным гостям.
>
> ## 3. Соседи и соцсети — без бюджета на рекламу
>
> - Суть: договоритесь о взаимной поддержке с 2–3 соседними бизнесами (например, обмен флаерами или небольшая скидка друг у
>   друга) и ведите одну соцсеть лично, отвечая на комментарии.
> - Почему работает: рекомендация от соседнего бизнеса и живое личное общение в соцсети создают доверие быстрее и дешевле
>   любой рекламы.
> - Первый шаг: сегодня зайдите к одному соседнему бизнесу и договоритесь о взаимной поддержке; на этой неделе сделайте
>   первый личный пост в соцсети.

Оценка по цели: три совета (ровно три), у каждого суть, причина и первый шаг, язык простой, обращение «вы», рекламного

1. **Маскирование спрятало адреса источников в исследовании (низкая важность: критерии не нарушены, но источник не проверить).** В файле Исследователя два адреса
   выглядят так: `https://[скрыто]/blog/35618/` и `https://[скрыто]/items/0c997492-…` (источники education.ua и
   исследование University of Wisconsin). Причина: правило маскирования «три части через точки» принимает адрес хоста из
   трёх частей (например, `minds.wisconsin.edu`) за токен; я проверил это чтением функции маскирования на трёх обычных
   адресах — трёхчастный хост скрывается, двухчастные (например, `education.ua`, `kontur.ru`) нет. Для секретов это безопасная ошибка, но источник
   читатель проверить не может. Предлагаю ORCH завести дефект.
2. **В записи проверки лежит обрывок разметки (низкая важность).** В замечаниях проверки задачи t-0004 (событие 89) в
   конце остались служебные теги `</notes>` и `</invoke>`: ответ модели с лишними тегами принят как есть. На решение
   «прошла» это не влияет, но попадёт на страницу, если там показываются замечания проверяющего. Остальные пять проверок
   чистые.
3. **Опечатка на итоговой странице** («2–3 визита») — выше; правка на усмотрение владельца.
4. **Задача, которая называет файл, получает только прямые зависимости (вопрос к BA-ANALYST и ORCH).** У t-0006 в плане
   сказано: «утвердить финальную версию `tips_cafe.md`», этот файл сдала t-0004, а зависимость t-0006 — только t-0005 (по
   коду `depsOf` ядро выдаёт содержимое файлов только задач из `depends_on`). Видела ли t-0006 текст t-0004, по журналу
   сказать нельзя: вход запуска не сохраняется. Итоговая страница получилась хорошей, и критерий 15 говорит только про
   файлы предыдущего круга, поэтому нарушения критерия здесь нет; но то же самое внутри одного круга критерием не охвачено.
   Проверяющий t-0005 сам написал, что содержимого `tips_cafe.md` не видел, — это ожидаемо: проверяющий получает файлы только

## Остаточные риски

- **Форма согласия.** Критерии 13 и 14 требуют письменного согласия владельца «в сессии» и потолка, который назовёт владелец.
  Владелец поручил ORCH решить пункт о запуске и потолке (`decisions/0048`), потолок «не больше 3 USD» записан ORCH. Запуск
  уложился в запись, но владелец сам названного числа не говорил. Если нужен строгий смысл критерия, согласие стоит получить
  отдельным словом.
- **Один запуск — одна цель.** Простая цель с идеальным ходом (без неудач, без второго круга) показывает, что основной путь

  исследование само честно отметило.
- **Оценка расхода** взята у самого Claude Code, независимо я её не сверял.

## Как повторить

Настоящий запуск тратит лимит подписки владельца, поэтому делается только по его слову. Команды из каталога `tools/`; путь
к Claude Code и папку данных задаёт владелец:

```
SAI_TEAM_REAL_RUNS=1 SAI_TEAM_CLAUDE_BIN=<абсолютный путь к claude> SAI_TEAM_HOME=<новая пустая папка вне проекта> \
  npm run team -- new --goal "<цель>" --budget 3
SAI_TEAM_REAL_RUNS=1 SAI_TEAM_CLAUDE_BIN=<абсолютный путь к claude> SAI_TEAM_HOME=<та же папка> \
  npm run team -- start <id проекта> --parallel 2
```

Проверка уже готового запуска (только чтение, ничего не тратит):

```
SAI_TEAM_HOME=<папка данных> npm run team -- project <id проекта>
SAI_TEAM_HOME=<папка данных> npm run team -- events <id проекта> --after 0
SAI_TEAM_HOME=<папка данных> npm run team -- events <id проекта> --after 50
SAI_TEAM_HOME=<папка данных> npm run team -- events <id проекта> --after 100
```

Следующую страницу берут из поля `next_after` предыдущего ответа; когда там `null`, журнал закончился. Расход — сумма
`data.cost_usd` у событий `BUDGET_SPENT`; она должна совпасть с последним `data.total_usd` и с `spent_usd` в ответе `project`.
Порядок «готово» только после проверки — каждому событию `TASK_DONE` предшествует событие `REVIEW_RESULT` той же задачи с
`passed: true`.
