## Incident of the first deploy command (recorded as ORCH reported it)

The first `vercel deploy --prod` was started from the export root instead of the `app` folder inside it. The upload held
121 files (the `.vercelignore` of `app/` was not applied); the build ran no install and no `vercel-build` and produced an
empty output ("Build Completed in /vercel/output [141ms]", "Skipping cache upload because no files were prepared"); the
alias answered 404 NOT_FOUND on every path (the smoke check failed 6 of 7) from about 22:13:48Z to about 22:16Z. ORCH saw it
in the smoke check at once and redeployed from inside the app folder (63 files; install and `vercel-build` ran; "Build
Completed [8s]"); the smoke check then passed 7 of 7 with version `dd54f43`. Visitors saw a 404 for about two to three minutes
at night. Cause: the working folder of the deploy command; the recorded method said "in the export", read as the export root.

- **What I could confirm:** the site answers 200 now on `/`, `/how.html`, `/demo.html` and the assets, and 21 of 21 files of
  the build output are served byte for byte (no leftover of the empty first build). The health version is `dd54f43`.
- **What I could not confirm:** the 404 window itself (it was over before I started), the file counts (121 and 63), the
  build log lines and the smoke result: the Vercel side is not visible to me and I ran no Vercel command.
- **Lesson written down:** the deploy command runs inside the app folder of the export (`app/`, where `vercel.json` and
  `.vercelignore` are); the smoke check caught the fault within the same minutes; the first thing to read after any deploy is
  the smoke result and the file count of the upload line (63, not 121). ORCH adds it to the runbook and to memory (the
  modified `docs/runbooks/release.md` in the working tree is ORCH's, not mine).
