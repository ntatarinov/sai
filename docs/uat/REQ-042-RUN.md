## Как проводился прогон

- **Стенд.** Каждому сценарию — свой настоящий сервер Pixel Office из `tools/` (`node src/pixel-office/main.js --port <порт>`, то есть команда `npm run pixel-office` без обёртки) на **новом пустом каталоге состояния вне проекта** (`<вне проекта>/uat042/stands/<имя>`, `SAI_PIXEL_OFFICE_DIR` общий для сервера и хука), свой порт (47410–47475), свой секрет записи (создаёт сам сервер). Рабочий сервер владельца и его каталог не использовались. Каталог каждого стенда создавался заново: в ответе сервера ровно записанные строки и записи запусков.
- **События.** Живые — настоящей программой-хуком `hook.sh` (поля по таблице сценариев), запись оркестратора — командой `npm run pixel-office-note`. Молчащая и давняя работа — **дописыванием строк в `events.jsonl` стенда после последнего запуска сервера**, пока он работает; «сервер перезапускался» — остановкой (SIGINT) и новым запуском на том же каталоге и порту. Блоки готовились по рецепту BA-ANALYST с поправкой его расхождения I1 (строки дописываются после запуска, а не до него) и дали состояния, описанные в таблице стендов.
- **Страница.** Настоящий Chrome в режиме без окна, управление по протоколу отладки (щелчки по холсту и по кнопкам, клавиши Tab, Enter, Esc, наведение). Окна 1470 × 784 (все сценарии) и 375 × 812 (сценарий 37). Часы страницы — часы компьютера. «Свежесть стенда» (35 минут) соблюдалась: каждая группа сценариев готовилась заново.
- **После каждого действия** запрашивалось заново: ответ сервера (`GET /api/events?after=0`: код, строки журнала, записи запусков), текст страницы (в том числе подписи, которые рисует стиль: «последнее событие сессии», «конец»), дерево страницы, снимок. Слова на холсте офиса (облачки, экраны ноутбуков, доска) проверялись по снимкам глазами.
- **Подсказки при наведении** (сценарии 03, 07, 16, 28) проверены по атрибуту `title`: безголовый Chrome нативную подсказку не рисует.

В проект ничего из этого не входит.

**Ф1. Сценарий 12, шаг «живое событие конец задачи» — ВЫС (по документу); вероятная ошибка ожидания.**

- Предлагается: BA-ANALYST решает, чьё это расхождение. Если ожидание ошибочно — поправить «Ожидается» (строка основной сессии «в работе», «Сейчас» называет её); чтобы проверить, что молчащая строка остаётся молчащей, нужна другая сессия.
