# Release report E2E106-20261115-01 - REQ-106: Pixel Office tested end to end in a real Chrome

Report date: 2026-11-16 (UTC, from the clock). Process: WF-02 for REQ-106; the requirement itself was written and
accepted in the WF-01 run `E2E-20261103-01` (`handoffs/E2E-20261103-01/`). The push to `main` is an ordinary push under
`decisions/0048`, `0079` item 1 and `0110` item 4, after the PASS of RELEASE-VALIDATOR
(`handoffs/E2E106-20261115-01/step-09-release-validator.json`). Bookkeeping is by DOC-UPDATER
(`step-10-doc-updater.json`), checked by ORCH (`context.orch_check`, verdict PASS). The repository is open to everyone
on purpose (read on GitHub on 2026-11-16 at 01:26:45Z: `PUBLIC`, `isPrivate` false; `decisions/0111`). The report is in
English by `decisions/0080`, item 2.

**In short.** `npm run check` now also opens the Pixel Office page in a real Chrome against a real Pixel Office server
started in throwaway folders, and sends events only through the real hook program. It proves the claim of REQ-001: a
new event is on the page within 5 seconds, without a reload. It also checks that the journal rows say the words of the
README table, that a key-shaped secret in a task description is masked on the page and in the stored file, that the
owner's real Pixel Office folder is not touched, that the page says «Нет связи с сервером Pixel Office» when the server
goes away and comes back when it returns, and that the page works in the windows 1470×784, 390×844 and 320×568. Every
test server of the kit now gets a private home folder and checked folder paths, so no stand can reach the person's
home folder or the real Pixel Office folder. REQ-106 is `done`: all 8 criteria are met (criteria 3, 4, 5 and 7 with
the readings named below). The code of Pixel Office (`tools/src/`) was not changed. REQ-107 is not built.

## What was done

  hook helper go to a spawn that records and throws and is called 0 times; the state folder holds only the five files
