Report date: 2026-10-27 (UTC, from the clock). Process: WF-02, requirement REQ-070 (part 2 of the new office of the picker site),
with the micro-amendment `MA070-20261027-01` made after the first design pass. The push to `main` is made under `decisions/0048`

**In short.** The picker site now has two invented demo tenants written in the new format /3: `stock` (stock control) and `agency`
(marketing). Each has 5 questions, 4 solutions, 15 rules, a full `look` (badge, door sign, headline, colours for the light and the
dark theme, four staff members), a desk and an office object for every question, quick numbers, a WhatsApp number and lead settings.
Every visitor text is in Russian, Kazakh and English (189 three-language texts in all). Each tenant has an answer file with four sets: `leader`
(one clear leader), `close` (two close solutions), `none` (nothing fits) and `half` (the first two answers only). Nothing in the
engine, the server or the format changed: this release is data, one test file and one paragraph of the README. `npm run check` is
green: 2065 tests, 2065 pass, 0 skipped, 0 todo (it was 2044 before the run).

**The stand command.** `cd tools && npm run picker -- serve --tenants src/picker/demo-tenants-v3 --home <a folder outside the project>`
prints two links, `/t/stock/` and `/t/agency/`. The old stand (`--tenants src/picker/demo-tenants`, formats /1 and /2) is not touched.
The answer sets are in `tools/src/picker/demo-answers-v3/`.

**What the owner cannot see yet.** No page draws this data: the office on the site is REQ-071. The set `half` is meant for the live
result (REQ-072); the result command refuses it today because the questions it leaves out are required. The request form is REQ-059
and REQ-076, so the invitation texts "leave a request" lead nowhere yet. The Kazakh texts have not been read by a person who knows
Kazakh (see below).
