# Отчёт о выпуске TEXT068-20261021-01 — запрет управляющих и невидимых знаков в текстах арендатора (REQ-068)

Дата отчёта: 2026-10-21 (время с часов, UTC). Процесс — WF-02, выпуск требования REQ-068; вместе с ним уходит прогон WF-01
`PICKERTEXT-20261021-01` (запись требования REQ-068 и микроправки, все шаги закрыты). Отправка в `main` — по `decisions/0048`
после PASS RELEASE-VALIDATOR (`handoffs/TEXT068-20261021-01/step-07-release-validator.json`); учёт ведёт DOC-UPDATER
(`step-08-doc-updater.json`), сверка ORCH записана в его `context.orch_check`.

**Коротко и прямо.** Файл арендатора больше не принимает управляющие и невидимые знаки в текстах. Раньше такие знаки позволяли
обойти правила «фраза не длиннее 18 слов» и «без обращения на ты» и могли ввести посетителя в заблуждение (например, знак,
который переворачивает порядок букв на экране). Теперь проверка файла отвергает такой текст и называет знак кодом, например
`U+200B`. Решение — `decisions/0076` (с тремя дополнениями), дефект ISS-0078 закрыт. Один остаток остаётся открытым осознанно
(ниже, «Что не закрыто»).

## Что готово

- **Проверка файла арендатора** (`npm run picker -- check`) отвергает управляющие знаки (кроме пяти пробельных: табуляция,
  переносы и подобные), невидимые знаки форматирования, разделители строк и абзацев, а также «половинки» знаков (одиночные
  суррогаты). Это работает для названий, вопросов, вариантов и пояснений, на русском, казахском и английском, в обоих форматах
  файла. Ошибка — `E_TEXT` с кодом первого запрещённого знака.
- **Порядок проверок в тексте:** тип, запрещённый знак, длина, правила слов. Знак проверяется раньше длины, чтобы невидимый знак
  не менял подсчёт.
- **Сообщения команды не содержат знака-замены** (U+FFFD): одиночные «половинки» знаков в выводе заменяются так же, как
  управляющие.
- **Сервер не обслуживает такого арендатора:** файл со знаком, обошедший проверку, отвечает как неизвестный арендатор (404).
- **Не затронуто допустимое:** пробелы, неразрывные пробелы в числах, простые эмодзи (в том числе с вариантом оформления
  U+FE0F), буквы всех трёх языков.
- Перечень знаков лежит в одном месте (`tools/src/picker/text-rules.js`, функция `forbiddenSign`); `validate.js` и `places.js`
  её вызывают, старая проверка в `places.js` убрана.

## Как проверяли

- **Одна команда проверки** (`cd tools && npm run check`): на метке до работы 1862 теста, после работы 1898 (36 новых), все
  зелёные, пропусков нет. RELEASE-VALIDATOR прогнал её сам (код 0); результат запуска в этом шаге — в `result.self_check`
  handoff-а шага 9.
- **Перебор всего Юникода двумя независимыми способами:** оракул, записанный по описанию литералами, и свойства самого движка;
  расхождений 0. Запрещено ровно 232 знака, допустимо 1 111 832. Одиночные половинки (2048 значений) отвергаются все; из пар
  1024 × 1024 запрещены 127 (знаки форматирования вне основной плоскости), допустимы 1 048 449.
- **Обход мест файла:** 16 688 случаев по всем местам (1192 места, 19 видов), ошибок 0.
- **4000 враждебных файлов** (генератор проверяющего): все 4000 отвергнуты кодом `E_TEXT`.
- **Сервер:** файл с запрещённым знаком не обслуживается.
- **Защита от зависания:** текст из 400 000 знаков отвергается за 14 мс, 100 000 одиночных половинок — за 16 мс.
- **Намеренные поломки (мутанты)** TEST-DESIGN-VALIDATOR и RELEASE-VALIDATOR: пойманы тестами; два эквивалентных мутанта
  приняты и записаны в ISS-0077.
- Ворота прогона: проект кода — PASS со второй попытки (первая — FAIL по одному блокирующему замечанию, исправлено); проверка
  безопасности, ревью, тесты, запуск — PASS; RELEASE-VALIDATOR — PASS (10 критериев из 10, два замечания Low закрыты DOC-UPDATER:
  имя файла теста в критерии 9 и оговорка в README).

## Что НЕ закрыто и что не доказано

- **Часть невидимых знаков пока допустима.** Это знаки, которые невидимы, но не относятся к управляющим и не относятся к знакам
  форматирования: их около 4 тысяч (точно 4036 по Юникоду 17.0). Полный перечень — в `docs/issues/ISS-0085-...md`. Всё свойство
  целиком запретить нельзя: оно захватило бы допустимые эмодзи. **Решение о коротком явном списке — за вами.**
- **Перенос строки внутри текста не запрещён** (решение 0076, п. 5): демо-файлы без переносов проверяет отдельный тест.
- **Склеенные эмодзи запрещены:** знак склейки U+200D входит в запрещённые, исключения для него нет (п. 6). Эмодзи из нескольких
  частей, склеенные этим знаком, файл не пройдёт; простые эмодзи и эмодзи с U+FE0F проходят.
- **Перечень привязан к версии Юникода Node 22.x** (в тесте закреплено 17.0). Другая версия движка Юникода сделает тест TT-1a
  красным осознанно, с требованием обновить перечень и числа; на раннере GitHub версия может быть иной — результат запуска
  `check.yml` указан в handoff-е этого шага.
- Мелкие замечания (имя вспомогательной функции неточно, код ошибки собирается внутри `validate.js`) записаны в ISS-0077,
  пп. 19–22. Страницы REQ-059 и REQ-060 при стройке берут тот же перечень знаков.
