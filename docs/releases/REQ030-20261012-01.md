## Что не сделано и почему

- **Критерий 2 REQ-030 не выполнен.** Запуск `check.yml` на GitHub на отправленном коммите — шаг 12 (отдельная проверка
  RELEASE-VALIDATOR после отправки). Этот шаг его не ждёт и не проверяет. До него утверждение «проверка на GitHub
  работает» не доказано.
- **Критерий 3 REQ-030 не выполнен.** Красная ветка (намеренно падающий коммит в отдельной ветке и проверка, что
  GitHub его краснит) требует отдельного согласия владельца; оно не дано. Никакие ветки, кроме `main`, не отправлялись.
- **Workflow на Linux-раннере не запускался.** Всё, что проверено, проверено на macOS локально и на чистой копии.
- **REQ-030 остаётся `in_progress`.**
- **Видимость репозитория.** Документы называют репозиторий приватным, а по проверке чтением GitHub он публичный
  (ISS-0049; вопрос владельцу: оставить публичным и исправить документы, или сделать приватным). Настройки репозитория на
  GitHub этим шагом не менялись. Следствие публичности: workflow запускается и от форков (поэтому действия закреплены по
  SHA, секретов в workflow нет).
- Дефекты ISS-0048…ISS-0052 только заведены, не исправлены (все LOW): пробелы тестов, формулировка о приватности,
  корневой README не проходит prettier, границы хука (последняя строка stdin без перевода строки; проверяется рабочая
  папка, а не отправляемый коммит), усиление GitHub Actions (нет `dependabot.yml`).
- Защита ветки `main` не включена: требование её не даёт, решение 0023 (D1) исходило из приватного репозитория, а
  репозиторий публичный (см. выше) — пересмотр решения 0023 за владельцем. На момент проверки (`step-01b-...-r2.json`)
  GitHub отвечал, что защиты ветки нет.
- Мерж не делался и не нужен: коммит идёт прямо в `main` в границах слов владельца ниже; метки `base/*` остаются
  локальными.

## Остаточные риски

- До шага 12 неизвестно, как раннер GitHub поведёт себя на Linux (версии действий и Node взяты по чтению GitHub и
  закреплены, но запуска не было).
- Хук не защищает от `--no-verify` и от неподключённого `core.hooksPath` — это локальная защита, а не граница (README
  говорит об этом).
- Решения 0044 и 0045 принял ORCH, не владелец.
