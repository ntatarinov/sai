## The incident of the first deploy command

The first `vercel deploy --prod` was started from the export root instead of the `app` folder inside it. The upload held 121
files (the `.vercelignore` of `app/` was not applied); the build ran no install and no `vercel-build` and produced an empty
output; the alias answered 404 on every path from about 22:13:48Z to about 22:16Z, two to three minutes at night. The smoke
check caught it at once (6 of 7 failed); ORCH repeated the same command inside the app folder (63 files, `vercel-build` ran), the
smoke check then passed 7 of 7 with version `dd54f43`. Cause: the recorded method said "in the export", read as the export root.
RELEASE-VALIDATOR confirmed the state after the repair (21 of 21 files served byte for byte, no leftover of the empty build)
but not the 404 window, the file counts or the logs: the platform side is not visible to it. A deploy that goes straight to the
alias has no safe window; the first thing to read after any deploy is the smoke result and the upload line (63 files, not 121).
`docs/runbooks/release.md` now says so (ORCH's edit), and the lesson is AP-176 in `docs/anti-patterns.md`.
