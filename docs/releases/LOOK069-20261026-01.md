# Release report LOOK069-20261026-01 - REQ-069: the tenant file format `sai-picker-tenant/3` (the look of the office)

Report date: 2026-10-27 (UTC, from the clock). Process: WF-02, requirement REQ-069 (part 1 of the new office of the picker site),
with the micro-amendment `MA069-20261026-01` made before the design gate. The push to `main` is made under `decisions/0048` and
`decisions/0057` after the PASS of RELEASE-VALIDATOR (`handoffs/LOOK069-20261026-01/step-18-release-validator.json`). Bookkeeping is by
DOC-UPDATER (`step-19-doc-updater.json`); ORCH's check is in its `context.orch_check` (PASS, 2026-10-27T04:44:43Z). The report is in
English by `decisions/0080`, item 2.

**In short.** A tenant file of the picker site can now be of the new version `sai-picker-tenant/3`: the old format /2 plus a section
`look` (the letter on the badge, the sign on the door, the headline of the first screen, colours for the light and the dark theme, four
staff members) and optional fields on questions, options and leads (a desk, quick numbers, an object of the office from a closed list of
15, a WhatsApp number, limits for leads). The command `npm run picker -- check` checks such a file and says in plain Russian what is wrong
and where; the picker server hands the look to the visitor's page. Files of the formats /1 and /2 behave exactly as before, byte for
byte, and get a fallback look. `npm run check` is green: 2044 tests, 2044 pass, 0 skipped, 0 todo (it was 1998 before the run).

**What the owner cannot see yet.** No page draws the look: the office on the site is REQ-071. The lead server that would use `whatsapp`,
`max_per_hour` and `max_stored` is not built (REQ-059). What is done is the format, the check and the delivery of the data to the page.

## What was released

- **The format /3** in `tools/src/picker/`: the new modules `shape.js` (shared shape checks) and `v3-check.js` (the rules of `look`,
  `desk`, `chips`, `object`, `whatsapp` and the lead limits); changed `validate.js`, `lang-check.js`, `limits.js`, `public-data.js`,
  `view.js`. No new error code, no new dependency; `engine.js`, `server.js`, `tenants.js` and `package.json` are not touched.
- **The page module** `tools/src/picker/public/tenant-look.js`: one pure module (15 exports) with the fallback look for /1 and /2 files
  (first letter of the name on the badge, neutral colours, four nameless staff members) and the desk tables. It is served by the
  existing rule for `/assets/`; no page reads `look` yet.
- **What the visitor's page receives** for a /3 tenant: `look`, `desk`, `chips`, `object`, `whatsapp` and the public part of the lead
  settings. `max_per_hour` and `max_stored` are not sent. The answers for /1 and /2 tenants equal the answers on the base tag byte for
  byte (six answers compared by hash). A tenant cannot set a picture, an address, a style or code: only values from closed lists,
  colours as `#rrggbb`, and texts.
- **The rules decided in `decisions/0085`:** 17 design choices accepted; a staff name is letters, combining marks, digits, space,
  hyphen, apostrophe and dot, 1-30 signs; the accent colour must have contrast of at least 3.0 : 1 with the sheet of its theme (the
  accents `#e0731f` and `#5b3fd6` of the approved sample do not pass and REQ-070 will replace them); a second public function
  `ownLookOfView` for REQ-077; the behaviour for a chips range with `min` not below `max` is written down as it is (item 10).
- **Tests:** 46 new, in `picker-look.test.js` (36), `picker-look-property.test.js` (3) and `picker-server.test.js` (7), with the
  helper `picker-look-helpers.js` (its own contrast function and its own literal expectations) and 89 sample files in
  `tools/test/fixtures/picker-look/`. Old guard tests were repaired by the replacement table of the design, none deleted or
  weakened (Q6): QS-12 now covers all `picker-*.js` files (at least 25, now 28). One old sample, `e-field-schema.json`, was changed
  from the schema /3 to /4, because /3 is now a known schema and the sample must still be an unknown one.
- **Mistakes log:** AP-127 (criteria that demand an error for an input that the description of the same requirement allows) and
  AP-128 (a sample named by a word that the output hides).

## Limits that stay attached to this release

- **Nothing new is visible on the site** until REQ-071 (the office drawn) and REQ-059 (the lead server) are built.
- **The texts of `look` are free text** and may contain markup-like words (`<script>`, `url(...)`). Safety holds only if every page that
  shows them uses text only. This is a rule for REQ-071 and REQ-066 and must be repeated by their security gates (`ISS-0089`, item 8);
  nothing can check it yet because no page reads `look`.
- **The property test LP-1** runs the check command 500 times and needs 40-56 seconds on a calm computer; on an overloaded one it
  failed with "code null" during the release check (step 18, I2). It is related to `ISS-0065` and `ISS-0083`. The check ran green
  at steps 16 and 18 and again before this commit.
- The criteria of REQ-061 (item 1) and REQ-054 (item 2) still say "/1 and /2" in words; the reading rule is in the description of
  REQ-069 (`ISS-0089`, item 18). REQ-060 (the tenant guide) must still get the look section.
- **Follow-ups, open and not blocking:** `ISS-0089` (18 Low items: code and README wording, design text, security rules for later
  requirements, test gaps, release check notes).
- Two process lessons are in the mistakes log: AP-127, AP-128.
