## Границы доказательства

- **ISS-0031 на настоящей модели не проверен.** Критерий 15 REQ-013 (задача второго круга плана получает принятый файл) закрыт тестами

  проверки нужен запуск, где проверка цели первый раз скажет «не прошла».
- **R-1 и R-2 требования REQ-011 не закрыты:** запуск шёл командами, а не через страницу (настоящая сессия через страницу,
  `decisions/0027`).
- **Потолок 3 USD и «не больше трёх запусков» назвал ORCH по поручению владельца** (`decisions/0048`), а не сам владелец.
  RELEASE-VALIDATOR счёл основание достаточным; владелец может отменить решение 0048. Использован один запуск из трёх.
- **Расход 0,92 USD — условная стоимость по отчёту самого Claude Code** (во всех 14 записях расход со значением «по отчёту»); запуск шёл
  по подписке владельца, деньги по API не тратились. Версию Claude Code (2.1.296) назвал ORCH, в журнале её нет.
- **Не пробовалось на настоящем исполнителе** (проверено только тестами на поддельном): команда `run-task` в настоящем виде (запуск шёл
  командой `start`; обе вызывают один `runTask` — по оценке RELEASE-VALIDATOR этого достаточно для критерия 14 REQ-010), запись вне
  папки проекта, пауза, продолжение, остановка, ответы владельца и чат, сбои сети и исполнителя, исчерпание потолка, параллельные
  задачи (план шёл цепочкой), критические задачи, повторные попытки.
- **Сырой поток `stream-json` не сохранён:** форма подтверждена косвенно (разбор прошёл все 14 запусков), побайтно не сверена.
- **Подпись BA-ANALYST не получена.** Решение ORCH (записано в `STATE.md`): для REQ-009, REQ-010 и REQ-013 интерфейса нет, все критерии —
