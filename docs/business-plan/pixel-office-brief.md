## Попытка сформулировать ценность

Агент-автор написал одну фразу: кто платит, какой результат получает после сессии и почему этого нельзя получить в Claude, Copilot и Pretty Prompt. Она приведена ниже дословно: это цитата, а не утверждение этого документа. Фраза и таблица конкурентов лежат в рабочей записи шага handoffs/BP-20260930-01/step-02a-plan-writer-value.json; таблица осталась только там, в этот документ она не входит.

> Программисты, запускающие в Claude Code несколько агентов, платят $10 в месяц (цена и покупатель — допущение) за отчёт после сессии по двум из шести элементов: действия агента и потерянное время (только длительность задач), без разбора запросов и ошибок; в Claude и Copilot это есть лишь частично или не найдено, Pretty Prompt смотрит только на текст запроса.

Проверяющий (рабочая запись handoffs/BP-20260930-01/step-02b-plan-validator-value.json) вынес отказ (FAIL) и назвал две причины. Каждая приведена дословно, в одной строке, с номером проверки (check) по критерию 5 требования REQ-006 (источник: docs/requirements.yaml); к каждой добавлено одно пояснение простыми словами.

**Причина 1, check: 2.** Простыми словами: «лишь частично» — это оценка охвата, а не причина, а показ длительности работы у Claude Code и Copilot CLI уже есть (источник: research/session-review-platforms.md). Дословно, как записал проверяющий:

> Фраза не говорит, почему результат нельзя получить в Claude и Copilot: «лишь частично или не найдено» — оценка охвата из таблицы, а не причина (чего именно там нет, не названо; «частично» признаёт, что часть есть, а «не найдено» — отсутствие сведений в поиске, не «нет»); при этом обещанное «потерянное время (только длительность задач)» — по легенде исследований ровно уровень «частично» (показ длительностей без выделения потерь), и такие показы у Claude и Copilot есть: Claude Code — agent view (research preview) показывает, что делает каждая сессия, и замораживает возраст завершённой на длительности прогона, /usage даёт Total duration; Copilot CLI — длительность вызова инструмента от 5 секунд (источник: research/session-review-platforms.md, строки 100, 204–215, 332); различие названо только для Pretty Prompt (работает с текстом запроса), для Claude и Copilot — нет.

**Причина 2, check: 3.** Простыми словами: в таблицах исследования четырнадцать других продуктов уже сами разбирают оба обещанных пункта, и как минимум пять из них — retro, AgentsView, Claude Code Trace, session-audit и analyze-sessions — работают с сессиями Claude Code (session-audit и analyze-sessions — навыки: анализ ведёт сама модель, готового отчёта «из коробки» нет), причём четыре из пяти без платных тарифов (источник: research/session-review-tools.md). Дословно, как записал проверяющий:

## Что нужно узнать сначала

Вопросы взяты из того, что нашли исследования, и из разбора автора в рабочей записи шага 2a (список замечаний result.issues). Ни на один из них не нужно строить продукт. Пункты разбора сессии (разделы 3 и 4 файла отзывов): постановка задачи, действия агента, вмешательства пользователя, ошибки, потерянное время, советы на следующий запуск (источник: docs/business-plan/reviews/2026-09-30-external-review.md). Вопросы 2 и 3 можно задать одним разговором с одними и теми же людьми.

**Вопрос 1. Чего не хватает человеку, у которого уже есть встроенные команды Claude Code и бесплатные средства для разбора сессий?**

Что известно: Claude Code сам показывает длительность сессии (`/usage`), краткое резюме (`/recap`) и сводный отчёт по многим сессиям (`/insights`) (источник: research/session-review-platforms.md); в Copilot CLI есть `/chronicle` — сводки и советы по истории сессий (источник: research/session-review-platforms.md). Бесплатные средства для разбора сессий Claude Code есть: приложение AgentsView и навыки session-audit и retro (источник: research/session-review-tools.md). По описанию REQ-001, Pixel Office записывает роль агента, короткое описание задачи, время начала и конца (источник: docs/requirements.yaml). Таблицы исследования полны только в границе его поиска, а не по рынку в целом: так сказано в его разделе «Где искали» (источник: research/session-review-tools.md).

Как узнать: возьмите рабочую сессию, где работало несколько агентов. В её конце запустите `/usage` и `/recap`, потом `/insights`, а агента попросите прогнать по записи этой сессии перечисленные средства (и `/chronicle` в Copilot CLI, если у вас есть к нему доступ). Выпишите, что каждый инструмент показал про действия агентов и про время.

Что будет ответом: запись по этой сессии — что показал каждый инструмент и что из этого мог бы показать Pixel Office по своим записям. Из неё видно, есть ли у платного отчёта хоть одно отличие.

**Вопрос 2. Нужно ли платной версии читать текст запросов и можно ли это делать?**

Что известно: по описанию REQ-001, Pixel Office не хранит текст запросов, текст задач агентов, ответы и результаты, в том числе потому, что в них бывают пароли, ключи и личные данные (источник: docs/requirements.yaml). Поэтому честно обещать можно только действия агента и длительность, а остальные пункты упираются в данные, которых нет: это вывод автора в замечании I3 рабочей записи шага 2a (источник: handoffs/BP-20260930-01/step-02a-plan-writer-value.json). По расчёту автора (замечание I1 той же записи), любой набор пунктов, по которому ни у одного продукта нет «да» сразу по всем, обязательно включает «постановку задачи» (источник: handoffs/BP-20260930-01/step-02a-plan-writer-value.json), а ей нужен текст запроса (источник: research/session-review-tools.md). Claude Code сам хранит полную расшифровку сессии у пользователя (источник: research/session-review-platforms.md), и бесплатные средства для разбора её читают (источник: research/session-review-tools.md).

Как узнать: решите сами и спросите пользователей. Вам — вопрос о правилах: может ли платная версия читать эту расшифровку на компьютере пользователя, не сохраняя копию? Пользователям — вопрос о доверии: пустили бы они такой разбор к тексту своих сессий и на каких условиях?

Что будет ответом: ваше письменное решение в decisions/ («читаем текст на компьютере пользователя» или «не читаем») и записанные ответы пользователей. От него зависит, какие пункты вообще можно обещать.

**Вопрос 3. Кто платит и за какой пункт?**

Что известно: покупатель в фразе (сами программисты) и цена — допущения. Для Dash0 и многих других платных продуктов исследование нашло в разделе «Свидетельства оплаты» только страницы цен: число платящих и выручка не найдены (источник: research/session-review-tools.md). Одним из двух ценовых ориентиров плана (вторым был Pretty Prompt Pro) был Dash0 AI Coding Insights (источник: docs/business-plan/README.md): $10 за отслеживаемого разработчика в месяц (источник: research/session-review-tools.md), но его покупатель, по словам продавца, — руководитель разработки, а не сам программист (источник: research/session-review-tools.md). Исследование нашло одну независимую работу о том, что идёт не так в сессиях агентов (20 574 сессии): она построена на поправках и возражениях разработчика агенту (источник: research/session-review-platforms.md). Поправки Pixel Office по описанию REQ-001 не различает: это вывод автора в замечании I3 рабочей записи шага 2a (источник: handoffs/BP-20260930-01/step-02a-plan-writer-value.json).

Как узнать: спросите нескольких человек, которые запускают несколько агентов Claude Code (где они собираются — допущение): что они делают после сессии сейчас, какой пункт хотели бы получать, платили ли за подобное и кто платит — они сами или работодатель. Цену и кнопку оплаты не показывайте. В записи ideas/05 агенты отметили ещё «щель» в подсказках для непрограммистов, но здесь она не проверялась (источник: ideas/05-drugie-idei.md); таких людей можно спросить тем же способом.

Что будет ответом: список ответов по людям — что делает сейчас, какой пункт нужен, платил ли и кто платит. Из него видно, кто покупатель и нужен ли ему хотя бы один из пунктов, которые Pixel Office может дать, — действия агента или длительность.
