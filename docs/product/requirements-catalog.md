## Что такое Sai как продукт

Sai — виртуальная команда. Пользователь пишет цель одной фразой («подготовь коммерческое предложение»).
Система сама составляет план, раздаёт задачи ролям команды (руководитель проекта, аналитик,
исследователь, юрист, маркетолог и другие), выполняет независимые задачи параллельно, проверяет каждый
результат отдельным проверяющим, спрашивает человека только о важном и заканчивает проект, только когда
цель достигнута. Всё, что происходит, видно простыми словами: на странице проекта, в чате и в Pixel
Office — офисе, где сотрудники команды двигаются только по настоящим событиям, без имитации.

## Что значит «самостоятельный»

Sai работает сам по себе, без других проектов:

- в файлах Sai нет путей этого компьютера, нет названий и ссылок на другие проекты, и он не
  использует их файлы или настройки;
- у Sai нет зависимостей во время работы — только Node 22 и, для настоящей работы агентов, Claude Code;
- на другом компьютере его открывают так: `git clone` репозитория Sai, затем `cd tools`, `npm ci`,
  `npm run check` (все проверки проходят), затем `npm run pixel-office` и `npm run team -- projects`.

Лучшее из других проектов взято только по смыслу и переписано своими словами: из платформы
бизнес-процессов (здесь — «[образец]») — надёжное ядро: журнал событий, права, аудит, повторы при сбоях,
согласования, шаблоны; из прежнего проекта владельца (Pixel Office) — живой офис, где всё движется только
по настоящей работе.

## Порядок работ

1. REQ-013 — движок (без него страницам нечего показывать).
2. REQ-014 — самостоятельность (можно в любой момент; ничего не ждёт, кроме ядра).
3. REQ-011 — страница для бизнеса.
4. После неё, в любом порядке: REQ-017 (решения), REQ-015 (результаты), REQ-021 (проблемы), REQ-022 (лента),
   REQ-016 (память), REQ-020 (шаблоны).
5. REQ-012 — Pixel Office как зеркало (после движка; до кода — ваша запись решения о втором источнике событий).
6. REQ-018 — пользователи (до кода — ваша запись решения о доступе), затем REQ-019 — аудит.
