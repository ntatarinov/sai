# Sai сегодня — что есть, чего нет и что мешает видению владельца

Проверено 2026-10-05 (UTC) в прогоне `PROD-20261006-01`, шаг 01a. Видение владельца — слова
2026-10-06 в пересказе ORCH: пользователь ставит большую цель, система сама строит план,
запускает агентов, собирает результаты, проверяет и показывает всё в Pixel Office как в
живом зеркале; никакой имитации. Всё ниже — только то, что проверено файлом, запуском или
счётом; где это суждение, так и написано.

## Коротко

- Работает и проверено: **наблюдатель** (Pixel Office на событиях хуков Claude Code) и
  **служебные команды** выбора идеи (WF-06). Проверка служебного кода: 483 теста из 483.
- Не существует: движка, который сам запускает агентов, хранилища проектов и задач, чата для
  бизнес-пользователя, согласований, памяти проекта, учётных записей. Роли и процессы — это
  тексты для Claude Code, а запускает их человек (ORCH — тоже сессия Claude Code).
- Готовность к видению владельца в целом: **около 10 %** (по областям — раздел 5).
- Главный совет по исполнителю агентов: основной — Claude Code как процесс (`claude -p`),
  запасной — Anthropic API по ключу (раздел 4).

## 2. Что работает только визуально или только как документация

Исполняемым агентом файл не становится: кто-то должен открыть сессию и запустить роль. ## 4. Исполнитель агентов для автономного движка

Что известно на этой машине (команда `claude --version` из расширения Claude Code для
VS Code): версия **2.1.284**. Команда `claude` в обычном пути командной строки не найдена —
запускать пришлось бинарный файл расширения; при настоящей работе путь надо будет вынести в
настройки. Вход — по подписке (`claude auth status`: способ `claude.ai`); переменная
`ANTHROPIC_API_KEY` в среде пуста. Отдельного пакета Agent SDK в `tools/` нет
(`tools/package.json`: только prettier, eslint и их друзья).

| Критерий | (а) Anthropic API по ключу | (б) Claude Code как процесс (`claude -p`, потоковый вывод) |
|---|---|---|
| Что нужно | Ключ владельца в переменной окружения (в проекте — только её имя), своя «петля» агента: вызов модели, инструменты, работа с файлами, повтор при сбое, контекст | Установленный Claude Code и вход (подписка или ключ), процесс на каждый запуск роли |
| Возможности из `claude --help` | — | `-p` (печать и выход), `--output-format stream-json` (поток событий), `--input-format stream-json`, `--include-hook-events`, `--json-schema` (структурный ответ), `--agents` (свои агенты), `--tools`, `--allowedTools`, `--permission-mode`, `--max-budget-usd` (только с `-p`), `--fallback-model`, `--resume`, `--session-id`, `--add-dir`, `--worktree`, `--bg` (фоновые сессии), `--no-session-persistence`, `--bare` |
| Запись файлов и команды | Всё пишется самим | Уже есть: инструменты Claude Code; права ограничиваются `--allowedTools` и `--permission-mode` |
| События для Pixel Office | Свои, из своей петли; точные | Поток `stream-json` с событиями; плюс хуки Claude Code (их можно включить, но в `claude -p` обработчик `async` теряет последние события — проба P2–P3 в `decisions/0005`, D2) |
| Состояние | Всё хранит движок | Состояние движка — в хранилище; состояние сессии Claude Code — файлы сессий; можно продолжать (`--resume`) |
| Деньги и лимиты | Платит владелец по расходу токенов; точных цен я здесь не проверял, их берут с официальной страницы цен перед запуском | Расход идёт на подписку владельца и делит лимит с его ручной работой (так прямо сказано в `STATE.md`: запуск настоящей сессии «расходует лимит»). `--max-budget-usd` ограничивает расход одного запуска, но его действие на подписке не проверено |
| Надёжность | Выше контроль повторов и таймаутов; выше объём собственного кода и тестов | Меньше кода; зависит от версии Claude Code (версию надо закрепить) и от того, что процесс вообще можно запустить без человека |
| Правила Sai | Зависимость (SDK) нарушает `decisions/0002`, прямой вызов по HTTP — нет | Не требует зависимостей: `child_process` — встроенный модуль Node |

Рекомендация (суждение):

- **Основной — (б) `claude -p` как процесс.** Причины: все инструменты работы с файлами,
  командами и ролями из `.claude/agents/` уже есть; не нужны ни новая «петля» агента, ни
  зависимость времени выполнения (`decisions/0002`); поток `stream-json` даёт события для
  Pixel Office; рычаги управления (`--max-budget-usd`, `--allowedTools`, `--json-schema`)
  есть в справке этой самой версии.
- **Запасной — (а) Anthropic API по ключу**, когда лимит подписки мешает (упёрлись в потолок)
  или владелец хочет оплату по расходу. Его строят позже за тем же интерфейсом «запустить
  роль с заданием и получить результат», чтобы смена исполнителя не меняла движок.
- Главный риск основного варианта: работа зависит от входа владельца и общего лимита
  подписки. Это первая проверка с владельцем (раздел 6).
