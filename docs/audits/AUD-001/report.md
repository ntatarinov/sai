# AUD-001 — сводка первого аудита Sai

Дата: 2026-10-27. Прогон: `AUD-001-20261027-01`. Собрал AUDIT-COMPILER (WF-05, шаг 4) по отчётам шага 3
в `docs/audits/AUD-001/all/` и `docs/audits/AUD-001/requirements/`. Все данные — в `report.json`.

## Итог для владельца

Общая оценка проекта — 40 из 100; её задаёт самая слабая часть, Pixel Office. Причина простая: на
этом компьютере стоит старая сборка Node 22 (22.21.1), в ней нет пяти выпусков исправлений
безопасности, и на ней работает сервер Pixel Office. Я проверил сам: уязвимое место сервера
досягаемо, но только для программы на этом же компьютере, и сервер при этом не упал, а отказал в
запросе — вред небольшой, но по правилам аудита это высшая отметка; лечится обновлением Node и
перезапуском сервера. Вторая по важности проблема: в Sai Team защита от утечки секретов портит
файлы с кодом в результатах (обычные записи вида `a.b.c` заменяются на «[скрыто]»), а исходный файл
удаляется, так что исправной копии не остаётся. Из 33 готовых требований три больше не выполняются
так, как записаны, а у одного не было записи независимой проверки — аудит проверил его сейчас, оно
выполняется. Секретов в файлах и в истории нет, все 2065 тестов проходят, данные разных клиентов
сайта подбора не смешиваются. Ни одна серьёзная находка при перепроверке не отменена; это первый
аудит, поэтому сравнивать не с чем, а настоящие запуски Claude Code не проверялись, потому что
тратят ваш лимит.

## Что не проверено и почему

- Настоящий запуск Sai Team в Claude Code (изоляция файлов агентов, запреты WebFetch, реальный
  результат после маскирования) и хук Pixel Office в живой сессии — тратит лимит владельца или пишет
  в рабочий журнал (решение 0090, п. 5; R2).
- Атака на работающий сервер Pixel Office по каждому исправлению Node — не проводилась, чтобы не
  трогать рабочий экземпляр; досягаемость исправления заголовков показана на отдельном сервере.
- Построчное соответствие кода Team решениям 0017–0026 и кода сайта подбора решениям 0065–0087,
  живые коды ответов серверов Team и сайта подбора, «всё или ничего» для набора результатов Team —
  ширина вместо глубины в сжатом первом аудите (решение 0090).
- Доказывает ли каждый тест свой критерий целиком (380 критериев), мутанты и прогоны под нагрузкой —
  разрешён был один полный прогон проверки.
- Описания ролей и процессов против последних прогонов — срок не наступил (сверка 2026-10-25,
  решение 0079).
- Бизнес-документы (`ideas/` кроме `ideas/README.md`, `docs/business-plan/`, `docs/research/`) — вне
  плана аудита.
- Критерии требований, которым нужен новый запуск агента-читателя (REQ-050 к. 8, REQ-051 к. 6,
  REQ-052 к. 9, REQ-053 к. 7, REQ-057 к. 11, REQ-061 к. 8, REQ-070 к. 5) или настоящая модель
  (REQ-010 к. 14, REQ-013 к. 13) — проверены только по записям прогонов.
- Q8 и Q11 для Team, R3 — не применимы: один владелец на компьютер, исходящих адресов нет, продукт с
  фотографиями снят (решение 0033).
