# ISS-0082 — Сайт подбора решения: три текста сервера (kk server_method; en server_wrong_type, server_slow), спорные для носителя, и единое «Please» в английских призывах

Серьёзность: LOW. Статус: open. Найдено: читатели переводов (BA-ANALYST, прогон `SERVER056-20261020-01`, шаг 7: I1–I3), подтверждено RELEASE-VALIDATOR (шаг 9: I2, сверка `texts.js`); заведено DOC-UPDATER (шаг 10), 2026-10-21. Пункты планки: Q3 (не выдавать согласие агентов за доказательство), решение `0070`, п. 10, и `0069`, п. 6. Требование: REQ-056 (`done`; условие (г) LANG061 выполнено только в части агента-читателя), AP-114.

## Что не так

Двенадцать новых ключей `texts.js` (`server_*` и `page_stub_notice`) прошли два круга читателей-агентов. Итог круга 2: kk «да» у 11 из 12, en «да» у 10 из 12. Три строки читатели не согласовали; по AP-114 после двух кругов они третьему читателю-агенту не отдаются:

1. **kk, `server_method` (ответ 405).** В файле: «Бұл бетке бұлай жүгінуге болмайды.» Читатель круга 1 предложил «бұлай», читатель круга 2 назвал «бетке жүгіну» калькой и предложил «Бұл бетке мұндай тәсілмен кіруге болмайды.» Смысл по-русски: «Так обращаться к этой странице нельзя.» Нужен знающий казахский человек.
2. **en, `server_wrong_type` (ответ 415).** В файле: «Request not accepted: unsupported data type.» Читатель круга 2: «unsupported» сдвигает смысл «неверный тип данных» на «не поддерживается»; предлагает «invalid data type».
3. **en, `server_slow` (ответ 408).** В файле: «The request took too long to arrive. Send it again.» Читатель круга 2: приказ без «Please» суховат. Если принять, «Please» нужно проверить единообразно во всех английских призывах: `server_too_large`, `server_bad_request`, `server_no_answers`, `server_extra_field`. В `server_internal` «Please» уже есть (проверено по `texts.js`); `server_answers_invalid` («Go through it again.») тоже призыв без «Please».

Тексты в файле — предложения читателей круга 1; предложения круга 2 в файл не внесены. Все три не меняют смысла для посетителя, это естественность и вежливость; ни один читатель не нашёл ошибки в числах, пропуска или добавления. Кроме того, читатели казахского не носители (`0069`, п. 6): «да» по 11 ключам kk — согласие агентов, а не доказательство. Пять строк kk из REQ-061 (105, 121, 139, 141, 160) ждут того же человека.

## Доказательство

`handoffs/SERVER056-20261020-01/step-07-ba-analyst.json` (I1–I4, круги 1 и 2), `step-09-release-validator.json` (I2; текст в `texts.js` равен названному в записях). Проверить: `grep -n "server_method\|server_wrong_type\|server_slow" tools/src/picker/public/texts.js`.

## Как исправить

Показать три строки знающему человеку до публикации (вопрос владельцу, `STATE.md`); принятое внести в `texts.js` (только ключи `TEXTS`, условие (в) LANG061), если меняется «Please» — единообразно во всех призывах; тесты текстов (`picker-texts.test.js`, тесты сервера, берущие текст из `texts.js`) не ослаблять. Ни третьего читателя-агента, ни споров между агентами не заводить (AP-114: спор двух читателей между кругами — уже случился здесь).

## Маршрут

Владелец / знающий человек (решение) → BACKEND-DEV (правка `texts.js`) → TEST-RUNNER → RELEASE-VALIDATOR → DOC-UPDATER; отдельный прогон не нужен, если правка идёт вместе с ближайшим требованием, которое добавляет ключи (REQ-057).
