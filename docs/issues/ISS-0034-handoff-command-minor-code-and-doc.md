# ISS-0034 — Мелкие недочёты кода и документа команды handoff

Серьёзность: LOW. Статус: open. Найдено: REVIEWER (`handoffs/REQ039-20261011-01/step-04-reviewer.json`, F1…F4), SECURITY-REVIEWER (`step-03-security-reviewer.json`, I2). Пункт планки: Q3 (лишнее). Требования: REQ-039.

## Что не так

1. Регулярка RUN-ID записана дважды: `tools/src/handoffs/args.js` и `tools/src/handoffs/git-history.js` (сознательно, чтобы `tagExists` не зависел от `args.js`); при смене формата RUN-ID менять надо в обоих местах (F1).
2. Функции `hasControl` повторены в `args.js` и `close.js`, `byBytes` — в `create.js` и `one-file.js`; в `close.js` строка `side(...)` собирается дважды (F2).
3. В `docs/workflows/handoffs.md`, раздел «Время», фраза «заранее handoff не создаётся» стоит в одной длинной строке рядом с «Если handoff создан заранее…» и читается как противоречие (F3).
4. Слово `--help` в любом месте вызова печатает справку и даёт код 0, даже когда это значение ключа (F4; значение, начинающееся с `--`, и так считается отсутствующим ключом, поведение предсказуемо).

## Как исправить

WF-03 с шага 1 (или одним проходом CODE-FIXER): импортировать RUN-ID из одного места; вынести `hasControl` и `byBytes` в общий файл рядом; собирать `side(...)` один раз; во второй фразе раздела «Время» дать вводное «Если всё же создан заранее» без изменения смысла; решить, читать ли `--help` только в первой позиции.

## Доказательство

`handoffs/REQ039-20261011-01/step-04-reviewer.json` (F1…F4, все Low, не блокируют), `step-03-security-reviewer.json` (I2).
