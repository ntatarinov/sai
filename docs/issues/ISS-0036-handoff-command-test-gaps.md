# ISS-0036 — Пробелы тестов команды handoff

Серьёзность: LOW. Статус: open. Найдено: TEST-DESIGN-VALIDATOR (`handoffs/REQ039-20261011-01/step-05b-test-design-validator.json`, F1…F6). Пункт планки: Q5. Требования: REQ-039.

## Что не так

1. `tools/test/handoffs-cmd-new.test.js`, HO-01: описание говорит «дословно», но значения вызова отличаются от критерия 1 (F1; структура и путь совпадают, критерий закрыт по существу).
2. `tools/test/handoffs-cmd-close.test.js`, HO-38: в названии нет H5, который есть в таблице случаев; H8 командой недостижим (`E_HO_CLOCK` срабатывает раньше), и в тесте это не записано (F2).
3. `tools/test/handoffs-cmd-close-refuse.test.js`, HO-35: 43 случая в одном тесте, первое падение прячет остальные; мутанты V13, V15, V16, V22, V25, V28, V29 ловит один этот тест (F3).
4. `tools/test/handoffs-cmd-docs.test.js`, HO-46 и HO-47: запускают `node --test` для `handoffs-runtime.test.js` и `traces-runtime.test.js` внутри теста — те же файлы `npm run test` уже выполняет (F4).
5. Допущения среды не записаны: жёсткие ссылки во временной папке, `sh`, `git` и `npm` в PATH (HO-13b, HO-53, HO-23*, HO-41a) (F5).
6. Часть критерия 8 (HO-92…HO-94: `npm ci` на копии, закрытый перечень, handoff-ы прогона созданы командой) автотеста не имеет — это команды RELEASE-VALIDATOR и TEST-RUNNER (F6, по проекту п. 10, О3).

## Как исправить

WF-03 с шага 1 или одним проходом TEST-FIXER: добавить H5 в название HO-38 и комментарий о H8; развернуть таблицу HO-35 циклом `test(...)` по случаям; убрать или оставить дубли HO-46/HO-47 по решению владельца; записать допущения среды в `tools/README.md` одной строкой; значения HO-01 сделать дословными.

`handoffs/REQ039-20261011-01/step-05b-test-design-validator.json` (F1…F6, все Low, не блокируют).
