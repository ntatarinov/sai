# ISS-0013 — Ключ замка по пути и снятие замка по одному pid в одном процессе

Серьёзность: LOW. Статус: open. Найдено: SECURITY-REVIEWER прогона `PROD-20261010-01` (`handoffs/PROD-20261010-01/step-34-security-reviewer.json`, F1 и A3c). Пункт планки: Q10, «один писатель» (REQ-009). Журнал при обоих случаях не портится: здоровый писатель получает E_CONFLICT.

## Что не так

1. `tools/src/team/lock.js:62`: ключ `keyOf` строится через `path.resolve`, а не по самой папке. Если в одном процессе один каталог данных записан двумя путями (через симлинк) и замок удалили извне, третий писатель снимает замок здорового. В продукте недостижимо: в процессе один home (`web/main.js`).
2. `releaseLock` (`lock.js` около 243–252) сверяет только pid. Здоровый писатель, потерявший замок, при `close()` снимает замок другого писателя этого же процесса, и открывается третий писатель. Проблема старше исправления `ISS-0010`.

## Как исправить

Ключ через `realpath` (или dev:ino); `releaseLock` сверяет билет и байты замка, как `noteOrphanedLock`; тесты при фиксированных часах. Проект — CODE-DESIGNER (WF-03), затрагивает ядро (REQ-009, решения 0017, 0026).
