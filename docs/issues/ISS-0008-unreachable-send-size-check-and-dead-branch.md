# ISS-0008 — Недостижимая проверка E_MSG_TOO_BIG у отправителя и мёртвая ветка «текст решения» в plan.js

Серьёзность: LOW. Статус: open. Найдено: TEST-DESIGNER прогона `PROD-20261006-02`
(`handoffs/PROD-20261006-02/step-34-test-designer.json`, I2 и I3); заведён DOC-UPDATER по поручению ORCH 2026-10-09.
Пункт планки: Q5 (мутант без теста), Q6.

## Что не так

1. Проверка размера `buf.length > MSG_BYTES_MAX` у отправителя (`tools/src/team/engine/channel.js`, около строки 499,
   ошибка `E_MSG_TOO_BIG`) недостижима при текущих пределах: текст ограничен 4000 знаками до и после маскирования, остальные
   поля короткие, тело не больше примерно 24 КиБ при пределе 64 КиБ. Мутант C11 (проверка убрана) эквивалентен — тест на
   него написать нельзя без смены констант. Со стороны движка правило «больше 64 КиБ — отказ до записи» проверено (EN-62).
2. Ветка «; решение пользователя: <текст>» в `closedLine` (`tools/src/team/engine/plan.js`) мёртвая: у закрытой задачи
   `last_decision` — это отказ, а отказ не несёт текста. Мутант T04 эквивалентен. Проект (п. 7.2) говорит «с текстом
   решения пользователя», фактически текста там не бывает.

## Доказательство

step-34-test-designer.json, `result.issues` I2 и I3 (мутанты C11 и T04 — эквивалентные, не убиваются).

## Как исправить

Решает CODE-DESIGNER: оставить проверку размера как защиту на случай роста пределов (и записать это в проекте) либо
убрать; ветку в `closedLine` убрать или объяснить в проекте, когда текст возможен. Любое решение — с обновлением
проекта REQ-013, чтобы код и проект не расходились (Q12).

## Маршрут

По `docs/workflows/WF-03-defect.md`; срочности нет. ORCH подтверждает маршрут при запуске.
