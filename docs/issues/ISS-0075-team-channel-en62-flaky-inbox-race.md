## Поправки к описанию по диагнозу 2026-10-21 (DOC-UPDATER, прогон `ISS-0075-20261021-01`, шаг 10)

Прежние записи выше не переписаны; здесь — что оказалось иначе (диагноз `handoffs/ISS-0075-20261021-01/step-01-issue-fixer.json`, I1, I9; подтверждено `step-05-release-validator.json`, I3).

- **Три теста — три разные причины,** общего у них было только слово «нестабильный».
- **HC-6a — это не «медленная машина GitHub» и не гонка при нагрузке.** Причина — git версии 2.55 и новее (на `ubuntu-24.04` в GitHub Actions стоит такой): после `git commit` он запускает фоновую уборку (`git maintenance run --auto --detach`), которая берёт файл `.git/objects/maintenance.lock` в личном временном репозитории теста; хеш дерева (`treeHash` хеширует всё дерево, `.git` включительно) «до» видит замок, «после» — нет, отсюда «the command changed the tree». Дерево — личное, параллельный тест в него не пишет, команда `handoffs-check` тоже; пишет сам git. На системном git 2.50.1 тест не краснеет вообще. Измерено: замок виден после возврата `git commit` в 74 из 100 коммитов у git 2.55.0 и в 0 из 100 у 2.50.1.
- **EX-42 — не новый тест, а уже заведённый ISS-0065** (шаг стенных часов назад и строгая проверка времени для событий ENGINE); вписан туда, здесь не исправлялся.
