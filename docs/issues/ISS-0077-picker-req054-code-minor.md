## Что не так

Ничего из ниже перечисленного не нарушает критерии REQ-054; это места, о которые споткнётся следующая работа.

1. **`isObject` записана дважды** (`tools/src/picker/conditions.js:12-14` и `tools/src/picker/validate.js:42-44`): проверка «объект, не null и не список» одинаковая, в двух файлах (род AP-014). Поведение одинаковое. Экспортировать из `validate.js` нельзя (цикл импорта) — нужна отдельная функция в `text-rules.js` или в маленьком общем модуле (REVIEWER, L1).
2. **`cli.js` исполняет команду при загрузке и при этом экспортирует `COMMANDS`** (`tools/src/picker/cli.js:42-59`): импорт файла в тест или в сервер REQ-056 вызовет проверку с чужими аргументами `process.argv` и поставит `process.exitCode`. Так же устроены соседние cli-файлы Sai, но те ничего не экспортируют. Исправление — либо не экспортировать `COMMANDS`, либо отделить точку входа проверкой «файл запущен напрямую», как в `tools/src/team/cli.js` (REVIEWER, L2). Пока REQ-056 не добавил новые команды — не срочно; сервер `cli.js` как модуль подключать не должен.
3. **Ошибка программы завершает процесс кодом 1 — как «найдены ошибки»** (TEST-DESIGNER, I1): необработанное исключение Node даёт код 1, он совпадает с кодом 1 «в файле арендатора найдены ошибки». Различить можно по пустому stdout и стеку в stderr (тест PK-L2 это проверяет). Если нужно различать по коду выхода — решение CODE-DESIGNER (отдельный код или перехват верхнего уровня).
4. **`show()` скрывает имя файла целиком, если в нём запретное слово** (`tools/src/picker/places.js`, RELEASE-VALIDATOR L1): для файла `h-null.json` ответ «(скрыто): весь файл: E_FIELD: …» — пользователь не видит, какой файл разобран. Скрывать нужно только запретное слово, а не всё имя, или писать имя файла без маскировки (оно известно пользователю, он его набрал).
5. **`baseDir` в `load.js` написан и проверен, но CLI его не использует** (SECURITY-REVIEWER, I1; ревью, I1): режим «файл только внутри папки арендаторов» нужен серверу REQ-056. Когда сервер начнёт читать файлы арендаторов, он обязан вызывать `readTenantFile(путь, { baseDir })` и вести повторную проверку на тех же байтах, что получены при чтении (`readTenantFile` возвращает байты, а не путь). Это требование к проекту REQ-056, а не дефект REQ-054.

## Обновление 2026-10-19 (DOC-UPDATER, прогон `PICKER055-20261019-01`, шаг 10): заметки для проектов REQ-056 и REQ-058 по движку (REQ-055)

Дефект остаётся `open`. Движок `tools/src/picker/engine.js` готов (REQ-055 `done`); ниже — то, что не дефект движка, а обязано попасть в проекты сервера (REQ-056) и страницы результата (REQ-058). Источники: `handoffs/PICKER055-20261019-01/step-03-security-reviewer.json` (I1–I3), `step-09-release-validator.json` (Q8, I1), решение `decisions/0067`.

6. **`error.question` — строка посетителя произвольной длины.** При ошибке ответов движок кладёт в `error.question` id вопроса из файла арендатора или, для неизвестного вопроса, наименьший чужой ключ из ответов — то есть то, что прислал посетитель (любой длины, с управляющими знаками и U+202E). Сервер и страница выводят её только как текст и с ограничением длины (в проверке файла арендатора для этого есть `show()`); чужой ключ посетителю целиком не отдают. Сервер не должен выводить чужой ключ из ответа в том виде, как он пришёл. Связано с ISS-0078.
7. **`ranking` содержит баллы нерекомендованных решений** (`decisions/0067`, п. 4). Что из этого видит посетитель, решает сервер: он не отдаёт баллы и названия нерекомендованных решений, если проект REQ-058 их не показывает. Настроек `top`, `min_score`, `clear_lead_gap` и правил нерекомендованных решений в результате нет, и добавлять их в ответ сервера не нужно.
8. **Причина ошибки при нескольких испорченных элементах списка `multiple` зависит от порядка элементов.** Например, `["__proto__", 1]` даёт `unknown_option`, а `[1, "__proto__"]` — `wrong_kind`. Для одного и того же входа результат стабилен, на успех порядок валидного списка не влияет. Страница не должна строить на конкретной причине ничего, кроме понятного сообщения посетителю; тесты сервера не должны закреплять причину для списка с несколькими испорченными элементами.
