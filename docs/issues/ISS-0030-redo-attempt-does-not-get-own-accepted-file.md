# ISS-0030 — При повторной попытке задачи исполнитель не получает свой прежний принятый файл

Серьёзность: LOW. Статус: open. Найдено: ISSUE-FIXER прогона `ISS-0023-20261011-01` (`handoffs/ISS-0023-20261011-01/step-01-issue-fixer.json`, I4, «место 3»). Пункт планки: Q1. Требования: REQ-013.

## Что не так

При переделке задачи (`engine.js` `workRun`: `defaultContext` плюс замечания проверяющего) `depsOf` берёт только `depends_on`; переделывающая роль не получает свой прежний файл, `work/` пуст (исходник удалён). Воспроизведено: «own previous files given to a redo of t-0001: []». Каждая попытка пишет файл заново, без опоры на прошлую; в замечаниях проверяющего может стоять «создайте файл с этим содержимым». В первом настоящем запуске расход рос на шести попытках (0,67 из 1). Исправление ISS-0023 этого места не касалось (не расширять прогон).

## Как исправить

WF-03 с шага 1: передавать переделке последний принятый файл этой же задачи (согласовать с ISS-0024: «последний»). Родственен ISS-0031.

## Доказательство

`handoffs/ISS-0023-20261011-01/step-01-issue-fixer.json` (I4, repro2).
