# ISS-0093 — Team masks result files with the free-text rules M7 and M10, which silently corrupt code, and the unmasked source is deleted
Серьёзность: HIGH. Статус: closed, 2026-10-30. Найдено: AUD-001, SECURITY-AUDITOR (находка SEC-01, перепроверена AUDIT-COMPILER), 2026-10-27; заведено AUDIT-TRIAGE, 2026-10-28. Пункт планки: Q7 (механизм маскирования), Q10 (обычный ввод — код — ломает результат без понятного сообщения). Требования: REQ-009 (критерий 12). Связан с открытым ISS-0058 (то же правило M7, см. ниже).

## Что не так

Sai Team passes every result file through `maskSecrets` (`tools/src/pixel-office/mask.js`) before it is stored (`tools/src/team/store.js:395`) and before a dependent task gets it (`tools/src/team/runner.js:132`). `maskSecrets` includes free-text rules: M7 (any `x.y.z` run of letters, digits, `_`, `-` and dots, `mask.js:104-108`) and M10 (long strings, `mask.js:259`). They fit a short line of a request, but not a result file. Ordinary code is changed silently: `a.b.c` and `obj.prop.method()` become `[скрыто]`, a version number such as `"0.1.0"` becomes `"[скрыто]"`.

The harm is larger than a hidden word: only the masked text is published, the reviewer and the dependent tasks get the broken text, and the unmasked source in `work/` is deleted after the acceptance (`tools/src/team/runner.js:655-680`; `tools/README.md:391`: «an unmasked copy does not stay»). The role «Разработчик» has Write/Edit and returns code as result files, so no sound copy is left. No message tells the user that the content was changed.

## Доказательство

The script runs outside the project: `maskSecrets` from `tools/src/pixel-office/mask.js` applied to copies of project files, as `store.js:395` does to a result file (`docs/audits/AUD-001/report.json`, SEC-01, field `recheck`). Count of the marks `[скрыто]`: `tools/src/team/files.js` — 3 (line 12 `const NOFOLLOW = fs.constants.O_NOFOLLOW ?? 0;` becomes `const NOFOLLOW = [скрыто] ?? 0;`), `tools/src/web/server.js` — 7, `tools/src/picker/public/app.js` — 52, `tools/package.json` — 5, `tools/src/pixel-office/public/app.js` — 196. None of these files holds a secret. A sample line `const v = a.b.c; x = obj.prop.method();` becomes `const v = [скрыто]; x = [скрыто]();`. It matches the owner's probe of 2026-10-27 (a code result with 41 marks). Repeated by AUDIT-TRIAGE on 2026-10-28: `maskSecrets('const v = a.b.c; x = obj.prop.method();')` gives `const v = [скрыто]; x = [скрыто]();` and `maskSecrets('"version": "0.1.0"')` gives `"version": "[скрыто]"`.

Relation to the open ISS-0058 (MEDIUM): the same rules M7 and M10 of `mask.js`. ISS-0058 describes hosts in source addresses, file names in task descriptions and long role names, and calls the error «safe» (readability only). It does not name result files, the code corruption or the deletion of the unmasked source, and its fix (a smarter M7) does not require that a code file keeps every byte. Therefore the cause of this finding is not counted as covered by it; the two fixes touch the same file and must be diagnosed together (see «Маршрут»).

## Как исправить

One item (no Critical finding stands behind this cause).

1. Do not run the free-text rules M7 and M10 over result files as they are. Mask result files only by the precise rules (PEM blocks, `Authorization`, keys with known prefixes, `name=value` pairs), or keep the original and mark the places found instead of replacing them; do not delete the unmasked source of an accepted file while the published copy differs from it silently. Files: `tools/src/pixel-office/mask.js` (rules M7, M10 and the entry used for results), `tools/src/team/store.js` (`#publish`, line 395), `tools/src/team/runner.js` (line 132, and 655-680 for the source), `tools/README.md` (the paragraph on result files, line 391). The choice between the variants is recorded in `decisions/` (Q12; it touches the records on masking, `decisions/0013` and `0017`).
2. Regression test: a JavaScript file with `a.b.c` expressions and version numbers keeps every byte after the result is stored and handed to a dependent task, and a real key inside the same file is still hidden. The test also checks that, when the content is changed on purpose, the user gets a message and the source is not lost.
3. Look for all places of the same kind (AP-014): every caller of `maskSecrets` or of the free-text rules over text that is not a short request line (result files, the copy for dependent tasks, the review context, the web view).
