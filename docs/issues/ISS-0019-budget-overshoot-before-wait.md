# ISS-0019 — Расход может превысить потолок проекта до ожидания решения

Серьёзность: LOW (требует проверки). Статус: open. Найдено: SECURITY-REVIEWER прогона `PROD-20261011-01` (`handoffs/PROD-20261011-01/step-16-security-reviewer.json`, вопрос 3). Пункт планки: Q10 (потолок расходов — жёсткая граница).

## Что не так

На scripted-исполнителе при потолке проекта 0.1 и стоимости одного запуска 0.05 итоговый расход дошёл до 0.15, прежде чем проект встал на ожидание по потолку. Не проверено, достижимо ли это на настоящем исполнителе: там каждый запуск получает собственный `--max-budget-usd` не больше остатка потолка (`tools/README.md`, «Потолок на запуск и учёт расхода»). Возможно, это учёт худшего случая («assumed») у попытки без отчёта о расходе, возможно, ошибка округления.

## Как исправить

ISSUE-FIXER (WF-03): воспроизвести на scripted, выяснить причину (учёт после запуска или повтор попытки), решить — принятое поведение с записью в README или правка движка REQ-013 с тестом.

## Воспроизведение на запущенной системе (дополнено 2026-10-11T10:30:40Z)

RELEASE-VALIDATOR, `handoffs/PROD-20261011-01/step-41-release-validator.json` (находка L2): scripted-исполнитель, потолок проекта 0,2 — итоговый расход 0,26 (сценарий s4) и 0,25 (сценарий s5) до ожидания по потолку. Дефект воспроизводится не только при 0,1 / 0,05. Остаётся **открытым**: причина (учёт после запуска, повтор попытки или округление) не выяснена; на настоящем исполнителе не проверено. Вне области REQ-035 (движок REQ-013).
