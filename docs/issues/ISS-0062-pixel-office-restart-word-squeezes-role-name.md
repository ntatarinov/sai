# ISS-0062 — Pixel Office: длинное слово «сервер перезапускался, события не записывались» сжимает название роли в панели «Задачи» до 20 px

Серьёзность: MEDIUM. Статус: closed, 2026-10-13. Найдено: UAT-RUNNER (прогон `REQ042-20261013-01`, шаг 8b, находка «О1» в `docs/uat/REQ-042-RUN.md`), измерено заново RELEASE-VALIDATOR (шаг 9, F1 и I1), заведено DOC-UPDATER (шаг 10), 2026-10-13. Пункт планки: Q3 (вид не проверен ни одним запуском до приёмки). Требования: REQ-042 (вид слова; критерии не нарушены), REQ-036 (критерий 7 — название роли целиком на 1470×784; этот дефект его ударит).

## Что не так

В панели «Задачи» слово состояния «сервер перезапускался, события не записывались» (новое слово REQ-042, критерий 6) стоит в плашке шириной около 300 px рядом с названием роли в одной строке. Названию остаётся около 20 px, и оно ломается по буквам: «Plan» выводится как «Pl / an», «Основная сессия — обрабатывает запрос» — столбиком. Строка основной сессии вырастает с обычных около 100 px (UAT: 39 px у обычного слова состояния) до 387 px в основном окне 1470×784 и до 716 px в окне 375×812.

Все буквы и слово состояния на месте, горизонтальной прокрутки нет — поэтому критерии REQ-042 и принятые критерии REQ-007 не нарушены (в них нет требования к высоте или ширине строки; «название роли целиком» — критерий REQ-036). Но это регресс по эффекту (слово новое и длинное; по коду — см. «Закрыто»: правила раскладки старше REQ-042), и он виден в основном окне владельца, а слово «сервер перезапускался…» — самое частое состояние сразу после перезапуска сервера.

## Доказательство

Воспроизведение (так проверяли UAT-RUNNER и RELEASE-VALIDATOR, на отдельном стенде вне проекта):

1. Пустой каталог состояния, свой порт, своя подпись записи; запустить `cd tools && npm run pixel-office` с этим каталогом.
2. Через настоящий `hook.sh` отправить начало задачи субагента `Plan` и запрос основной сессии (задача и строка «Основная сессия — обрабатывает запрос» в состоянии «в работе»).
3. Остановить сервер и запустить снова (запись запуска сервера после начала задач), события окончания сессии не присылать: обе строки получают слово «сервер перезапускался, события не записывались» (сценарий 16 из `docs/uat/REQ-042.md`, стенд СТ-3).
4. Открыть страницу в окнах 1470×784 и 375×812, панель «Задачи», измерить `getBoundingClientRect` у названия роли и у строки.

Измерено RELEASE-VALIDATOR (`handoffs/REQ042-20261013-01/step-09-release-validator.json`, F1): окно 1470×784 — плашка 300 px, название роли 20 px, «Plan» → «Pl / an», строка основной сессии 387 px; окно 375×812 — строка 716 px, название по одной букве; scrollWidth окна 375 равен 375. Первое наблюдение UAT-RUNNER (`docs/uat/REQ-042-RUN.md`, О1) — 332 px и 644 px, название 11–20 px; числа различаются не из-за двух прогонов (поправка при закрытии, диагноз ISSUE-FIXER, I1): 332 и 644 — высота шапки `.item-head`, 387 и 716 — высота всей строки `.item`; в одном прогоне получаются оба набора. Снимки и `item-head-geometry.json` лежат вне проекта в папках стендов; в документе прогона перечислены имена файлов (`evidence/s16/01-after-restart.png`, `evidence/s37/tasks-375-5.png`, `evidence/s37/item-head-geometry.json`).

Причина (сначала предположена по чтению `tools/src/pixel-office/public/style.css`, затем подтверждена ISSUE-FIXER запуском и изменением CSS на копии, см. «Закрыто»): `.item-head` — строка `display: flex`, плашка `.item-state` с `flex: none` не сжимается, весь остаток отдан названию `.item-role`, у `.item` стоит `overflow-wrap: anywhere`, поэтому название переносится по буквам. Окончательно причину устанавливает ISSUE-FIXER воспроизведением (WF-03, шаг 1).

Почему тесты не поймали: размеров и высоты строк в тестах страницы нет (страница проверяется по тексту и разметке, не по раскладке в браузере); в handoff-ах прогона нет шага 7 (DESIGN-QA-VALIDATOR), раскладку впервые измерили UAT-RUNNER и RELEASE-VALIDATOR.

## Как исправить

WF-03 с шага 1. Направление, не решение: плашку состояния — отдельной строкой под названием роли (или с переносом слова внутри плашки), чтобы название роли оставалось в одной строке. Проверка — браузер, окна 1470×784 и 375×812: название роли видно целиком, строка основной сессии не выше соседних строк на разумную величину; слово состояния читается целиком; контраст слова не ниже уровня остальных (см. ISS-0063). Исправить **до REQ-036**: его критерий 7 требует название роли целиком на 1470×784 (и 390×844). Тест, который падает до исправления: либо проверка раскладки в настоящем браузере (если появится такой инструмент), либо проверка правил CSS (плашка не `flex: none` в одной строке с названием) с явной оговоркой, что это проверка правила, а не вида (свойство «название видно целиком» поиском строки в CSS не доказывается).
