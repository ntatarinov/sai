# ISS-0122 — The local read APIs need no token: `GET /api/events` of Pixel Office and `GET /api/projects` of the team page answer 200 with the stored text to any process of the computer, and the text of the owner's requests is stored by default

Серьёзность: MEDIUM (предложена ORCH по словам проверки; диагноз может её изменить). Статус: open. Найдено: внешняя проверка безопасности (передано ORCH 2026-11-18 другой сессией владельца); заведено DOC-UPDATER (шаг 01), прогон `SECREG-20261118-01`, 2026-11-18T15:30:07Z. Пункт планки: Q7 (хранимый текст, в котором может остаться не распознанный секрет, читает любой процесс этого компьютера, в том числе программа другого пользователя ОС). Требования: REQ-001 и REQ-008 (Pixel Office; статус `blocked` по `decisions/0099`), REQ-011 (сделано; страница команды, `tools/src/web/`). Решения: `decisions/0025`, W2 (принятый остаточный риск: любой процесс компьютера может открыть `GET /`, прочесть ключ страницы и читать все проекты), `decisions/0011` (Pixel Office хранит текст запросов владельца; выключатель — переменная окружения). Вопрос владельцу: значение `SAI_PIXEL_OFFICE_STORE_TEXT` по умолчанию.

## Что не так

The words of the review (an external security review, relayed to ORCH on 2026-11-18; the reviewer used only artificial values and localhost, nothing real leaked): `GET /api/events` of `tools/src/pixel-office/server.js` and `GET /api/projects` of `tools/src/web/api.js` answer 200 with the stored text to any local process; the texts of requests are stored by default (`SAI_PIXEL_OFFICE_STORE_TEXT`); the servers listen on `127.0.0.1`, and a foreign `Host` gets 403. The risk is lower on a computer that one person uses and matters on a shared one.

What this step saw, reading the files as text (`tools/src/pixel-office/server.js`, `tools/src/pixel-office/protocol.js`, `tools/src/web/api.js` and `tools/src/web/server.js` are unchanged against the tag `base/SECREG-20261118-01`; the work running now, the parallel run ISS-0092-20261117-01 among it, has changed other files of these folders — `pixel-office/main.js`, `hook.sh`, `note.js`, `public/office-report.js` and `web/main.js` — not these four). Nothing was run.

**Pixel Office.**
- The server listens on `HOST` = `127.0.0.1` (`tools/src/pixel-office/config.js`, line 6; `server.js`, line 504). `route` (line 430) checks `Host` first: exactly `127.0.0.1:<port>` or `localhost:<port>`, otherwise 403 (lines 431–440). **Matches.**
- `GET /api/events` goes to `handleRead` (lines 447–448 and 221–259): no key, token or `Origin` check; the answer is 200 with the events of the journal from `after` (0 when it is missing, lines 225–226). **Matches.** The writes are signed: `signedObject` answers 401 without a valid HMAC signature (lines 281–292).
- Stored text: `storeTextEnabled` (`tools/src/pixel-office/protocol.js`, lines 80–84) is on when the variable is not set, empty or `1`. **Matches** «stored by default». The stored `prompt_text` is masked (`protocol.js`, line 227), with the holes of ISS-0121. The design of REQ-008 (section 2.4) chose this: on by default, a typo turns storage off.
- The Pixel Office design already names a part of this as accepted: `docs/design/REQ-001-pixel-office.md`, section 7.3, line 3085 (the description of an event «лежит в журнале и видно любой локальной учётной записи»: lies in the journal and is visible to any local account).

**The team page (Team Web).**
- `getProjects` (`tools/src/web/api.js`, lines 106–114) reads `listProjects` of the core and answers 200 with the list. The route is in `tools/src/web/server.js` (`routeOf`, line 161; `get` of `/api/projects`, line 167). `handle` (line 428) checks `Host` (lines 429–438, 403) and then runs every GET at once (lines 462–465); the checks of `Origin`, `Content-Type` and the page key (`writeAllowed`, lines 327–347) run only for POST (line 473). **Matches.**
- The page key does not stop a local reader today: the server puts the key of the start into `index.html` (`<meta name="sai-page">`, lines 240–251), and `GET /` gives it to anyone who passes the `Host` check. `decisions/0025`, W2, line 48 records this as an accepted residual risk: «любой процесс на этом компьютере (в том числе программа другого пользователя ОС) может открыть `GET /`, прочесть ключ страницы и читать и менять все проекты Sai Team через API» (any process of this computer, a program of another OS user included, can open `GET /`, read the page key and read and change all projects through the API); the same in the design `docs/design/REQ-011-team-web.md`, line 879. So the option «the existing page key» of the review's acceptance closes the read only if a local process cannot take the key from `GET /`.
- The header comment of `tools/src/web/server.js` (lines 2–3) says «the checks of Host, Origin and the key of the page before any read of data», while the code and the design (`docs/design/REQ-011-team-web.md`, section 4.1, item 3: «Только для POST», only for POST) check `Origin` and the key only for writes. The comment says more than the code does.

Good measures that the review named and that bear on this defect: only `127.0.0.1`; the `Host` check against DNS rebinding in both servers; HMAC on the writes of Pixel Office; the `Origin` and page-key checks on the writes of the team page; a CSP on the pages (`tools/src/pixel-office/server.js`, lines 43–53 and 213; `tools/src/web/server.js`, lines 37 and 299).

Why MEDIUM (as proposed): the journal holds the owner's request texts and the projects hold goals, chats and results; a process of another OS user, or any program the owner runs, reads them with one local request. The diagnosis may change the severity.

The review's advice for now, until the fix: run on a separate virtual machine with depersonalised data; set `SAI_PIXEL_OFFICE_STORE_TEXT=0` (the hook and the server both read it; `0` and any other value except empty and `1` turn storage off, `protocol.js` lines 80–84; `decisions/0011`, condition (е)); set `SAI_TEAM_WEB=0`. By the code `SAI_TEAM_WEB=0` removes WebSearch and WebFetch from the Researcher (`tools/src/team/config.js`, line 85; ISS-0119); it does not stop the team page, which serves only while `npm run team-web` runs.

## Как исправить

The acceptance that the review proposes (to be measured by the diagnosis; not a ready fix, AP-161): the read endpoints of Pixel Office and of the team page need a random token made at every start (kept in a file that only the owner can read, mode 0600) or the existing page key; without it the answer is 401 or 403; the page still works in the browser.

Before the design: the fix changes the accepted residual risk of `decisions/0025` W2 and the trust border that Pixel Office shares with it, so ORCH records a decision (Q12) and asks the owner; and the owner answers the question about the default of `SAI_PIXEL_OFFICE_STORE_TEXT` (a change of the default changes the design of REQ-008, section 2.4, and `decisions/0011`). How the browser page gets the token without giving it to any process that reads `GET /` (the way of W2 gives the key away) is the design's question. All read paths of both servers get the check, not only the two the review named (AP-014): `GET /api/projects/<id>`, the chat, the tasks and the roles of the team page. A weaker check or a skipped test is not a fix (Q6).
