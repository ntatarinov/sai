# ISS-0079 — Движок подбора (REQ-055): порядок условий в `because` и порядок `answers` на малом файле различает только свойство на 1000 наборов; у нескольких тестов одинаковые префиксы имён (PE-2e, PE-3a, PE-7d)

Серьёзность: LOW. Статус: open. Найдено: TEST-DESIGN-VALIDATOR (прогон `PICKER055-20261019-01`, шаг 5d, F5, F6); RELEASE-VALIDATOR (шаг 9, R3) принял как известные записи ORCH; заведено DOC-UPDATER (шаг 10), 2026-10-19. Пункты планки: Q5 (тест на каждый критерий), Q6 (проверка не должна держаться на одном случае). Требования: REQ-055 (все восемь критериев выполнены и подтверждены RELEASE-VALIDATOR; дефект не блокирует).

## Что не так

1. **F5. Порядок условий в `because` и порядок ключей `answers` у `resolveAnswers` на малом файле тестов не различается.** Мутант M10 (условия в `because` отсортированы по id вопроса) краснит только PE-5 (свойство на 1000 наборах двух вымышленных арендаторов): у правил малого файла `pico` условия идут по алфавиту (a, b, c), поэтому явные случаи PE-3a и PE-7d порядок «как в файле» и порядок «по алфавиту» не различают. Мутант M7 (`answers` в `resolveAnswers` по алфавиту) краснит только PE-6a по той же причине: ключи a, b, c, d, g по алфавиту совпадают с порядком вопросов файла. Защита есть, но держится на одном свойстве; если свойство когда-нибудь ослабят, явные тесты порядок не удержат.
2. **F6. Одинаковые префиксы имён тестов.** В `tools/test/picker-engine.test.js` по два-три теста носят общий префикс: PE-2e (2), PE-3a (3), PE-7d (3). При запуске по шаблону имени и в списке красных их различает только хвост имени, а отчёты ссылаются на идентификатор без хвоста. На корректность это не влияет.

## Доказательство

`handoffs/PICKER055-20261019-01/step-05d-test-design-validator.json` (F5, F6; мутанты M7 и M10 — в его `summary`), `step-09-release-validator.json` (R3). Проверить: `grep -nE "PE-(2e|3a|7d)" tools/test/picker-engine.test.js`; повторить мутант M10 на свежем клоне (в `engine.js` отсортировать условия в `because` по id вопроса) и убедиться, что красен один PE-5.

## Как исправить

Только тесты, без изменения кода движка. F5: в копии малого файла с обратным порядком правил (`picoReversedRules`) добавить правило, чьи условия идут не по алфавиту (например, c, затем a), и сверить `because` литералом; в PE-7d для `resolveAnswers` взять копию малого файла с вопросами в неалфавитном порядке. F6: дать повторяющимся тестам суффиксы (PE-2e-1, PE-2e-2 и так далее) и обновить ссылки на них в `docs/design/REQ-055-picker-engine.md`. Проверку не ослаблять (Q6).

## Маршрут

TEST-DESIGNER → TEST-DESIGN-VALIDATOR → TEST-RUNNER → RELEASE-VALIDATOR → DOC-UPDATER → RELEASE-FINALIZER; вместе с ближайшей работой над `tools/test/picker-engine*.test.js` (REQ-056/058) или по WF-03 — решает ORCH.
