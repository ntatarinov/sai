# ISS-0065 — Тест EN-57 (1, 2) движка команды один раз упал с E_TIME: служба времени macOS сдвинула часы назад, а проверка времени для событий ENGINE строгая

Серьёзность: MEDIUM (была LOW; повышена 2026-10-21, см. «Обновление 2026-10-21»). Статус: open. Найдено: TEST-DESIGNER (прогон `REQ042-20261013-01`, шаг 5, `result.issues` I2), причина по журналу службы времени — TEST-DESIGN-VALIDATOR (шаг 5b, I1); RELEASE-VALIDATOR (шаг 9, I4) в своём прогоне падение не повторил; заведено DOC-UPDATER (шаг 10), 2026-10-13. Пункты планки: Q4, Q6 (случайная красная проверка; чинить причину, не перезапускать до зелёного). Требования: REQ-013 (файл-очередь движка; тест `tools/test/team-channel.test.js` назван в его критериях, стр. «(6) Тест tools/test/team-channel.test.js»), код проверки времени — `tools/src/team/reducer.js` (журнал команды); к REQ-042 не относится.

## Что не так

В первом полном прогоне `npm run check` TEST-DESIGNER (около 12:12Z) тест `EN-57 (1, 2) the first number of an empty channel is 1; two senders at once take 1 and 2` в `tools/test/team-channel.test.js` упал с ошибкой `E_TIME` («Часы компьютера показывают время раньше последней записи проекта», правило И11). Отдельный запуск файла три раза и повторный `check` — зелёные; позже TEST-DESIGN-VALIDATOR шесть раз прогнал файл и один раз полный `check` — зелёные; TEST-RUNNER (шаг 6) два полных прогона — зелёные; RELEASE-VALIDATOR (шаг 9) полный прогон на чистой копии — зелёный.

Связь с часами нашёл TEST-DESIGN-VALIDATOR по журналу службы времени macOS (`timed`), который прочитал сам: на этом компьютере служба время от времени шагает часы **назад** вызовом `settimeofday` — 2026-10-13T12:13:16.497Z на −0,111 с и 12:29:16.299Z на −0,060 с; кроме того, 12:12:10Z шли подстройки `adjtime` на −19 мс и −7 мс. Первый полный `check` TEST-DESIGNER шёл с 12:12Z около двух минут — шаг на 111 мс пришёлся на его окно.

Механизм (прочитан в коде): в `tools/src/team/reducer.js`, функция `checkTime`, для событий источника `ENGINE` проверка строгая — `at < prev` даёт `E_TIME` без допуска (для остальных источников допуск `LIMITS.TIME_SKEW_MS` есть). Тест `EN-57 (1, 2)` пишет события движка по настоящим часам `Date.now` в одном процессе без подставных часов; два события подряд в пределах нескольких миллисекунд при шаге часов назад на 60–110 мс дают именно эту ошибку.

Граница доказательства: сбой никто не вызвал заново; свидетельство — совпадение по времени с журналом ОС (не повтор теста). Это «внешняя причина названа, но не воспроизведена» (quality-bar §6, п. 4) — поэтому первым шагом ISSUE-FIXER должен воспроизвести её подстановкой часов. Файлы работы REQ-042 (`tools/src/pixel-office/public`, `tools/test/pixel-office-*`) с каналом команды не пересекаются.

Тот же риск касается и других тестов движка, которые пишут события по настоящим часам в один журнал.

## Доказательство

`handoffs/REQ042-20261013-01/step-05-test-designer.json` (I2), `step-05b-test-design-validator.json` (I1), `step-05b-test-design-validator-r1.json`, `step-06-test-runner.json` (EN-57 прошёл, шаг часов назад в окне не найден), `step-09-release-validator.json` (I4). Код: `tools/src/team/reducer.js` (`checkTime`), `tools/test/team-channel.test.js` (EN-57).

## Как исправить

WF-03 с шага 1 — **решение по коду команды принимает владелец или ORCH** (это политика времени движка, `decisions/`), не DOC-UPDATER. Варианты, названные TEST-DESIGN-VALIDATOR: (а) подставные часы в тестах движка, которые пишут события по настоящим часам; (б) допуск вниз на шаг службы времени для источника `ENGINE` в `checkTime`. Выбор (б) меняет поведение продукта и требует записи решения (Q12). Чинить не перезапуском до зелёного (Q6).

## Маршрут

ISSUE-FIXER (воспроизвести подстановкой часов) → решение ORCH/владельца (а или б) → CODE-DESIGNER → CODE-DESIGN-VALIDATOR → TEST-DESIGNER → TEST-DESIGN-VALIDATOR → CODE-FIXER → TEST-RUNNER → RELEASE-VALIDATOR → DOC-UPDATER → RELEASE-FINALIZER.
