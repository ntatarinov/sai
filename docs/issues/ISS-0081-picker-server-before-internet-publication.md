# ISS-0081 — Сайт подбора решения: пять мелочей сервера (REQ-056), которые нужно закрыть до публикации в интернет

Серьёзность: LOW, при решении о публикации — MEDIUM. Статус: open. Найдено: SECURITY-REVIEWER (прогон `SERVER056-20261020-01`, шаг 3: F1, F2, I3), REVIEWER (шаг 3b: F3), RELEASE-VALIDATOR (шаг 9: F1, F2, F4, I3; F2 и F4 воспроизвёл сам); заведено DOC-UPDATER (шаг 10), 2026-10-21. Пункты планки: Q10 (запросы, которые разборщик Node обрабатывает сам, идут мимо нашей защиты). Требование: REQ-056 (`done`; все восемь критериев выполнены, ни одна находка не блокировала). Сегодня сервер слушает только `127.0.0.1` и проверяет `Host`, поэтому вред ограничен; данных ни одна из находок не раскрывает.

## Что не так

1. **`Expect` обрабатывает сам Node, мимо защиты.** В `tools/src/picker/server.js` нет обработчиков `checkExpectation` и `checkContinue`. Запрос с `Expect: foo` получает от Node ответ 417 без `Cache-Control`, `X-Content-Type-Options` и `Referrer-Policy`. Запрос с `Expect: 100-continue` и чужим `Host` получает сначала «100 Continue» и только потом 403 (проект, п. 5.6, велит проверять `Host` первым шагом).
2. **`Content-Security-Policy` и `X-Frame-Options` есть только на HTML-ответах** (страница и `/assets/index.html`). У ответов JSON, файлов `.js` и пустых ответов (403, 308) их нет. По критерию 7 («у каждого ответа страницы») это верно, но шире, чем «на всех ответах». Вред маловероятен: JSON не показывается, есть `nosniff`.
3. **Нет предела времени записи при конвейере запросов.** Клиент, который шлёт запросы подряд и не читает ответы, удерживает соединение неограниченно: память ограничена обратным давлением, времени жизни нет. RELEASE-VALIDATOR такого клиента в своих пробах не создавал, поэтому это не измерено. Рядом (REVIEWER, F3): `refuseParse` пишет закрытый ответ прямо в сокет, не проверяя, идёт ли на нём ответ на предыдущий запрос; портит ответы только тому же клиенту.
4. **Регистр в имени файла страницы зависит от файловой системы.** На системе без учёта регистра (macOS, Windows) `/assets/Stub.js` отдаёт `stub.js` (200), на Linux было бы 404. Выхода из каталога нет (42 пути обхода проверены: 404 или 400), расхождение только в ответе.
5. **Значок страницы.** Браузер просит `/favicon.ico`, сервер отвечает закрытым 404 (так велит закрытый список маршрутов), и Chrome пишет в консоль строку `error` (воспроизведено: 18 из 18 загрузок UAT-RUNNER, 4 из 4 у RELEASE-VALIDATOR). Критерий 5 условия «нет ошибок консоли» не содержит, поэтому REQ-056 выпуск не заблокирован. Посетитель этого не видит. Решение нужно в проекте REQ-057, пока значок не объявлен (условие записано в ISS-0077, обновление 2026-10-21).

## Как исправить

Не срочно; нужно до решения владельца о публикации (`decisions/0068`, п. 2) или при ближайшей работе над `server.js`. (1) `server.on('checkExpectation', …)` с ответом через общую функцию `send` (417 с общими заголовками и текстом на языке) и `server.on('checkContinue', …)`, который сначала проверяет `Host` и только потом пишет «100 Continue»; тест в `SF-6c`. (2) Дописать в общие заголовки `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` для не-HTML ответов; HTML-ответы сохраняют политику из `config.js`. (3) Предел времени жизни соединения и проверка «на сокете нет ответа в пути» в `refuseParse`; решение о публикации и её требование — за владельцем. (4) Принимать только имена строчными буквами или сверять имя с перечнем каталога. (5) Объявить значок под `/assets/` (путь есть в закрытом списке, политика `img-src 'self'` его допускает) либо записать исключение в сценарий приёмки. Тесты не ослаблять (Q6); к пункту 1 нужен тест, который краснеет на текущем коде.
