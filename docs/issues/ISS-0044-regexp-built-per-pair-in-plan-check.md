# ISS-0044 — RegExp в namesFile и missingSources собирается заново для каждой пары «задача x файл x поле»

Серьёзность: LOW. Статус: open. Найдено: SECURITY-REVIEWER и REVIEWER (прогон ISS-0031-20261011-01), 2026-10-12. Пункты планки: Q10. Требования: REQ-013 (критерий 15).

## Что не так

В `tools/src/team/engine/plan.js` `namesFile` и `missingSources` собирают RegExp заново для каждой пары «задача плана x принятый файл x поле». Время растёт линейно: на предельном проекте (40 задач, 8 000 принятых файлов с длинными именами и текстами) `validatePlan` занял 5,4 с синхронно и блокирует цикл событий движка. Неверного результата нет; на реалистичном проекте — миллисекунды (400 файлов — 21 мс, 2 000 — 100 мс).

## Доказательство

`handoffs/ISS-0031-20261011-01/step-05-security-reviewer-security.json` (L1), `handoffs/ISS-0031-20261011-01/step-05-reviewer.json` (R1).

## Как исправить

Перед сборкой RegExp проверять `text.includes(original)` или кэшировать правило по исходному имени на время одного `validatePlan`; тест на скорость предельного проекта с запасом (не по часам стены, ISS-0004).

## Маршрут

WF-03 с шага 1.
