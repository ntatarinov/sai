# ISS-0032 — Пробелы тестов handoffs-check: выживший мутант H8, хрупкие пороги и числа, тесты читают живое рабочее дерево

Серьёзность: LOW. Статус: open. Найдено: TEST-DESIGN-VALIDATOR (`handoffs/REQ038-20261011-01/step-05b-test-design-validator.json`, F3; `step-05b-test-design-validator-r1.json`, мутант H8 и F3/F4) и RELEASE-VALIDATOR (`step-09-release-validator.json`, остаточные риски). Пункт планки: Q5 (тесты закрывают критерии и ловят мутанты). Требования: REQ-038 (критерии 2, 7).

## Что не так

1. **Выживший мутант H8.** Если в правиле H8 («`completed_at` не раньше `started_at`») заменить сравнение на допуск в одну секунду (`completed + 1 < started`), ни один тест не падает (0 из 123). В `HC-2i` нет случая «`completed_at` ровно на одну секунду раньше `started_at`».
2. **Хрупкий порог.** `HC-RT-1a` требует не менее 7 файлов в `tools/src/handoffs/` (сейчас ровно 7): слияние двух модулей покраснит тест без причины.
3. **Число 114 и живое дерево.** `HC-7c`, `HC-7a` и `HC-5b` читают живое рабочее дерево и число записей базы (114); чужой handoff с ошибкой, новый файл базы или клон с обрезанной историей git делают набор красным не по вине кода. Для этих тестов нужна полная история git. Записи об этом в `tools/README.md` пока нет: README правит BACKEND-DEV в следующем прогоне, этот дефект его не правит.

## Как исправить

WF-03 с шага 6: добавить в `HC-2i` случай «на 1 секунду раньше» (красный на мутанте); заменить порог «не менее 7 файлов» проверкой по содержимому (по названиям модулей или по списку из проекта); числа 114 брать из базы, а не вписывать, и для тестов живого дерева явно требовать полную историю (понятная ошибка вместо красного теста на обрезанной истории).

## Доказательство

`handoffs/REQ038-20261011-01/step-05b-test-design-validator-r1.json` (мутант «допуск в 1 секунду» — 0 упавших; F3, F4), `step-05b-test-design-validator.json` (F3), `step-09-release-validator.json` (остаточные риски).
