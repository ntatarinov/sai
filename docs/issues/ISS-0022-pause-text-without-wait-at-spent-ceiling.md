# ISS-0022 — Текст паузы «чтобы работа пошла дальше» не всегда правда: пауза без ожидания при исчерпанном потолке

Серьёзность: LOW. Статус: open. Найдено: RELEASE-VALIDATOR прогона `PROD-20261011-01` (`handoffs/PROD-20261011-01/step-41-release-validator.json`, L1; записан при учёте 2026-10-11T10:30:40Z). Пункт планки: Q10 (текст для человека правдив). Остаток ISS-0020.

## Что не так

Если потолок расходов уже исчерпан, а проект поставлен на паузу без ожидания решения (кнопка «Пауза» во время последнего запуска), строка паузы говорит «Проект на паузе. Нажмите «Продолжить», чтобы работа пошла дальше». После нажатия журнал получает PROJECT_RESUMED, затем PROJECT_WAITING budget и сообщение в чат; запусков 3 → 3, проект «ждёт решения». Живьём (step-41, потолок 0,2, расход 0,25): обещание не сбывается, но после нажатия страница говорит правду, денег не тратится.

## Почему LOW

Работа не теряется, деньги не расходуются, страница после нажатия показывает правдивое состояние. Текст «чтобы работа пошла дальше» требует критерий 1 REQ-035 дословно, поэтому это принятый остаток (`decisions/0032`, C4, C7).

## Как исправить

Решение владельца: изменить критерий 1 REQ-035 (WF-01) так, чтобы текст паузы у проекта с исчерпанным потолком не обещал продолжения («…после «Продолжить» он снова спросит о потолке»), затем текст, тест и строка README (CODE-DESIGNER и ORCH, WF-03). Связан с ISS-0019 (расход выше потолка до ожидания).
