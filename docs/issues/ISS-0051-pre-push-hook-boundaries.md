# ISS-0051 — Хук pre-push теряет последнюю строку stdin без перевода строки и проверяет рабочую папку, а не отправляемый коммит

Серьёзность: LOW. Статус: open. Найдено: REVIEWER (L1) и CODE-DESIGN-VALIDATOR (F3), прогон REQ030-20261012-01, 2026-10-12…2026-10-13. Пункты планки: Q10. Требования: REQ-030 (критерий 4).

## Что не так

1. Цикл `while read -r` в `.githooks/pre-push` (строки около 5–12) не отдаёт в тело последнюю строку stdin без завершающего перевода строки. Если перед ней были только удаления, хук решит, что отправляемого кода нет, и пропустит проверку. На настоящей отправке это не случается: git всегда завершает строки переводом (проверено на отправке в локальный bare-репозиторий, `od`). Обычная защита (`|| [ -n "$local_ref" ]`) запрещена правилом PH-2 (никаких `||` в хуке), поэтому тест закрепляет безопасное направление (PH-5: строка без хеша — не удаление), а не саму границу.
2. Хук запускает `npm run check` на рабочей папке (с неотправленными правками и неотслеживаемыми файлами), а не на коммите, который уходит. Отправка другой ветки или чистого коммита проверяется по чужому состоянию. Граница названа в README (R-7) и проекте (п. 3.4).
3. Хук отнимает около двух минут на каждую отправку (107–120 с); обход флагом git запрещён только правилами процесса.

## Доказательство

`handoffs/REQ030-20261012-01/step-04-reviewer.json` (L1), `step-01b-code-design-validator.json` (F3), `step-05b-test-design-validator.json` (F8), `step-09-release-validator.json` (I2, риск 3).

## Как исправить

Для п. 1: переписать цикл так, чтобы последняя строка не терялась, без `||` (например, `while IFS= read -r line` с отдельной обработкой остатка через `read`-проверку после цикла) и снять запрет в PH-2 в той части, где он мешает, — решение с тестом. Для п. 2: проверять отправляемый коммит в чистой рабочей копии (`git worktree` / `git archive`) — отдельный проект и решение в `decisions/`.
