# ISS-0041 — Задача, называющая файл задачи того же круга плана, файла не получает

Серьёзность: LOW. Статус: open. Найдено: REQ-ANALYST и CODE-DESIGNER (прогон ISS-0031-20261011-01), 2026-10-12. Пункты планки: Q1. Требования: REQ-013 (критерий 15).

## Что не так

Правило критерия 15 касается только принятых файлов прежнего круга. Если в первом круге плана две независимые задачи идут параллельно и вторая называет файл первой в `text`, файл она не получит: принятого файла ещё нет, а ядро зависимость не достраивает. Критерий 15 явно вынес этот случай в «не входит».

## Доказательство

`handoffs/ISS-0031-20261011-01/step-02a-req-analyst-r1.json` (граница «не входит»), `handoffs/ISS-0031-20261011-01/step-03-code-designer.json`.

## Как исправить

Решить, нужна ли для такого случая достройка `depends_on` по имени, которое задача-источник обещает в `done_when` (файл ещё не принят); при необходимости новый критерий REQ-013 и проект.

## Наблюдение настоящего запуска (2026-10-13, прогон `REAL-20261013-01`)

Случай этого дефекта встретился на настоящей модели. В плане проекта `p-20261013-e20bfa` задача `t-0006` называет в тексте `tips_cafe.md` («утвердить финальную версию `tips_cafe.md`»); этот файл сдала `t-0004`, а `depends_on` у `t-0006` — только `t-0005`. Ядро выдаёт содержимое файлов только задач из `depends_on` (`depsOf` в `tools/src/team/runner.js`), поэтому файл `t-0004` задача `t-0006` могла не получить. Видела ли она текст, по журналу сказать нельзя: вход запуска не сохраняется. Итоговая страница получилась хорошей. Критерий 15 REQ-013 говорит только о файлах предыдущего круга и такой случай (задача того же круга, не в `depends_on`) явно исключает, поэтому критерий не нарушен, а дефект остаётся открытым. Родственный пробел — ISS-0046: у достроенной ядром зависимости нет отметки «добавлено ядром», и по журналу нельзя отличить, кто поставил зависимость.

Источники: `docs/uat/REAL-RUN-20261013.md`, раздел «Что нашлось попутно», п. 4; `handoffs/REAL-20261013-01/step-09-release-validator.json` (F5).
