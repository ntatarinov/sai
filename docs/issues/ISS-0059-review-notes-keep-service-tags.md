# ISS-0059 — Служебные теги `</notes>` и `</invoke>` остаются в замечаниях проверки: ответ модели принят как есть

Серьёзность: LOW. Статус: open. Найдено: UAT-RUNNER (прогон `REAL-20261013-01`, шаг 8), подтверждено RELEASE-VALIDATOR (шаг 9, F3), заведено DOC-UPDATER, 2026-10-13. Пункты планки: Q3, Q10. Требования: REQ-013.

## Что не так

В записи проверки задачи `t-0004` настоящего запуска (событие 89, `data.notes`) в конце замечаний остались теги разметки `</notes>` и `</invoke>`: настоящая модель вернула их внутри поля, и движок принял текст как есть. На решение «прошла» это не влияет (остальные пять проверок чистые), но замечания проверяющего показываются владельцу, и на странице попадёт обрывок разметки.

## Доказательство

`docs/uat/REAL-RUN-20261013.md`, раздел «Что нашлось попутно», п. 2; `handoffs/REAL-20261013-01/step-09-release-validator.json` (F3: теги видны в `data.notes` события 89). Проверить на данных запуска: `team -- events <id проекта> --after 80` и найти событие 89.

## Как исправить

Отдельная работа по WF-03 с диагноза ISSUE-FIXER. Развилка для проекта CODE-DESIGNER: где чистить ответ проверяющего (разбор ответа в движке, до записи события) — убирать из `notes` хвостовые служебные теги (`</notes>`, `</invoke>`, `</parameter>`) либо считать их признаком порчи ответа. Не менять решение «прошла/не прошла». Регрессионный тест на поддельном claude: ответ проверки с хвостовыми тегами — в журнале замечания без тегов, решение то же. Критерии REQ-013 не нарушены, поэтому правка критерия не нужна, если проект не меняет наблюдаемое поведение шире этого.

ISSUE-FIXER → CODE-DESIGNER → CODE-DESIGN-VALIDATOR → CODE-FIXER → SECURITY-REVIEWER → REVIEWER → TEST-DESIGNER → TEST-DESIGN-VALIDATOR → TEST-RUNNER → RELEASE-VALIDATOR → DOC-UPDATER → RELEASE-FINALIZER.
