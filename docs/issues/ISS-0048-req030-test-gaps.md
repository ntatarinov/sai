# ISS-0048 — Пробелы тестов REQ-030

Серьёзность: LOW. Статус: open. Найдено: TEST-DESIGN-VALIDATOR (прогон REQ030-20261012-01), 2026-10-13. Пункты планки: Q5, Q6. Требования: REQ-030.

## Что не так

Ворота тестов (60 мутантов, 51 пойман, 9 выжили) нашли места, где 22 новых теста REQ-030 в `tools/test/repo.test.js` не ловят ошибку или привязаны к внутреннему тексту:

1. **F1, мутант W10.** Строка `shell: echo {0}` в шаге проверки `check.yml` (шелл, который проглатывает код выхода `npm run check`) проходит все 22 теста: CI-4 требует нужные строки и ровно две строки `run`, а список слов CI-7 («ничто не прячет красную проверку») слова `shell:` не содержит. Тот же приём через `defaults.run.shell` ловится только случайно (CI-4).
2. **F2, мутант R10.** RD-2 проверяет только наличие основы «обход»: замена «обход запрещён правилами процесса» на «обход разрешён правилами процесса» проходит все тесты.
3. **F4, мутант H17.** Обход хука по переменной окружения (`if [ -n "$SAI_SKIP_CHECK" ]; then exit 00; fi`) выживает: запрет «`exit 0` не больше одного» обходится написанием `exit 00`; теста «при любых переменных пропуска (SKIP, HUSKY, CI) хук всё равно проверяет» нет.
4. **F5, мутанты W12, W13, W16, W21.** Не закреплены имена шагов workflow («Get the code», «Install Node 22», «Install dependencies», «Run the check»), на которые опирается шаг П-3 проекта (`gh run view … steps`), а также `runs-on`, `timeout-minutes`, `cancel-in-progress`. Переименование шага не краснит ни один тест.
5. **F9, мутант H21.** Сообщение пути «отправляются только удаления…» не закреплено: тесты проверяют код 0 и отсутствие запуска проверки, но не вывод.
6. **F3.** PH-2…PH-8 строят мутанты по точным строкам хука (`code=$?`, `(код $code)`, строки условий): нейтральное переименование переменной `code` краснит PH-2 и PH-3 (проверено запуском E5) — громко и с понятным сообщением, но правка хука потребует правки тестов.

## Доказательство

`handoffs/REQ030-20261012-01/step-05b-test-design-validator.json` (findings F1…F5, F9; запуски мутантов W10, R10, H17, W12, W13, W16, W21, H21, E5 в `summary`). Критерий 1 REQ-030 этих слов не называет, поэтому ворота их не блокировали.

## Как исправить

Один проход TEST-DESIGNER (WF-02) или WF-03: (1) в CI-4 сделать список ключей шага закрытым либо добавить `shell:` и `defaults:` в запрещённые слова CI-7 с мутантом на каждое в CI-8; (2) в README_WORDS заменить «обход» на «обход запрещён»; (3) в PH-3/PH-4 добавить запуск с типичными переменными пропуска; (4) закрепить четыре имени шагов в CI-4; (5) закрепить сообщение пути «только удаления». Пункт 6 — при следующей правке хука менять тесты вместе с ним.

## Маршрут

WF-03 с шага 1.
