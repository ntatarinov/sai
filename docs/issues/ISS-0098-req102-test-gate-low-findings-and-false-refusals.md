## Что не так

All items are Low, none changes the verdict of the gates, and the code is on the safe side in each one: the real code refuses where the tests are silent. The tests of REQ-102 simply do not hold these positions, so a later edit of `findSecrets` could change them unseen.

1. **The host after the at sign and a non-string argument (08p F1).** The comment block `X-BEGIN` of `tools/test/team-result-bytes.test.js` says an address with a real password is refused «whatever stands behind the at sign (even nothing)», but no row puts an empty, a white-space or a slash host behind the at sign: the reference of the address place always appends a host of its own. Two mutants of the validator survive: «the host must be non-empty» (a text that ends with the at sign is stored; survived the whole bytes file, 55 of 55 green) and «the host is one non-white-space character» (survived the fast subset). The guard at the end of `findSecrets` (a non-string returns `null`) is also held by no row (mutant without it survives). The requirement is silent on the host and on a non-string, so this is a silent position, named in the comment and pinned by nothing. Fix (TEST-DESIGNER, rows only, no code change): refused rows for the password of an address with the host missing (the text ends with the at sign, or the at sign is followed by a line end, by a space, by a slash), as a sweep of one slot after the at sign with the empty slot included; optionally `findSecrets(undefined)` and a number give `null`.
2. **«Without regard to case» is read as ASCII only (08p F2).** A fifth silent position, not in the list: a value made of the Kelvin sign (U+212A) followed by `ey` is refused by the code (the safe side), while a Unicode case-folding reading would make it the word `key` and store it. Mutant «`findLowerAscii` replaced by `toLowerCase`» survives the whole bytes file because no row has such a character in a case-insensitive slot (the extra set holds an accented letter, a sharp s, full-width forms and an astral character, none of which folds to an ASCII letter). Fix: name it as silent position (5) in the comment («case is ASCII only; U+212A is not k»); optionally add U+212A and U+017F to the extra set or one refused row with the Kelvin sign inside a name-value pair.
3. **A damaged comment (08p F3).** In the same file the two comment lines before `X_EXTRA` («a letter outside ASCII (two), the full-width forms …») lost the head of their sentence when the list of silent positions was inserted in the middle of the paragraph (about lines 3405-3406 at the time of the gate). Comment only. Fix: restore the head («The fixed set of other characters in the slots: …») below the list.
4. **Mutant m23 as written is equivalent (RELEASE-VALIDATOR L4) and the time of the bytes file (08p F4).** On the final code the design mutant «`depsOf` throws on a secret» changes nothing, because the throw sits inside `withheldOrContent`, whose `try`/`catch` returns the constant text; 18 tests stay green. The variant that throws outside the `try` is red in RB-03 (d). The behaviour is held. Fix: the list of mutants in the design or the test comment says that m23 means a throw outside the `try`. The bytes file alone takes 144-147 s on the developer's machine (132, 140, 144.5, 138.8, 146 s over the passes, no trend), inside the 600 s test timeout; no action, noted so that nobody reads it as growth.
5. **False refusals of the new scan (RELEASE-VALIDATOR L5, F1 of the task; the price accepted by the owner).** Measured by the validator on a copy of the project: of 2325 text files the new scan refuses 133, and all of them are documents, handoffs and tests that talk about secrets, plus one line of ordinary code, `tools/src/team/language.js` line 30 (a quoted Russian sentence with a space after the name `secret`). The old masking changed 1591 of the same files. A refused file fails the whole attempt of the task without retry (`tools/README.md`, «False refusals»). **Decision of DOC-UPDATER: a note in this defect, not a change of the README.** The README sentence already names the kinds of false refusal (a fake password in an agent's own test, messages such as `Unexpected token`, text about PEM headers other than the certificate, a value after a plain lower-case name, a placeholder with an ampersand, a slash or a colon glued on, a bare address as a value, a quoted value with a space), and the two numbers above change with every file of the project, so they would be stale in a week. What this item adds is the measure for the day of the release and the one code line that hits a real file of the project. What can be done later: if agents' real code is refused often, revisit the false-refusal list together with ISS-0097 item 1 (a wider rule means more false refusals: measure them again on the project's text files and write the new count here).
