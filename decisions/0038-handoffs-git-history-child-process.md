# 0038 — Третье место child_process: tools/src/handoffs/git-history.js (поправка к 0021, D1)

Статус: **принято** (ORCH, 2026-10-11, решение о ходе работы по `CLAUDE.md`, «Роли», закрытый список ORCH; основание — остановка B1 в `handoffs/REQ038-20261011-01/step-01-code-designer.json` и FAIL REQ-VALIDATOR в `step-00b-req-validator.json`, замечание F1; владелец может отменить).

## Вопрос

Правила H4, H7 и сверка базы REQ-038 читают историю git (`log`, `cat-file`, `merge-base`, `rev-parse`). Решение `0021` (D1) и критерий 4 REQ-014 допускают `child_process` в `tools/src` только в исполнителе `claude-cli` и в `tools/src/traces/git-files.js`, а тест TR-4c требует ровно эти два файла.

## Варианты

1. Добавить вызовы git в `git-files.js` — запрещено (`0021` D1: ровно два вызова, фиксированные аргументы) и ломает TR-4c.
2. Не проверять историю (отказаться от H7, H4(б) и сверки базы) — понижение требования REQ-038.
3. Обойти TR-4c (спрятать слово, вынести файл из `tools/src/`) — обход проверки (Q6).
4. Третье место — один файл `tools/src/handoffs/git-history.js` с теми же ограничениями, что D1 (только `execFileSync`, без оболочки, фиксированные аргументы, `core.fsmonitor=false`), одна строка в `CHILD_PROCESS_FILES` теста TR-4c, новый тест команды повторяет для этого файла проверки TR-4c.

## Решение

Вариант 4. Формулировку критерия 4 REQ-014 приводит в соответствие отдельный шаг WF-01 (поправка, как в прецеденте `0025`); `0021` D1 не отменяется: оно относится к `tools/src/traces/`.

## Почему

Защита не ослабляется: TR-4c остаётся красным для любого другого файла с `child_process`, а содержимое нового файла держит новый тест команды (HC-RT-1 в проекте REQ-038).

## Граница

Решение не разрешает других новых мест с `child_process` и не меняет код `git-files.js`.

## Основание

Ворота проекта REQ-038 и REQ-VALIDATOR (ссылки в статусе), `decisions/0021` (D1), `decisions/0025` (прецедент), `decisions/0034`. Отдельных слов владельца об этом решении нет — оно принято ORCH и может быть отменено владельцем.
