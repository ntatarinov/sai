# 0031 — База сравнения для проверок «что изменилось в прогоне»: метка git `base/<RUN-ID>`

Статус: **принято** (ORCH, 2026-10-11, по общему поручению владельца; владелец может отменить). Уточняет WF-02.

## Вопрос

Критерии REQ-036 и REQ-037 проверяют границу изменений командой `git diff` от коммита начала прогона. В WF-02 нет файла «шаг 0», где хранить хеш этого коммита, а сравнение с последним коммитом пусто после любого коммита посреди прогона.

## Решение

В начале прогона WF-02 ORCH ставит лёгкую метку git `base/<RUN-ID>` на коммит, с которого начинается прогон (до первого изменения). Проверка границы читает базу только отсюда: `git diff base/<RUN-ID>` (с рабочим деревом, включая незакоммиченное; новые файлы — через `git status --porcelain`). Если метки нет, проверка сообщает «база не задана» и прогон не получает PASS на этом пункте. Метка локальная, в репозиторий отдельно не отправляется; её имя ORCH записывает в `context` каждого handoff-а прогона (`base_tag`).

## Последствия

- Правка WF-02 (`docs/workflows`): одно предложение в шаге 0 ORCH — «поставить метку `base/<RUN-ID>`».
- Критерии REQ-036 (9 б) и REQ-037 (2) читают базу из метки, а не из «handoff шага 0».
