Status: **accepted** (ORCH, 2026-11-16, inside the owner's word of 2026-11-16 «Продолжай» after the report of REQ-106 that named REQ-107 as the next item, and of 2026-11-08 in `decisions/0110`; the owner can cancel each point).

## Question

The design `docs/design/REQ-107-e2e-team-web.md` (section 19) leaves eighteen questions for ORCH (WF-02, step 1a). They must be closed before the gate CODE-DESIGN-VALIDATOR. The design also proposes choices C-1…C-13 (section 2) that could be disputed and are recorded here (Q12). The run has a safety rule R2-T written in the task of step 1 (no Node program of the project with the person's real home or without a temporary `SAI_TEAM_HOME`; `SAI_TEAM_REAL_RUNS` never set; `SAI_TEAM_CLAUDE_BIN` always a recording trap; the real `claude` program never started; the rule R2-S of `decisions/0112` kept).

## Options

For each point the design names a default and what the other choice costs (section 19). No point is closed by a guess outside that table.

## Decision

- **О1.** Accepted: the kit gives Chrome the argument `--use-mock-keychain` (BACKEND-DEV, sub-step 1; `E2K-25` edited; the README sentence). Reason: measured by the designer (F32), under a home folder below the temporary root the released kit's Chrome on macOS does not answer its first navigation; with the argument the page loads. The argument also keeps the browser of the normal check away from the person's keychain. Conditions: the gate checks that no criterion of REQ-104 forbids a new argument; the effect on Linux is proven by the GitHub run of step 6 (green spec files on ubuntu-24.04), not assumed.
- **О2.** Accepted, the designer's default: R2-T binds what its words say — every sketch, trial and mutant of this run that starts the team server, the engine, a team command, a Pixel Office program or a Node program of the project. The full `npm run check` of steps 6 and 9 and the last command of criterion 8 run as in REQ-106: the spec process keeps the person's home, every stand gets its private home, and the GitHub run is the evidence (`decisions/0110`). Basis checked by ORCH on the tag: the released tests that give a child `SAI_TEAM_REAL_RUNS=1` do it through `tools/test/exec-helpers.js`, which refuses to run unless `SAI_TEAM_CLAUDE_BIN` names an executable fake inside `tools/test/fixtures/team/` (its lines about "SAI_TEAM_CLAUDE_BIN is not set / is outside fixtures / relative is not allowed"); the other hits in tools/test unset the variable or check that it is absent. The gate repeats this check on the tag: a released test that sets `SAI_TEAM_REAL_RUNS=1` without such a fake is a High finding. A stricter reading (the whole check under a temporary home) is a raise of the bar and goes to the owner (quality-bar §4).

- **О4.** Accepted (C-4): "at the end of the whole file the trap marker file does not exist, and the data folder has no project of the executor `claude-cli`" is read as an end check in every test (stronger: each test is also run alone, criterion 8).

## Why

Each answer is the default of the designer where the default keeps the work inside the criteria of REQ-107 (Q5) and inside the bar (Q4, Q6, Q7, R2, R3). No exemption of rule P is added: the trap and the scenarios are copied under the temporary root, so the starter stays as released. The one kit change (О1) is a single standard browser argument with its own test edit, and its effect on Linux is proven on GitHub, not assumed. The two weak places of the product found on the way (О10, О11) are recorded as defects instead of being hidden by the test or fixed outside the run's write set.

## Boundary

Only the run E2E107-20261116-01, the kit argument of О1 and the spec `team-web.e2e.js` with its fixtures. It changes no product code in tools/src/, it does not fix the open defects ISS-0105, ISS-0107, ISS-0108, ISS-0110 and ISS-0111, and it does not answer `decisions/0112` О19.
