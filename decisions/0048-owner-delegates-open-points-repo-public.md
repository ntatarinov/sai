# 0048 — Репозиторий Sai на GitHub открыт намеренно; владелец поручает ORCH решить пункты 2–5

Статус: **принято** (по слову владельца, 2026-10-13; ORCH записал; владелец может отменить).

## Вопрос

В отчёте ORCH от 2026-10-13 владельцу были заданы вопросы: (1) открыт ли репозиторий Sai на GitHub намеренно; (2) согласие на отправку временной ветки с падающим тестом на GitHub (критерий 3 REQ-030); (3) защита ветки `main` и настройка «Require approval for all external contributors»; (4) новый настоящий запуск Claude и потолок расходов; (5) как считать критерий «сохранён в out/memo.md» с папкой (ISS-0028). Нужно записать ответ и границы поручения.

## Варианты

1. Ждать отдельного слова владельца по каждому пункту.
2. Принять поручение: на (1) ответ владельца известен, на (2)–(5) решает ORCH сам в рамках границ ниже.

## Решение

Вариант 2. Слова владельца 2026-10-13, дословно: «Репозиторий в GitHub я специально открыл. А все остальное сам реши, пожалуйста. Два три четыре пять пункт. Я тебе доверяю. Но это не финальный результат наш. Нужно работать и работать. Который правки я тебе еще не говорил. Мне нужно базу подготовить. Самое главное. Чтобы можно было с этим кому-то подойти».

- Репозиторий публичен намеренно. Основание решения `0023` (D1: защиты ветки нет, потому что репозиторий приватный) отпало: защита `main` доступна, её включает ORCH в границах ниже. Документы, которые называют репозиторий приватным (ISS-0049), приводятся к факту.
- Пункты (2)–(5) решает ORCH: выбранное и причины записываются в `docs/releases/`, `STATE.md` и, где это выбор между вариантами, в `decisions/`.
- Цель владельца, сказанная в том же сообщении: подготовить «базу», с которой можно подойти к другим людям. Правки по существу владелец ещё не называл — следующие задачи придут от него; до них ORCH работает над готовностью базы (проверка отсутствия секретов и путей в публичной истории, точность документов, зелёная проверка на GitHub, понятное описание).

## Почему

Владелец дал прямое поручение и доверие; затягивать пункты, на которые у ORCH есть разумные ответы, значит терять время.

## Граница

Решение не отменяет планку: мерж — по R1 (ORCH отправляет в `main` только после PASS RELEASE-VALIDATOR, как разрешено 2026-10-11); не разрешает ничего, что нельзя отменить или что тратит деньги вне подписки владельца; не разрешает отправку чужого содержимого, смену владельца, удаление репозитория, изменение платных настроек и приглашение людей. Настоящие запуски Claude Code идут за счёт подписки владельца; потолок одного запуска — по записи ORCH (не больше 3 долларов за запуск), не больше трёх запусков до следующих слов владельца. Временная ветка с падающим тестом создаётся, проверяется и удаляется в том же шаге; настройки GitHub меняются только обратимо (защита `main` без блокировки прямой отправки администратором; одобрение первых вкладчиков), каждое изменение записывается.

## Основание

Слова владельца 2026-10-13 (выше, дословно); `decisions/0023` (D1), `decisions/0044`, `decisions/0045`; `docs/design/REQ-030-github-check.md`; отчёт ORCH с вопросами владельцу.

Narrowed by decisions/0092 (2026-10-28): for `app/` the 3 $ × 3 run limit is replaced by the owner's written answer to G2 (real AI runs); the push rule after RELEASE-VALIDATOR PASS stays.
