# 0015 — Старт разработки продукта «виртуальная команда» (Sai Team): стек, хранение, исполнитель и решения D-A…D-F

Статус: принято (2026-10-06, ORCH). Владелец может отменить. Меняет границу `CLAUDE.md` («код продукта пишется только
после решения о старте»), границу решений `0002` и `0003` («код продукта в `tools/` не пишется») для каталога
`tools/src/team/` и принимает для него стек и команду проверки (quality-bar Q4) вместо зарезервированной `0001`.
Расширяет `0011` правилами хранения проектов и чата.

## Вопрос

Владелец поручил довести продукт до рабочего состояния: пользователь ставит цель, система сама строит план, запускает
агентов, проверяет результат, а Pixel Office показывает настоящую работу. Можно ли начать писать код такого продукта,
каким стеком и по каким правилам хранения, исполнения, проверки и безопасности?

## Честно о том, чего не было

Проверки спроса — 20 магазинов одежды и платный пилот — по `0001` и разделу «Решение владельца о старте» в `STATE.md` не
проводилось. Это принятый риск: продукт строится по слову владельца без подтверждённого спроса. По quality-bar §6, п. 7
такое решение принимает владелец; здесь оно принято ORCH по его прямому слову и поэтому отменяемо: владелец может
остановить работу, и записи `0001` и условия старта из `STATE.md` снова станут главными.

## Варианты

1. Ждать проверки спроса (прежний порядок, `0001`): код продукта не пишется.
2. Начать по слову владельца: код продукта — в `tools/src/team/`, стек и проверка — как у служебного кода (`0002`, `0003`).
3. Начать по слову владельца с отдельным стеком и базой данных (решение `0001` после выбора стека).

## Решение

Вариант 2. Стек для `tools/src/team/` — **Node 22 без зависимостей во время выполнения**, как в `0002` и `0003`; одна
команда проверки по Q4 — `cd tools && npm run check` (в неё входит `npm test`). Запись `0001` (стек продукта) для этого
кода не нужна; её граница остаётся за кодом, которого здесь нет. `node:sqlite` не используется (в Node 22 экспериментальный).

### Решения ORCH D-A…D-F

| № | Вопрос | Решение |
|---|---|---|
| D-A | Хранение | Каталог `~/.sai-team` (права 0700; для тестов и запуска — переменная `SAI_TEAM_HOME`), в нём папка на проект: `events.jsonl` (0600) и `files/` для результатов (файлы 0600, папки 0700). Журнал `events.jsonl` — только на добавление, строка целиком или ничего, `fsync` до ответа «записано». Состояние проекта и задач выводится воспроизведением журнала; любой другой файл состояния только производный. Право записи — у одного процесса, файл-замок создаётся атомарно, с pid; замок мёртвого процесса снимает следующий писатель |
| D-B | Исполнитель | Интерфейс `run()`. «claude-cli» — единственный настоящий: Claude Code как дочерний процесс (`claude -p`, вывод `stream-json`, потолок `--max-budget-usd`, набор инструментов по роли, без оболочки). «scripted» — только для тестов, с честной пометкой «тестовый исполнитель», по умолчанию не выбирается. Настоящие запуски — только при `SAI_TEAM_REAL_RUNS=1` и заданном потолке стоимости. Запасной вариант — API Anthropic по ключу из переменной окружения — позже, отдельным решением |
| D-C | Планировщик | Роль «Руководитель проекта» отдаёт план по схеме (задача: роль, описание, критерий готовности, зависимости, отметка «критическое»); движок проверяет схему, роли из каталога, отсутствие циклов и не больше 40 задач |
| D-D | Проверка «готово» | Отдельным запуском роли «Проверяющий» — не тем, что делал задачу; повторы с замечаниями, затем другая роль, затем вопрос пользователю |
| D-E | Согласования | Критическое действие (отправка, публикация, удаление, финансы, важные данные, передача наружу) не выполняется: роль готовит черновик, проект ждёт ответа пользователя. Движок в этом срезе не совершает действий вовне |
| D-F | Язык | Один модуль перевода событий в человеческие фразы для чата, ленты и Pixel Office; технического (контекст, токены, промт, JSON, коды выхода) во фразах нет |

### Дополнительные правила

- **Хранение проектов и чата** (расширяет `0011`): всё локально, права 0600/0700, ничего не уходит с компьютера; сообщения
  чата — события журнала; перед записью строки данных проходят маскирование секретов из `0013`; пользователь удаляет
  проект целиком — папкой проекта (команды удаления в этом срезе нет).
- **Параллельность:** по умолчанию 2 одновременные задачи, настройка 1–3 — лимит владельца (`PLAN.md`, «одновременно не больше
  двух»).
- **Q11 по сети Исследователя — остаточный риск:** роль «Исследователь» выполняет исходящие GET-запросы по адресам, которые выбирает модель; возможна утечка контекста через адрес, а проверить каждый адрес до запроса нельзя. Защита: только чтение, потолок стоимости, таймаут задачи и выключатель SAI_TEAM_WEB=0, который отключает сеть у этой роли. Этот остаточный риск назван здесь и будет назван в отчёте владельцу; он не равен полному выполнению Q11 (запрет внутренних адресов проверяется только там, где адрес задаёт сам Sai).
- **Второй источник событий Pixel Office (движок)** — отдельная запись `decisions/NNNN-*.md` перед началом REQ-012; эта
  запись его не разрешает.
- **Блокировки владельца:** согласие на реальные запуски движка и потолок расходов (ключ API для основного варианта не
  нужен — вход Claude Code под подпиской).

## Почему

Прямое слово владельца и его критерий готовности: рабочий продукт, а не планы. Стек и проверка без зависимостей уже
работают (483 теста служебного кода) и не требуют нового решения о стеке. Журнал только на добавление и один писатель дают
проверяемую правду (как R2 для Pixel Office); исполнитель Claude Code не требует ключа и ходит под подпиской владельца.

## Граница

- Разрешён код продукта только в `tools/src/team/` и тесты `tools/test/team-*.test.js`. `tools/src/pixel-office/` не меняется
  (из него только импортируется `mask.js`); `~/.sai-pixel-office` не трогается.
- Не меняются: планка качества (Q1–Q14, R1–R3), правила мержа (R1), `0002`, `0003`, `0005`, `0007` вне границы
  выше. Магазины, фото покупателей и SQL в этом срезе отсутствуют, поэтому Q8, Q9 и R3 неприменимы.
- Требования: REQ-009 (ядро), REQ-010 (исполнители), REQ-013 (движок); REQ-011 (интерфейс) и REQ-012 (Pixel Office как
  зеркало) зарезервированы, их блоков нет. Порядок и готовность — `docs/product/roadmap.md`.
