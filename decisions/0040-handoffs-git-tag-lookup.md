# 0040 — Шестой вызов git в `tools/src/handoffs/git-history.js`: поиск метки `base/<RUN-ID>` (поправка к 0038)

Статус: **принято** (ORCH, 2026-10-11T19:25:26Z, после PASS CODE-DESIGN-VALIDATOR step-01b-r2; предложено CODE-DESIGNER, прогон `REQ039-20261011-01`, шаг 01; владелец может отменить). Опирается на `0031`, `0037`, `0038`. Проект — `docs/design/REQ-039-handoff-command.md`, п. 6.3.

## Вопрос

Команда `npm run handoff -- new` читает метку `base/<RUN-ID>` для любого процесса (есть — пишет `context.base_tag`; нет — отказ у WF-02, у остальных поля нет) (`0031`). Как узнать, что метка есть, не добавляя новых мест с `child_process` (`0038`)?

## Варианты

1. Прочитать `.git/refs/tags/base/<RUN-ID>` и `packed-refs` без вызова git — отклонено: в `git worktree` и подмодуле `.git` — файл-указатель и метки лежат в общем каталоге; после `git gc` метки уходят в `packed-refs`; хранилище ссылок может быть иным (`reftable`). Любой из случаев даёт ложное «метки нет» и блокирует каждый WF-02.
2. Вызов git в новом файле — запрещено `0038` и красит `TR-4c` (проверено запуском на копии: файл с `child_process` в `tools/src/handoffs/probe.js` — `not ok` у `TR-4c` и `HC-RT-1a/1b/1d/1e`).
3. Вызов git в `git-history.js` — шестой вызов с фиксированными аргументами.

## Решение

Вариант 3. В `git-history.js` добавляется экспорт `tagExists(root, runId, timeoutMs?)`: до вызова `runId` проверяется образцом RUN-ID, ссылка собирается как `refs/tags/base/<RUN-ID>^{commit}`, вызов `git -c core.fsmonitor=false rev-parse --verify --quiet <ссылка>` без оболочки, 30 с, код выхода 1 — «метки нет». Вызов стоит в файле перед `readBlobs`, чтобы `cat-file --batch` оставался последним. Тест `HC-RT-1` (`tools/test/handoffs-runtime.test.js`: `HC-RT-1b`, `HC-RT-1c`, `HC-RT-1d`) получает шестую запись списка вызовов; число вызовов и точные списки аргументов остаются закреплёнными — проверка не ослабляется. `TR-4c` не меняется: слово `child_process` по-прежнему только в трёх файлах.

## Почему

Защита по `0038` сохраняется (один файл, `execFileSync`, без оболочки, фиксированные аргументы, `core.fsmonitor=false`, таймаут), а ложных отказов в WF-02 нет и `base_tag` не теряется у других процессов. Проверено запуском: шестой вызов красит ровно `HC-RT-1b`, `HC-RT-1c`, `HC-RT-1d` и не трогает `TR-4c`.

## Граница

Не разрешает других новых мест с `child_process` и других вызовов git в этом файле без новой записи. Строка-обновление проекта REQ-038 (число вызовов — шесть) — у DOC-UPDATER на шаге 10.
