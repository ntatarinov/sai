# 0021 — Проверка следов (REQ-014): git как источник списка файлов, файлы данных в `tools/traces/`, исключения не для названий

Статус: принято (ORCH), 2026-10-09, прогон `PROD-20261009-01`, шаг 01. Владелец может отменить. Расширяет `0002` (служебный
код конвейера) и продолжает `0019` (Sai без следов). Проект — `docs/design/REQ-014-traces.md` (r2). Дополнено 2026-10-09 по FAIL ворот проекта (`handoffs/PROD-20261009-01/step-04-code-design-validator.json`) и решениям ORCH: D4 уточнён, D6–D9 и ограничения добавлены. Дополнено ещё раз (проект r3) по FAIL кода (`step-11-security-reviewer.json`, `step-12-reviewer.json`): D1 — `core.fsmonitor=false`, D11–D13.

## Вопрос

Как устроить команду `npm run traces`, чтобы она проверяла ровно файлы Sai из git, не хранила названий открытым текстом и не
давала обходить проверку названий?

## Варианты

1. Список файлов — вызов git (`rev-parse`, `ls-files --cached --others --exclude-standard`) из одного модуля через
   `child_process`, без оболочки.
2. Без `child_process`: свой разбор `.git/index` и правил `.gitignore` — второй источник правды, расходящийся с git.
3. Проверять все файлы папки без git — проверялись бы игнорируемые личные файлы (`.claude/settings.local.json`,
   `node_modules/`).

## Решение

Вариант 1, и вместе с ним:

- **D1.** `child_process` в `tools/src/traces/` — только в `tools/src/traces/git-files.js`: импорт только `execFileSync`,
  ровно два вызова git с фиксированными аргументами (`-c core.fsmonitor=false -C <папка> rev-parse --show-toplevel` и
  `-c core.fsmonitor=false -c core.quotePath=false ls-files -z --cached --others --exclude-standard`), без оболочки,
  таймаут 30 с; `core.fsmonitor=false` не даёт настройке репозитория запустить чужую программу. Слова критерия 4 REQ-014 уточняет REQ-ANALYST по WF-01.
- **D2.** Файлы данных — `tools/traces/forbidden-names.sha256` (хеши sha256 слов и пар слов) и `tools/traces/exceptions.tsv`
  (путь, хеш строки, причина). Файл хешей пишет только `npm run traces -- add` — запись «всё или ничего» по `0004`.
  `tools/src/traces/` — служебный код по `0002`, вне `tools/src/team/`: «пять мест записи» критерия 2 REQ-009 он не трогает.
- **D3.** Исключения действуют только на пути домашних каталогов и ссылки за корень, **не на названия**. Название,
  совпадающее с обычным словом, владелец вносит парой слов.
- **D4.** Названия проверяются и в тексте, и в путях файлов; путь файла с названием в выводе не печатается — вместо него
  строка `<файл №k, sha256 пути <12 hex>>: название из списка в имени файла` (k — номер в списке путей, отсортированном по
  байтам UTF-8; найти файл — `git ls-files -z --cached --others --exclude-standard | LC_ALL=C sort -z | tr '\0' '\n' | sed -n '<k>p'`).
  `hash-line` печатает только хеш строки.
- **D5.** Коды выхода: 0 — чисто, 1 — найден след, 2 — ошибка окружения или ввода, а также неполная проверка (файл не
  читается) без следов: неполная проверка зелёной не бывает. Вне git-репозитория — код 2; копии Sai для тестов и повторов,
  где запускается `npm run check`, делаются вместе с `.git`.

- **D6.** Перед делением на слова — NFKC, нижний регистр, удаление невидимых знаков U+200B–U+200D, U+2060, U+00AD, U+FEFF;
  одинаково для текста, путей, `add` и открытого списка.
- **D7.** Путь домашнего каталога ловится и в закодированной форме имени папки проекта Claude Code: `-Users-<имя>-` и
  `-home-<имя>-` (след, если за `-Users-`/`-home-` идёт имя и `-`; пометка в угловых скобках — не след). Имя пользователя
  вне путей владелец вносит в список названий.
- **D8.** `add` берёт замок `tools/traces/.forbidden-names.sha256.lock` (эксклюзивное создание, pid), перед записью
  перечитывает файл хешей и при изменении отказывает; запись — временный файл и переименование (`0004`).
- **D9.** Ссылка Markdown с негодным `%XX` — «не разобрана», не след, код не меняет, без падения.
- **D10.** Шаг приёмки «чистая машина» сравнивает домашний каталог на двух уровнях (корень и первый уровень вложенности).

- **D11.** Пределы: файл больше `MAX_FILE_BYTES = 16 МиБ` (размер по `lstat` до чтения) пропускается с пометкой, как
  двоичный; строка `.md` длиннее `MAX_LINE_CHARS = 100 000` знаков не разбирается на ссылки (с пометкой); разбор скобок
  линейный. `add` ждёт неблокирующий ввод не больше 30 с без новых байтов.
- **D12.** Файл, чей `realpath` вне `realpath` корня (папка-ссылка наружу), не читается: `check` — пропуск «вне корня
  репозитория», `hash-line` — отказ; `add` отказывает (`E_WRITE`), если `tools` или `tools/traces` — ссылка или вне корня,
  ничего не создавая.
- **D13.** Подкоманды и ключи разбираются по `Map`/`Object.hasOwn`: имена из `Object.prototype` — неизвестная подкоманда.

## Принятые ограничения

- Название — одно или два слова, каждая часть не короче 3 знаков; длиннее — вносится отличительной парой.
- Хеш отдельного слова обратим перебором словаря: файл хешей защищает от случайного прочтения и поиска, тайной не является.
- Правило деления — защита от случайности, не от умысла: не ловятся склейка слов и camelCase («ZqxwvorgApi»), цифра
  вплотную («zqxwvorg2»), похожие буквы другого алфавита (гомоглифы); известные склеенные формы владелец вносит отдельным
  словом.
- Ссылки в сыром HTML и HTML-комментариях не проверяются; ссылка не переходит через перевод строки.
- Двоичные файлы по содержимому не проверяются (только путь). История git не проверяется (`0019`, «Граница»).
- Замена следа в копии `runs/<RUN-ID>/sources/` меняет `clean_sha256` в `run.json` и печать `run.json`; прежняя печать
  в handoff-ах WF-06 становится исторической, как `original_sha256`. Инструмента пересчёта в `tools/` нет: пересчёт —
  `shasum -a 256`, проверка — `npm run validate`.

## Почему

git — единственный источник того, что входит в репозиторий; свой разбор дал бы расхождения. Исключение для названия
означало бы оставить название в Sai, то есть сам след. Печать найденного текста сделала бы вывод, вставленный в handoff,
новым следом.
