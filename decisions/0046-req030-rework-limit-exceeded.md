# 0046 — Прогон REQ-030: лимит доработок превышен по слову владельца (только ворота проекта этого прогона)

Статус: **принято** (по слову владельца, 2026-10-13; ORCH записал; владелец может отменить). Образец — `0010`, `0014`.

## Вопрос

Проект REQ-030 (`docs/design/REQ-030-github-check.md`) три раза возвращался на доработку на воротах шага 1b (`handoffs/REQ030-20261012-01/step-01-code-designer.json`, `-r1`, `-r2`, `-r3`); четвёртые ворота (`step-01b-code-design-validator-r3.json`) вернули FAIL по одному пункту F7 (Medium): неверная форма запуска теста в п. 7.2 проекта и не названо удаление `NODE_TEST_CONTEXT` при вложенном запуске. По WF-02 («Цикл доработки») больше трёх доработок на одних воротах не делается без решения владельца.

## Варианты

1. Остановить REQ-030 и перейти к следующему пункту очереди.
2. Разрешить одну дополнительную доработку (четвёртую) по перечню F7 и низких N5–N7, затем повторные ворота.

## Решение

Вариант 2, по слову владельца 2026-10-13, дословно: «Продолжи все чтобы я мог тебе дать следующую задачу» (ответ на отчёт ORCH об остановке по лимиту и вопрос «разрешить четвёртую доработку?»). Одна дополнительная доработка, только по перечню замечаний; после неё повторные ворота. Если и они вернут FAIL, прогон останавливается без нового исключения.

## Почему

Остаток — одна локальная правка текста проекта (форма запуска тестов), остальное проекта прошло ворота; ещё один круг дешевле, чем потеря уже проверенной работы.

## Граница

Исключение относится только к воротам проекта прогона `REQ030-20261012-01`. Оно НЕ даёт согласия на: отправку ветки с падающим тестом на GitHub (критерий 3 REQ-030), изменение видимости репозитория, включение защиты ветки `main`, изменение настроек Actions. Эти действия требуют отдельного слова владельца.

## Основание

Слова владельца 2026-10-13 (дословно в разделе «Решение»); отчёт ORCH об остановке по лимиту доработок в той же сессии; `docs/workflows/WF-02-development.md`, «Цикл доработки»; `decisions/0010`, `decisions/0014`.
