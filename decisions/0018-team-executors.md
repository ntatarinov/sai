# 0018 — Исполнители Sai Team: запуск агента, потолок расходов, условия и граница файлов тестов (REQ-010)

Статус: принято (2026-10-06, ORCH). Владелец может отменить. Уточняет `0015` (старт разработки продукта) и `0017` (ядро
команды); опирается на `0011` и `0013` (маскирование). Основание — проект `docs/design/REQ-010-agent-executors.md`
(раздел 18, P1–P10 и вопрос I10), итоговые ворота (`handoffs/PROD-20261006-01/step-24-code-design-validator.json`, M2) и
приёмка (`handoffs/PROD-20261006-01/step-20-release-validator.json`, F6, F7).

## Вопрос

Исполнитель выполняет одну задачу проекта от имени роли: запускает Claude Code как процесс и принимает ответ. Нужно записать
оспоримые выборы — как запускать, чем ограничивать расход, где проверять условия настоящего запуска, как называть тестовый
исполнитель — и границу файлов тестов, которую `0015` и `0017` (P10) называют только частично.

## Варианты

1. Не записывать: выборы остаются только в проекте кода (против Q12 для оспоримых выборов).
2. Записать решения P1–P10, условия запуска, причины сбоев, границу файлов тестов и остаточные риски одной записью.
3. Разбить на несколько записей (запуск, расход, тесты) — больше файлов без новой пользы.

## Решение

Вариант 2. Принято (метки P1–P10 — по нумерации раздела 18 проекта REQ-010):

- **P1.** Текст задачи передаётся через stdin; списки инструментов — одним аргументом через запятую; позиционной подсказки нет.
- **P2.** Флаги изоляции: `--restricted`, `--safe-mode`, `--strict-mcp-config`, `--no-session-persistence`,
  `--permission-prompts none`. `--bare` не используется (ломает вход по подписке).
- **P3.** Окружение дочернего процесса — только список `CHILD_ENV_ALLOW`; `ANTHROPIC_API_KEY` не передаётся (вход — подписка;
  ключ — отдельным требованием).
- **P4. Потолок одного запуска** = меньшее из остатка бюджета проекта и `SAI_TEAM_RUN_CAP_USD`; по умолчанию — четверть
  потолка проекта (так при любом потолке остаются деньги минимум на три попытки одной задачи, если первые не сообщили расход).
  Если отчёт о расходе не пришёл, расход принимается равным потолку этого запуска и помечается `assumed`, а не нулём.
  Расход больше `1e9` считается неизвестным (тоже `assumed`).
- **P5.** После удачной попытки задача — «на проверке» (`TASK_REVIEW`); «готово» ставит только REQ-013.
- **P6.** Имена результатов `t-NNNN-N-<имя>`; исходники принятых файлов удаляются из `work/`.
- **P7. Процесс.** Дочерний процесс создаётся без оболочки, в своей группе процессов; при отмене, таймауте и сбое убивается
  вся группа. Таймаут задачи — 20 минут (`SAI_TEAM_TASK_TIMEOUT_MS`). Ожидание закрытия потоков процесса ограничено по времени,
  чтобы застрявший поток не подвешивал задачу.
- **P8.** Сбой сети Исследователя распознаётся по ошибке результата WebFetch/WebSearch и неуспеху попытки, без разбора текста
  ошибки.

Условия и настройки:

- **Условия настоящего запуска проверяет исполнитель, а не вызывающий:** `check()` в `claude-cli` (тип исполнителя,
  `SAI_TEAM_REAL_RUNS=1` — только строка `1`, положительный потолок проекта, рабочая папка, остаток расхода) вызывает сам `run()`
  первой строкой, до любого действия; `runner` вызывает её ещё раз перед запуском. Значения `SAI_TEAM_CLAUDE_BIN` (абсолютный
  путь) и `SAI_TEAM_RUN_CAP_USD` проверяет `config.js` при чтении настроек (`E_CONFIG`), а не `run()`. Потолок запуска считает
  `runner`, а не `run()`. Невыполненное условие — ошибка до любого действия: процесс не создаётся, журнал не меняется. Обойти
  условия прямым вызовом `run()` нельзя.
- **Переменные:** `SAI_TEAM_REAL_RUNS` (по умолчанию выключено), `SAI_TEAM_WEB` (`0` — у Исследователя нет WebSearch и
  WebFetch), `SAI_TEAM_CLAUDE_BIN`, `SAI_TEAM_RUN_CAP_USD` (≥ 0.01).
- **`scripted` — только для тестов.** Исполнитель-сценарий читает файлы из `tools/test/fixtures/team/` и не пишет на диск;
  его фразы в журнале несут пометку «тестовый исполнитель». Запасного исполнителя нет: неизвестный код — ошибка.
- **I10.** Пометка «тестовый исполнитель» стоит **только у фраз** (задач и запусков). У числовых событий (например,
  `BUDGET_SPENT`) пометки нет: число не фраза, и ложной подсказки в нём нет.
- **Причины сбоев — только из каталога ядра** (`retries_exhausted`, `rejected_by_user`, `executor_not_found`,
  `invalid_output`, `result_file`), подробности — в `detail` (текст не длиннее `DETAIL_MAX`). Причин `executor_error`, `network`,
  `budget_exhausted` в каталоге нет.

- **P10. Потолок запуска и расход.** Потолок запуска считает runner (`maxBudgetFor` в `runner.js`, по `runCapFor` из
  `executor.js`, P4); `checkBudget` в `executor.js` его только проверяет и отказывает `E_BUDGET_EXHAUSTED`. Сообщённый расход
  больше `1e9`, отрицательный или не число (`recordableCost` в `runner.js`) — неизвестный: пишется потолок запуска с `assumed`.
- **P10. Группа процессов не остановлена.** Если после выхода процесса группа не ушла, `transient: false` — повтора нет («Не удалось
  остановить процессы исполнителя»), чтобы не было двух процессов у одной задачи. Итог `ok` при неостановленной группе
  отклоняется (становится `failed`): результат такой попытки не принимается — ни файлов, ни памяти, ни `TASK_REVIEW`.
- **Запуск закрывается на всех путях выхода**, в том числе при исключении исполнителя не типа `TeamError` и при ошибке приёма
  результата; если закрыть нельзя — `writer.markBroken()`.
- **Сломанный писатель оставляет замок** (`0017` P12): проект остаётся «как после аварии», его восстановит следующий открывающий.

**P9. Граница файлов тестов** (расширяет `0015` и `0017` P10, которые называют буквально только `tools/test/team-*.test.js`):

| Что | Где |
|---|---|
| Тесты ядра и их помощник | `tools/test/team-*.test.js`, `tools/test/team-helpers.js` |
| Тесты исполнителей и их помощник | `tools/test/exec-*.test.js`, `tools/test/exec-helpers.js` |
| Фикстуры (поддельный `claude`, образцы `stream-json`, сценарии `scripted`) | `tools/test/fixtures/team/**` |
| Общий помощник сбоев записи | расширение `tools/test/fault-inject.js` (обратно совместимое) |
| Исходники продукта | `tools/src/team/**`, включая `tools/src/team/executors/` |

Все эти файлы — тестовый или продуктовый код в границе `0015` (Node 22 без зависимостей); за пределы этой таблицы решение
границу не расширяет.

## Остаточные риски (названы намеренно)

- **Потомок, вышедший из группы процессов** (например, через `setsid`), убийством группы не достаётся и может пережить задачу;
  также `kill -9` самого `run-task` оставляет открытый запуск (его закроет восстановление по `0017` P11 при следующем открытии).
- **Сеть Исследователя** (Q11, см. `0015`): запрет `WebFetch` для внутренних адресов задан правилами инструмента Claude Code, но
  проверку адресов делает сам Claude Code, а не наш код; полная проверка настоящим запуском — UAT (критерий 14 REQ-010).
- **Окно `EEXIST` замка** (`0017`, «Остаточный риск»): три процесса на устаревшем замке на короткое время могут оба считать
  себя писателями.
- **Не проверено без настоящего запуска** (проект, I4): точная вложенность строк `stream-json`, совместимость флагов изоляции
  в одном запуске, действие `--max-budget-usd` на подписке. Это UAT с согласия владельца и потолком расходов.

## Почему

Выборы оспоримы: запуск без оболочки, группа процессов и потолок на запуск ограничивают ущерб от зависшего или дорогого агента;
условия внутри `run()` не оставляют обходного пути; пометка у фраз, а не у чисел не вводит в заблуждение. Граница файлов
тестов записана, чтобы тесты исполнителей, помощники и фикстуры не оказались вне записанного решения (Q12), а остаточные
риски названы, а не спрятаны (Q3).

## Граница

Решение касается `tools/src/team/` и тестов `tools/test/exec-*`, `tools/test/team-*`, `tools/test/fixtures/team/**`.
Границы `0002`, `0003`, `0011`, `0013`, `0015`, `0017` не меняются. Решение не разрешает настоящий запуск `claude` без согласия
владельца и потолка расходов и не меняет статус требований.
