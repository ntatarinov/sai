- **О2.** Accepted: the oracle for the `<h1>` is the field `name` of the questionnaire answer (and `name[<lang>]` of the tenant file as a second source). The word «title» in criterion 1 is read as "the tenant's name"; DOC-UPDATER notes the wording at step 10 as an outdated word without a change of meaning.
- **О3.** Accepted: the start button is asserted by horizontal containment and by "the whole rectangle is inside the window after it is scrolled into view". At 320×568 in Russian the button lies below the first screen (594 > 568), which is a scrolled page and not a defect; the page is not changed in this run. If the owner wants the button on the first screen, it is a new requirement.
- **О4.** Accepted: the browser's line for a failed request (`net::ERR_CONNECTION_REFUSED`) is declared by its exact text with its path, and the test asserts exactly two entries. The kit is not made weaker.
- **О5.** Accepted: one `reload` through the kit, then keys.
- **О6.** Accepted: the starter's 20 tests are supporting tests under criteria 7, 8 and 10; no criterion 11.
- **О7.** Accepted: the marker folder reuses `makeTempDir("profile")`; `cleanup.js` is not changed.
- **О8.** This record is the record of the design's choices C-1 (the short environment list, never the whole environment), C-2 (detached, registered, marker), C-3 (exit code 0 required after SIGTERM), the new error codes, the place `tools/test/e2e/kit/stand.js`, the fixtures folder `tools/test/fixtures/e2e-stand/`, and the base list names, as they stand in the design.

- **О10.** Accepted: named properties (six names added to the list of `E2K-50`). The allowlist of files that read the whole environment stays at three.
- **О11.** Accepted: no time assertion inside the spec. The limit of 80000 ms is read by RELEASE-VALIDATOR from the record line; on the GitHub runner a value above 48000 ms is a question to the owner, not a silent pass (the runner was about 2 times slower than the developer machine for the smoke file, ISS-0103).

## Addendum 2026-11-08 (ORCH, WF-02 step 2, question I3 of BACKEND-DEV)

- **О14 (I3 of step 02).** Section 4.1 of the design read two ways for a stand that ends by itself with code 0 before `stop()`: the rule "STAND_EXIT only for a code other than 0 or a signal", and the sentence "a process that ended by itself before `stop()` … `stop()` then throws `STAND_EXIT`" (also row 9 of section 5). The second reading is taken: a stand is a server and must not end by itself; if it ended before `stop()` with ANY code, `0` included, `stop()` throws `STAND_EXIT` with `on its own`, so the test that relied on it fails. A stop after `SIGTERM` with code `0` stays the only good end. BACKEND-DEV changes the one condition and adds a stand-in mode that ends by itself with code 0 (step 02b); TEST-DESIGNER covers it inside `E2S-11` (no new test id, the counts of the design stay); DOC-UPDATER writes the reading into section 4.1 at step 10.

## Addendum 2026-11-08 (ORCH, WF-02 steps 3 and 4, after the first pass of the gates)

- **О13 kept, its premise corrected.** REVIEWER (step 04, issue I1) forced a group that survives `SIGKILL` with a real process on macOS: a helper in another language left an unreaped zombie in the group and left the group itself. The precedence held in all four paths of `stop()` (`CLEANUP_FAILED` each time, the message ending with the end of the main process). So "cannot be forced" is false; "cannot be forced with Node alone" is true for a stand started the normal way, because Node has no call that moves a process into or out of a process group (`process.setsid`, `setpgid` and `setpgrp` do not exist): the parent of every member of the stand's group is itself in the group, dies with its `SIGKILL`, and the system reaps the orphans (REVIEWER, step 04d, issue I1; Linux not measured). No test is added: the fixtures stay Node only (`decisions/0002`), and REVIEWER's trial is the evidence for S22.
- **О15 (F1 and F2 of SECURITY-REVIEWER, step 03; the precondition of REQ-106).** The starter gives the child no `HOME` variable, but Node still finds the real home folder through the system's list of users; and the starter checks the folders of `stateDirs` but does not bind them to the variables of `env` that the server reads. REQ-105 needs neither: the picker reads no home folder and writes no file. Before the design of REQ-106 (Pixel Office keeps its journal and its signing secret under the home folder by default), its designer settles both: a private temporary home folder for every stand, and state folders given to the server only through checked pairs "variable → folder" — and through its arguments too: Pixel Office also takes its folder from the argument `--dir`, so folder arguments are checked or forbidden the same way (SECURITY-REVIEWER, step 04c, issue I1). Until then the comment of `stand.js` and the README say the truth (no `HOME` variable, the home folder is not hidden).
- **О16 (findings outside this change).** F4 of SECURITY-REVIEWER (a group number stays registered until `stop()`, the exit handler or the sweep; a reused number would get `SIGKILL`; the same shape in `cleanup.js`, `browser.js` and `stand.js`) and I2 of REVIEWER (`browser.js` reads the pipes before it listens for the `error` event; `withBrowser` can attach an error to itself as its `cleanupError`) are opened as defects by DOC-UPDATER at step 10, one cause per defect. The two shapes of REVIEWER's I2 (the listener order and the self-attached `cleanupError`) are fixed in the new `stand.js` in this run (step 04b); F4 is NOT fixed in `stand.js` and goes into its defect with `cleanup.js` and `browser.js`. Added after step 04b (its issue I2): `withBrowser` assigns `cleanupError` to a body error without protection (a frozen error is replaced by a `TypeError`) and treats a body that throws `null` as a success; both go into the same defect as the other `browser.js` shapes.

## Addendum 2026-11-09 (ORCH, WF-02 step 5b, after the first pass of the test gate)

- **О17 (F1 and F2 of TEST-DESIGN-VALIDATOR, step 05b; I1 of TEST-DESIGNER, step 05).** Criterion 6 of REQ-105 is read as follows; its meaning (no text of tenant A reaches tenant B) does not change:
  - "the questionnaire of tenant B", against which the set of A's strings is built, is B's tenant file (`src/picker/demo-tenants*/<B>.json`, its `ru` texts: the name, the intro, and the title, help, unit and option labels of each question), not B's answer from the server under test. An answer of the server cannot be the oracle of its own leak: a text of A served in B's questionnaire would leave the set and hide itself (mutant W02 of step 05b).
  - "hold none of them": a text of A that has a blank is looked for as a part of every string value of B's answers; a text of one word is compared with the whole string values (a single common word of A stands inside B's own texts on the correct server: the unit «человек» of `uchet-pro` in a question of `svet-marketing`, the option «Обучение» of `agency` in a result of `stock`, measured at step 05). The solution names of A are looked for as a part of the answer text, and the page text of B is checked for every text of A as a part, as before.
  - Comparing every text by whole value only (I1 of step 05) is not taken: it misses a text of A placed inside a string of B (mutant W01 of step 05b).
  - The control of at least 10 texts stays. DOC-UPDATER writes this precision into criterion 6 at step 10 with `before_copy` (`decisions/0079`, item 5).
- **О18 (I1 of TEST-FIXER, step 05c; F3 of step 05b).** The mutant V12 (`stop()` does not wait for the group after its final `SIGKILL`) is caught by the timing of the system, not by a fact the test controls: the check right after `stop()` in `E2S-13` turns it red in 11 of 11 runs of the whole file `tools/test/e2e-stand.test.js` (the way `npm test` runs it), and `E2S-13` alone in 0 of 30 runs on a quiet machine and 18 of 30 under load. The last member of the group then is the child that ignored `SIGTERM`; its parent has ended, so the system reaps it, and a Node-only stand-in cannot keep a member of the group unreaped (the premise of О13 as corrected on 2026-11-08). Accepted and recorded like S22: no code is added only for a test, no fixture in another language (`decisions/0002`); the wait stays a thing REVIEWER reads in the code. The checks right after `stop()` and after a failed start stay, because they pin the contract of section 4.1 and catch V13 without luck (`E2S-07`, `E2S-08`: 10 of 10 each). The mutant P13 in its exact form is red in the first pair by the control of 10 texts (under it the address of A serves B, so A has no text that B lacks) and red by a hit in the second pair in the form limited to `demo-tenants-v3`; both count as caught.

## Addendum 2026-11-09 (ORCH, WF-02 step 5b, after the second pass of the test gate)

- **О17 corrected (F4 of TEST-DESIGN-VALIDATOR, step 05d).** Comparing every one-word text of A only as a whole value is too wide: 9 of the 12 one-word texts of A occur nowhere in B's file, and the name of A («Учёт-Про», «Лидвейв») placed inside a string of B was not seen (mutants N05 and N09 of step 05d survived). The rule for B's answers is now: a text of A with a blank, and a one-word text of A that does not occur as a part of any `ru` string of B's tenant file, are looked for as a part of every string value; only a one-word text of A that occurs inside B's own file texts is compared with whole string values. The measured common words are «человек» and «Средний» for `uchet-pro` → `svet-marketing` and «Обучение» for `agency` → `stock`; the test computes them from B's file and asserts them equal to these, so the exception cannot grow silently.
- **The approach changes (WF-02, rework loop: the same error came back after a rework step).** A list of A's texts can only see the leaks it lists. Besides it, the test asserts that B's answers hold B's own strings only: the texts of B's questionnaire answer (the name, the intro, and the title, help, unit and option labels of each question) equal the `ru` texts of B's tenant file, field by field, and every string value of B's result answer is a string of B's tenant file. A text of A of any length placed in B's answers then makes them differ from B's file, whatever its words. TEST-FIXER measures both on the correct server before it writes them; a field that the server composes itself (not a string of the file) is named in the test with the reason, and only that field is left out of the second check. The criterion's own check (the list of A's texts, the solution names of A, the page text of B) stays as О17 and this correction say.
- **Accepted as built at step 05e (TEST-FIXER, issue I1).** The second check covers B's questionnaire answer as well, because the first check reads only the visitor texts: a text placed in another field of that answer was not seen. Measured on the correct server in both pairs, the server composes no field of B's result answer. It composes three fields of B's questionnaire answer: `version` (the sha256 of the bytes of B's file, design of REQ-056, 5.2), `lang` (the language asked) and `languages` (the languages of the file). The test names them with the reason and leaves them out of the membership check. It asserts their values instead, so A's `version` in B's answer is red too. The error answer that B's address gives to A's leader set gets the same list rule as B's own answers; before, it was searched only for A's solution names.
- **О18 corrected (F5 of TEST-DESIGN-VALIDATOR, step 05d).** The premise "V12 is caught only by the timing of the system" is false. The gate made it red with Node only and the existing seam `deps.spawn`: the stand-in in mode `ignore-term` stays alive after `SIGTERM`, and `deps.spawn` hands the starter `exit` (code 0) and `close` as soon as the log of the stand-in shows `term`. At the final `SIGKILL` of `stop()` the group still holds the stand-in, a child of the test process that only the test process reaps, and only when its event loop turns; so `stop()` resolves with the group gone only if it waited for the group (red under V12 in 60 of 60 runs, green on the correct code in 120 of 120, measured by the gate). This case goes into `E2S-13` (its subject: the group gets `SIGTERM` and then `SIGKILL`), without a new test id. V12 then counts as caught, and S22 stays the only recorded survivor of the design's list (О13: a group that outlives the wait of 3 s after `SIGKILL` still cannot be made with Node alone).

## Addendum 2026-11-09 (ORCH, WF-02 step 5b, after the third pass of the test gate)

- **О19 (F6 and issue I1 of TEST-DESIGN-VALIDATOR, step 05f, verdict PASS).** Criterion 6 says that after a full pass of A "the page of B in the same browser has none of those strings in its `textContent`", and it names B's result answer "for B's own set", which B's page gets only at the end of its own pass. So the page clause covers every screen of B's page from its open to that result: the card, each question screen and the result screen.   - the page of B on every screen of its own pass, by the rule of О17 as corrected, applied to the page. Every other text and name of A is looked for as a part of the page text. The page text is the `textContent` of the body; as a raise of the bar, also `document.title` and the attributes `aria-label`, `title`, `alt` and `placeholder`, which a visitor reads or hears. TEST-FIXER measures the exceptions on the correct server before it writes them;
