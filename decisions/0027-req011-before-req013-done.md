# 0027 — REQ-011 доводится до готовности при незавершённой зависимости REQ-013

Статус: **принято** (ORCH, 2026-10-10, по общему поручению владельца «закрывай всё… сам всё сделай»; владелец может отменить).

## Вопрос

REQ-011 зависит от REQ-013. По WF-02 работа начинается, когда зависимости имеют статус `done`. REQ-013 остаётся `in_progress` по одной причине: критерий 13 (настоящий запуск Claude) заблокирован защитой сессии и ждёт разрешения владельца в настройках Claude Code и потолка расходов (решение 0018). Всё остальное в REQ-013 выполнено и проверено (`handoffs/PROD-20261006-02/`).

## Варианты

1. Остановить REQ-011 до разрешения владельца — прогресс по каталогу стоит из-за одной проверки, которую ORCH выполнить не вправе.
2. Довести REQ-011 до `done` с названным исключением — страница работает на том же движке и тех же тестовых исполнителях; настоящий запуск Claude в REQ-011 не используется (сценарии R-1 и R-2 записаны и не выполнены).

## Решение

Вариант 2. Исключение касается только порядка работ: REQ-011 строится и проверяется на готовом коде REQ-013 (движок, канал), а не вместо него. Критерий 13 REQ-013 остаётся открытым, а сценарии R-1 и R-2 REQ-011 — «не выполнены: нет согласия владельца»; когда владелец даст разрешение, оба закрываются одним настоящим запуском. До этого REQ-013 остаётся `in_progress`, а REQ-025 (рамка «не хуже образца») не получает `done`.

## Последствия

- В STATE.md записано: REQ-011 `done` с зависимостью по исключению 0027.
- RELEASE-VALIDATOR принимает это исключение как записанное, но владелец вправе отменить.
