# 0030 — Открытые вопросы REQ-035 и REQ-037: остановка, режим resume сервера, привязка записи этапа к сессии

Статус: **принято** (ORCH, 2026-10-11, по общему поручению владельца; владелец может отменить). Уточняет `0025` (W1) и `0028`.

## Решения

1. **Остановка необратима (REQ-035, вопрос 1).** Остановленный проект продолжить нельзя: так работает движок (`E_STOPPED`, `0020`). Кнопка «Остановить» просит подтверждение и говорит об этом словами «Это нельзя отменить». Если владелец захочет продолжать и остановленные, это правка REQ-013 и `0020`.
2. **Режим resume у сервера (правка W1 `0025`).** После перезапуска сервера проект на паузе запускается движком в режиме `resume` (у движка он есть, `engine.js`, `commands.js`), а не `start`; в режиме `start` кнопка «Продолжить» для такого проекта не работает. Меняется только то, как сервер запускает движок для проекта на паузе (файл `tools/src/web/engines.js`, режим вместо `start`); процесс остаётся тот же, `child_process` по-прежнему запрещён (`0025` W1). Проект правки — CODE-DESIGNER REQ-035.
3. **Привязка записи этапа к сессии (REQ-037, вопрос 2).** Сервер Pixel Office ставит записи `session_id` последнего сообщения владельца (оркестратор свою сессию не видит). Предел назван открыто: при нескольких одновременных сессиях владельца название прогона может встать над чужими строками; для одной рабочей сессии (текущий порядок) этого нет. Проверка шире на журналах — задача CODE-DESIGNER REQ-037.
4. **Зависимости REQ-036.** REQ-008 остаётся зависимостью REQ-037 (нужен записи этапа), в REQ-036 его нет; `0029` читается так: исключение распространяется на все названные там зависимости, где они есть в `depends_on`.
