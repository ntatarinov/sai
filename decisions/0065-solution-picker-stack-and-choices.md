# 0065 — Сайт подбора решения (REQ-054…REQ-060): стек и выборы REQ-ANALYST

Статус: **принято** (ORCH, 2026-10-19, по предложениям REQ-ANALYST `handoffs/PICKER-20261019-01/step-01-req-analyst.json`, П1–П7; просьба владельца `docs/owner-requests/2026-10-19-solution-picker-site.md`; владелец может отменить).

## Решение

1. Стек (дополняет `0015`): код сайта подбора — в `tools/src/picker/`, Node 22 без внешних зависимостей, проверка — общая `cd tools && npm run check`, команда `npm run picker`.
2. Файл арендатора — JSON, проверяется командой `npm run picker -- check`.
3. Арендатор выбирается путём `/t/<id>/`; путь — выбор открытой витрины, а не право доступа (толкование Q8): заявки по сети не отдаются вовсе. Общее хранилище браузера у всех арендаторов допускается: страница читает только свой ключ, контактов в нём нет.
4. Заявки — файл на заявку в `<папка данных>/<арендатор>/leads/`, права 0600 (папки 0700), папка по умолчанию `~/.sai-picker`.
5. На первом этапе заявки видит только тот, кто запускает стенд, локальными командами.
6. Границы: до 30 вопросов, 20 решений, 200 правил, баллы от −10 до 10; свободного текста нет ни в анкете, ни в заявке.
7. Вместо «уверенности» — пометка «явный лидер» по разрыву баллов.

8. Уточнения ORCH по неблокирующим замечаниям ворот (`handoffs/PICKER-20261019-01/step-02-req-validator-r1.json`, M1, M2) — для стройки без догадок: у каждого вымышленного арендатора `result.top` не меньше 2 (иначе исход «близкие варианты» невозможен); в командах инструкции (REQ-060, кр. 4) тест подставляет `<файл>` — путь к файлу заготовки во временной папке, `<id арендатора>` — id вымышленного арендатора, `<id заявки>` — id заявки, созданной тестом, `<порт>` — свободный порт, выбранный тестом.

## Граница

Только требования (WF-01); стройка — по слову владельца (на Sonnet). Публикация в интернет, вход арендатора, ИИ на сайте и языки кроме русского — вопросы владельцу, этим решением не разрешены. Код проекта-образца не копируется.
