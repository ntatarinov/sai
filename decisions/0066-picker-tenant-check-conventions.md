# 0066 — Проверка файла арендатора (REQ-054): условные прочтения требования

Статус: **принято** (ORCH, 2026-10-19, по вопросам О1–О6 проекта `docs/design/REQ-054-picker-tenant.md`, п. 16; владелец может отменить).

## Вопрос

Как устроена проверка файла арендатора там, где требование REQ-054 допускает несколько прочтений.

## Решение

Принимается написанное в проекте, п. 16.1:

1. Длина пунктов `needs_from_you`, `next_steps`, `not_suitable_when` — 1–150 знаков, как у `includes`.
2. `needs_from_you` и `not_suitable_when` — обязательные поля (допустим `[]`).
3. Цикл условий даёт одну строку E_ORDER — у условия, которое ссылается на тот же вопрос или вперёд; обратная ссылка верна.
4. Коды для случаев вне списка требования — по п. 4.12 проекта (E_FIELD, E_ID, E_DUP, E_LIMIT, E_COND, E_JSON).
5. Сверх описания: файл не больше 512 КБ (код выхода 2), BOM допускается, все поля `result` и `leads` обязательны, `--help`, `any_of`/`none_of` по 1–8 id.
6. Ошибки (код 1) идут в stdout, как у `handoffs-check`; в stderr — только код 2.
7. Свой строгий читатель JSON (позиция «строка, знак» по-русски, отказ на повтор ключа, предел глубины 20), порядок ошибок — по месту в файле, на место — одна ошибка в порядке «тип → шаблон → границы → повтор → ссылка → правило текста».

## Граница

Не меняет формат файла арендатора и список из десяти кодов REQ-054; решение `0065` в силе.
