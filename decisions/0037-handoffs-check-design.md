## Вопрос

Как построить команду `npm run handoffs-check`, чтобы она проверяла времена по истории git, не меняя код и тесты проверки следов (REQ-014), не ослабляя их и не позволяя «обновить» базу исключений?

## Варианты и выбор

1. **Где вызовы git.** Решено ORCH в `0038` (третье место `child_process` — `tools/src/handoffs/git-history.js`, одна строка в `CHILD_PROCESS_FILES`, тест `HC-RT-1`); здесь не повторяется. Проект фиксирует массивы аргументов пяти вызовов (п. 7) и таймаут 30 с.
2. **Граница H7.** Время коммиттера (`%cI`, в UTC) самого раннего коммита истории HEAD, в версии файла которого по пути поля стоит строка, равная значению; сравнение строгое; нет такого коммита — граница одна, часы.
3. **База исключений.** Файл `tools/handoffs/exceptions.tsv`, запись — пять полей (путь, правило, путь поля, sha256 значения, причина); каждая запись при каждом запуске сверяется с версией файла в коммите базы; коммит базы закреплён строкой в записи `decisions/` с наибольшим номером и совпадает с шапкой файла. Выбор не ослабляет планку: нарушение нового файла или нового значения снять нельзя.
4. **Снятие базы.** Ключ `--emit-exceptions` печатает записи для ещё не снятых нарушений (ничего не пишет); без него базу снимал бы одноразовый скрипт с копией правил (разрешён ORCH: stdout режима — только записи, порядок — путь, номер правила числом, путь поля).
