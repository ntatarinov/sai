# 0002 — Служебный код конвейера: Node 22, prettier, eslint, node:test

Статус: принято (2026-09-25). Подготовил ORCH. Подтверждено владельцем проекта.

**Подтверждение владельца, дословно** (2026-09-25, сессия Claude Code, ответ на вопрос
с вариантами):

- Вопрос: «Для сценария агентов нужен служебный код в sai/tools (Node 22). По правилам
  проекта код пишется только после вашего решения. Подтверждаете, что служебный код
  конвейера можно писать до старта продукта (это не код продукта)?»
- Ответ владельца: «Да, подтверждаю (Recommended)».

## Вопрос

WF-06 (REQ-002) требует кода, который проверяет контракты между агентами и применяет
вердикт. На чём его писать и какой командой проверять (quality-bar Q4), если стек
продукта ещё не выбран?

## Варианты

1. **Python 3 (стандартная библиотека) + ruff.** Есть на машине (3.14); ruff даёт
   форматирование и линтер одним инструментом. Минус: ruff надо ставить через pip в
   отдельное окружение; unittest беднее встроенного раннера Node.
2. **Node 22 + prettier + eslint + встроенный `node:test`.** Node 22 есть на машине;
   раннер тестов встроен; форматтер и линтер ставятся как зависимости разработки с
   lockfile. Плюс: интерфейс продукта почти наверняка будет в браузере, то есть на
   JavaScript/TypeScript.
3. **Без кода — правила только в инструкциях агентам.** Отклонено: это доверие к
   агенту вместо проверки, прямо против Q2 и Q3.

## Решение

Вариант 2. Node 22 (`engines`), зависимости только для разработки, точные версии в
`package-lock.json`: prettier, eslint, @eslint/js, globals. Во время выполнения
зависимостей нет. Единая команда: `npm run check` = `prettier --check` + `eslint
--max-warnings 0` + `node --test`.

## Почему

Меньше всего новых сущностей на машине, встроенный раннер тестов, lockfile делает
проверку воспроизводимой на чистой копии, язык совпадает с вероятным клиентским
стеком продукта.

## Граница

Решение касается **только** служебного кода конвейера в `tools/`. Это **не** выбор
стека продукта: он остаётся за решением `0001` после решения владельца о старте. Код
продукта в `tools/` не пишется.

## Основание

Прямое поручение владельца от 2026-09-25 реализовать сценарий WF-06 (текст — в
`docs/requirements.yaml`, перед REQ-002). Правило «код продукта — только после решения
о старте» (`CLAUDE.md`) не нарушается: служебный код конвейера — не код продукта.
