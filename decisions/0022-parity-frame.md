# 0022 — Рамка «не хуже [образца]» (REQ-025): решения по вопросам аналитика

Статус: **принято** (ORCH, 2026-10-10, по слову владельца «закрывай всё… сам всё сделай»; владелец может отменить каждый пункт). Уточняет `0015` и `0019`.

## Вопрос

Требование REQ-025 (рамка приёмки «Sai по зрелости не хуже [образца]») и таблица паритета (`docs/product/parity-matrix.md`, раздел 8) оставили пять выборов, которые по правилам WF-01 принадлежат владельцу. Владелец 2026-10-10 поручил ORCH закрывать всё самостоятельно.

## Варианты

Для каждого вопроса — оставить «ждёт владельца» (работа по REQ-025 стоит) или принять решение ORCH с правом владельца отменить. Выбран второй путь.

## Решения

- **D1. Источник слов владельца.** Фраза «он должен быть самостоятельным и не хуже проекта [образец]» — сообщение владельца в сессии Claude Code 2026-10-06 (то же сообщение, из которого взято основание `0019`); дословно в файлах Sai она не хранилась. В `original_request` REQ-025 она остаётся с пометкой источника «сообщение владельца в сессии 2026-10-06».
- **D2. Строки «не нужно».** 18 строк таблицы паритета, помеченных аналитиком «не нужно» по умолчанию, приняты с их причинами (возможности, присущие устройству BPM-платформы: визуальный редактор схем, токены и выражения, среды продвижения определений и подобное — у Sai цель обычным языком заменяет схему). Любую строку владелец может превратить в требование; тогда она получает номер REQ и идёт в каталог.
- **D3. Вебхуки.** «Не нужно», пока действует граница REQ-014 (во время работы сеть только 127.0.0.1). Исходящие уведомления вовне — отдельное решение владельца о границе сети.
- **D4. Как сравнивать тесты.** По плотности и по видам, а не по числу: у [образца] и Sai разные стеки и объём кода. Критерий: плотность тестов Sai (тестов на 1 000 строк кода `tools/src` и страниц) не ниже плотности [образца], посчитанной аналитиком (около 44 на 1 000), и в Sai есть те же виды тестов — обычные, свойств и браузерные (REQ-031); при этом у каждого критерия каждого требования есть тест (правило планки). Абсолютные числа в таблице остаются как справка.
- **D5. Второй язык.** Английский (REQ-028); русский — основной.
- **D6. Защита ветки `main` на GitHub.** Включить при реализации REQ-030 (запрет прямого пуша без зелёной проверки); включает ORCH через учётную запись владельца в сессии, где владелец это подтвердит; до тех пор REQ-030 даёт только проверку при отправке.
- **D7. Инструмент тестов страниц.** ~~Playwright по умолчанию~~ — **заменено решением `0023` (D2): jsdom как devDependency, тесты внутри `npm run check`**; снимки настоящего браузера — шаг DESIGN-QA-VALIDATOR. Честная оговорка: jsdom — не настоящий браузер, вёрстку, стили и прокрутку он не проверяет, а у [образца] 286 тестов в настоящем браузере; засчитать jsdom как тот же вид тестов решил ORCH (владелец может отменить и потребовать настоящий браузер вместе с поправкой к `REQ-014`).

## Последствия

- REQ-025 получает `done` только когда все требования столбца «требование Sai» в разделе 8 таблицы паритета `done`, а строки «не нужно» приняты (этим решением) — проверяет RELEASE-VALIDATOR чтением [образца] (только чтение).
- Название и путь [образца] в файлах Sai не появляются (`npm run traces`).
