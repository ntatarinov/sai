# 0075 — Нестабильные тесты EN-62 и HC-6a: способ исправления (ISS-0075)

Статус: **принято** (ORCH, 2026-10-21, по диагнозу `handoffs/ISS-0075-20261021-01/step-01-issue-fixer.json` и воротам `step-05-release-validator.json`; владелец может отменить).

## Решение

1. **EN-62** (гонка `readdir`/`lstat` в тесте канала команды): одна общая функция `listFilesLive` в `tools/test/team-helpers.js` вместо трёх копий (AP-014). Имя, исчезнувшее между чтением списка и проверкой, пропускается; исчезнувшая папка — пустой список; любая другая ошибка пробрасывается. Код канала не менялся (гонка была в самом тесте).
2. **HC-6a** (хеш дерева меняется из-за фоновой уборки git 2.55 и новее — замок `maintenance.lock` в личном репозитории теста): в среду `sandbox()` добавлены пять ключей (`GIT_CONFIG_COUNT=2`, `maintenance.auto=false`, `gc.auto=0`). Альтернатива «исключить замок из хеша» отвергнута: она ослабила бы проверку «команда дерево не меняет». `treeHash` и сама проверка остаются как были.
3. **EX-42** (шаг стенных часов назад, строгая проверка времени событий ENGINE) этим прогоном не исправляется. Исправление меняет поведение продукта (допуск назад или зажим времени), требует критерия и записи решения; передано в ISS-0065 и чинится отдельным прогоном.
4. Нагрузочные красные других тестов (PG-08, EN-60, HC-7a, TM-67, HK-26, HK-27 при параллельных полных прогонах) — отдельный дефект (запись DOC-UPDATER), не относятся к этому решению.

## Почему

Правки только в тестах, проверки не ослаблены, красное воспроизведено до правки и исчезло после (EN-62: 0 из 215000 опросов против 9194 из 215400; HC-6a: 0 из 60 против 45–54 из 60 на git 2.55).

## Граница

Не меняет код продукта и требования. Не закрывает EX-42.
