# Sai

«Сай» по-казахски — «подходящий». Здесь — что это за проект, чем он отличается, как открыть
его на другом компьютере и что ещё не готово. Положение дел на сегодня — `STATE.md`, план —
`PLAN.md`; агенты начинают работу с `CLAUDE.md`.

## Что такое Sai

В Sai два слоя работы (подробно — `CLAUDE.md`):

- **Продукт — пока гипотеза:** подбор размера, примерка по фото и заказ в WhatsApp для
  Instagram-магазинов одежды в Казахстане. Спрос не подтверждён, решения владельца о старте
  нет (`STATE.md`, раздел «Решение владельца о старте»), поэтому кода продукта нет.
- **Конвейер агентов:** роли, процессы и планка качества, по которым ИИ-агенты делают работу —
  требования, проекты, исследования, бизнес-план, служебный код. Служебный код лежит в
  `tools/` (Node 22): инструменты выбора идеи и Pixel Office.

## Чем Sai отличается

- **Pixel Office на настоящих событиях.** Страница, на которой видно, какие задачи выполняют
  агенты: всё строится только из событий, которые присылают хуки Claude Code, с их настоящим
  временем, — выдуманных и дописанных задним числом событий нет (планка R2,
  `docs/quality-bar.md`). Запуск и устройство — `tools/README.md`, раздел «Pixel Office»;
  проект — `docs/design/REQ-001-pixel-office.md`; решения — `decisions/0005-pixel-office-design.md`;
  код — `tools/src/pixel-office/`. Офис по образцу владельца
  (`docs/design/samples/office-2026-10-02.jpg`) — итерация 3, идёт (`PLAN.md`).
- **Проверка ценности одной фразой до постройки.** Прежде чем строить, агенты пишут одну фразу
  о том, за что платят, и таблицу конкурентов, а независимый проверяющий по исследованиям
  рынка проверяет, не дают ли того же другие:
  `docs/workflows/WF-07-business-plan.md`, раздел «Вариант: короткий документ с воротами
  ценности»; требование REQ-006 в `docs/requirements.yaml`. Для Pixel Office итог — «рано»
  (`docs/business-plan/pixel-office-brief.md`).
- **Выбор идеи тремя взглядами и судьёй.** Три аналитика оценивают идеи — рынок, исполнение,
  соответствие владельцу — с дословными цитатами и проверяют друг друга, судья выносит
  вердикт, исполнитель его перепроверяет и применяет: `docs/workflows/WF-06-idea-selection.md`,
  контракты — `docs/design/REQ-002-idea-verdict.md`, команды `prepare-run`, `validate`,
  `apply-verdict` — `tools/README.md`.
- **Параллельные прогоны с защищёнными файлами и снимком «до».** Пока идёт прогон с
  защищёнными файлами (вариант WF-07, REQ-006), каждый параллельный прогон заранее объявляет
  свои пути в `handoffs/<BP-ID>/parallel-runs.jsonl`, а защищённые файлы сверяются со
  снимком «до»: `docs/workflows/WF-07-business-plan.md`, раздел «Снимок «до» и параллельные
  прогоны»; команды `snapshot` и `snapshot-diff` — `tools/README.md`.
- **Запись файлов «всё или ничего» с откатом.** Новые байты пишутся во временный файл рядом с
  целью, старая версия остаётся жёсткой ссылкой, а при сбое всё откатывается:
  `decisions/0004-write-phase-rename-and-hardlink-rollback.md`, код — `tools/src/util.js`.
- **Работа итерациями с отчётом владельцу.** Одна итерация — один результат, который
  владелец может увидеть сам; после каждой — короткий отчёт: `PLAN.md`.
- **Планка качества, которую нельзя понизить, и пары «делает — проверяет».** Пункты Q1–Q14 и
  R1–R3, поднять планку можно только решением владельца: `docs/quality-bar.md`. У каждой
  производящей роли есть проверяющая: 37 файлов ролей в `.claude/agents/`, таблица ролей — в
  `CLAUDE.md`, процессы WF-01…WF-07 и протокол заданий агентам — в `docs/workflows/`.

## Как открыть на другом компьютере

Нужно: Node 22 с npm (`tools/package.json`, поле `engines`) и Claude Code.

1. Получить папку Sai целиком. Своего репозитория у Sai пока нет (`PLAN.md`, шаг 2f), поэтому
   сейчас это копия папки.
2. В терминале, в папке Sai:

   ```
   cd tools
   npm ci
   npm run check
   ```

   `npm ci` ставит инструменты разработки по `tools/package-lock.json`; `npm run check` —
   одна команда проверки: форматирование, линтер и все тесты. Все тесты должны пройти (на
   2026-10-02 — 197).
3. Открыть Claude Code в папке Sai — там, где лежит `CLAUDE.md`. Хуки Pixel Office записаны в
   `.claude/settings.json` и срабатывают только в сессиях, начатых в этой папке.
4. В Claude Code набрать `/hooks` и подтвердить хуки — или начать новую сессию. Если Claude
   Code спросит, доверять ли папке, — подтвердить: без этого хуки не запускаются.
5. В отдельном терминале, в папке Sai:

   ```
   cd tools
   npm run pixel-office
   ```

   Команда печатает ссылку — по умолчанию http://127.0.0.1:4780/. Откройте её: там задачи
   агентов, журнал событий и офис. Журнал и секрет записи сервер хранит вне папки Sai;
   подробности, остановка сервера и ограничения — `tools/README.md`.

## Где что лежит

- `CLAUDE.md` — указатель для агентов: что читать при старте, главное правило, роли, процессы.
- `STATE.md` — что сделано, что открыто, что дальше; `PLAN.md` — итерации и шаги.
- `.claude/agents/` — файлы ролей; `.claude/settings.json` — хуки Pixel Office.
- `docs/` — планка качества (`quality-bar.md`), требования (`requirements.yaml`), процессы
  (`workflows/`), проекты и образцы (`design/`), дефекты (`issues/`), журнал ошибок процесса
  (`anti-patterns.md`), бизнес-план и исследования (`business-plan/`, `research/`), цели
  владельца его словами (`owner-goals.md`). Папка аудитов `docs/audits/` появится с первым
  аудитом (`docs/workflows/WF-05-health-audit.md`).
- `decisions/` — записанные решения, их список — `decisions/README.md`.
- `handoffs/` — задания и отчёты агентов по прогонам; `runs/` — файлы прогонов выбора идеи;
  `reports/` — отчёты прогонов. Это история: её не переписывают.
- `ideas/` — идеи, из которых вырос проект, и почему остальные отброшены (`ideas/README.md`).
- `tools/` — служебный код и его тесты; команды — `tools/README.md`.

  идёт (`PLAN.md`, шаг 2d); проверка на чистой копии и первая перепроверка выполненных
  требований — шаг 2g.
- **Офис Pixel Office как на образце владельца** — итерация 3, идёт; **автотестов Pixel
  Office пока нет** — итерация 4.
- **Дефекты ISS-0002 и ISS-0003** открыты (`docs/issues/`); у ISS-0002 не дописаны тесты.
  Оба — итерация 5.
- **Решения владельца** — одним списком в итерации 6 (`PLAN.md`).
